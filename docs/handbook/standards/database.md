# 数据库规范

## 设计与说明

| 要求     | 内容                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 先概览   | 先列实体职责、关联及 ER 图，再说明字段与约束                                     |
| 变更完整 | 新增或变更设计列明字段名、类型、可空性、默认值、含义与约束；基础字段引用通用约定 |
| 手册精简 | 模块手册维护现行关系、关键字段与不变量，不照抄映射或迁移实现                     |
| 字段必要 | 每个字段有明确用途；冗余说明一致性机制，不为假设需求预留字段                     |
| 局部演进 | 保持职责与关联清晰，已知扩展说明限制，不以扩展性为由过度抽象                     |

## 基础约定

| 项目        | 统一要求                                                                        |
| ----------- | ------------------------------------------------------------------------------- |
| 数据库      | PostgreSQL 18.x，UTF8，确定性、大小写敏感排序；当前单库                         |
| 访问        | SQLAlchemy 2.x 同步会话与 Psycopg 3，连接协议 `postgresql+psycopg`              |
| 金额        | 整数分，禁止浮点；必要时用 `BIGINT`，范围有数据库约束；金额字段以 `_cents` 结尾 |
| 比例与数量  | 不使用金额后缀，按业务定义精度和边界                                            |
| 时间点      | `timestamptz(6)`，应用生成带时区 UTC，连接显式 UTC                              |
| 日期 / JSON | `date` / `jsonb`，索引按实际查询需要建立                                        |
| 迁移        | 统一使用 Alembic，利用事务性 DDL，不在应用启动时改结构                          |
| 已应用迁移  | 保持不可变；建库基线面向空 PostgreSQL，不承接其他数据库版本记录                 |

## 主键设计

- 实体必须有主键，默认单列代理主键 `id`，应用生成 UUIDv7，使用原生 `uuid` 存储。
- 对外 UUID 使用小写标准字符串；输入接受带连字符 UUIDv4、UUIDv7，拒绝其他表示；新建实体不生成 UUIDv4。
- 纯内部高写入表可用大整数身份列，小字典表可用整数；纯关联表按实际需要选择复合或代理主键。
- 主键唯一、非空、不可变、不承载业务含义；业务唯一性另设约束，外键与被引用类型一致。
- 保留独立、非空的 `created_at`，角色及关联表同样适用，不从 UUID 推导精确创建顺序。

## 字符串与约束

- 标识先校验允许字符再规范化，由数据库约束规范形式和唯一性；业务格式见[账号](../modules/identity/README.md)与[物业接入](../modules/property/README.md)。
- 普通文本保留大小写；名称包含查询显式忽略大小写并转义通配符，扩展索引依据执行计划选择。
- 布尔字段使用原生布尔值；可空字段参与唯一约束时明确空值相等语义。
- 平台及公司角色按公司归属与编码唯一，平台空公司同样保证唯一。
- 保留业务归属、账号与角色关联中用于公司及后台隔离的复合外键和被引用唯一约束；物业业务操作者关联见[物业模块](../modules/property/README.md#业务归属与操作者)。引用端索引按实际访问及删除检查建立。

## 连接、事务与查询

| 项目     | 要求                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------- |
| 默认隔离 | READ COMMITTED                                                                                 |
| 分页     | 记录与总数使用同一语句快照，空页仍给准确总数                                                   |
| 写入并发 | 稳定父记录协调、固定锁顺序，加锁后复核条件；不存在记录的竞争由唯一约束兜底                     |
| 应用超时 | 连接 3 秒、池等待 3 秒、语句 10 秒、锁等待 3 秒、空闲事务 60 秒                                |
| 迁移连接 | 连接超时及 UTC，不套用应用短语句超时                                                           |
| 冲突识别 | 唯一冲突按 SQLSTATE `23505` 和明确约束识别；未知约束、死锁、取消不一律解释成可重试或依赖不可用 |

事务归属见[后端架构](../architecture/backend.md#事务与任务)，失败与提交结果不确定见[错误规范](errors.md#事务与并发)。原生类型、约束、迁移及并发须在隔离 PostgreSQL 验证，按[测试规范](testing.md)执行。
