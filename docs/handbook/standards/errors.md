# 错误与异常规范

## 响应与权威定义

| 项目       | 要求                                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| 格式       | 内部 API 使用 RFC 9457 Problem Details、`application/problem+json`                                        |
| 字段       | `type/title/status/detail/instance`，扩展 `code/request_id`，校验问题另含 `errors`                        |
| 错误目录   | [公共错误契约](../../../openapi/components/errors.yaml)中的 `x-error-catalog`，统一错误码、状态和公开标题 |
| 类型与实例 | 类型前缀加错误码；实例为请求标识 URN，不回显请求 URL                                                      |
| 生成       | 从权威契约生成运行目录，不在运行时读取文档或依赖 Node.js                                                  |

- 错误码采用领域加名称，目录全局唯一；不得随意重用、更名或改变既有语义，不预建未实现领域。
- HTTP 状态与响应状态一致；标题稳定，详情仅给安全说明。生成与检查见 [API 规范](api.md#组织与构建)。

## 分类与集中处理

| 类别                     | 状态与处理                            |
| ------------------------ | ------------------------------------- |
| 输入校验                 | 422，只返回问题位置与类别             |
| 认证与权限               | 401 / 403，保留适用的认证响应头       |
| 资源与方法               | 404 / 405，保留适用的允许方法响应头   |
| 明确业务状态或并发冲突   | 409，不自动解释为可重试               |
| 明确基础设施不可用       | 503，按连接、连接池及明确驱动错误识别 |
| 未分类基础设施或系统异常 | 500，公开安全说明，保留脱敏诊断       |

- 通用转换集中注册，业务和中间件使用同一机制，不复制异常处理器。
- 已知业务异常仅用目录中确定状态的错误；普通 HTTP 异常保留合法 400–599 状态，无标准短语不改成 500。
- 编程错误和未知约束不一律转换为 409 或 503，只有明确业务语义的约束或状态竞争才映射为业务异常。

## 安全与追踪

- 响应不含原始异常、堆栈、SQL、内部地址或敏感值；校验问题不返回原始输入或内部上下文。
- 响应头 `X-Request-ID`、错误响应与日志使用同一有效标识，不重复或错配。
- 诊断仅保留错误码、异常链类别及脱敏位置，不记录异常文本、源码内容、局部变量、请求体、SQL 参数或认证数据。
- 响应开始后异常不再发送第二个响应，记录安全诊断并结束失败响应。

## 事务与并发

- [事务所属层](../architecture/backend.md#事务与任务)决定提交；异常与取消回滚并释放资源，清理失败不能掩盖原始异常。
- 失败事务不能返回成功；只有明确唯一或状态冲突才使用业务冲突。
- 提交结果不确定时，不能假设回滚撤销已提交数据；恢复须核实原操作。

## 幂等与安全恢复

- 幂等逐接口规定重复效果、请求标识和拒绝条件，资金写入使用持久去重，同键异输入拒绝，不能仅依赖 Redis 锁。
- 自动重试仅用于确认安全的读取或明确幂等操作，有上限和退避；409、超时和 503 不直接构成重试许可。
- 仅能承诺等待时间时返回 `Retry-After`；外部明确失败、超时与结果未知分别处理。
- 资金请求发出后结果未知，先查原单或核对，不建替代单、不直接认定失败；具体恢复见[支付模块](../modules/payment/recovery.md)。

## Webhook

- 运维接口遵循内部契约；渠道通知按对应协议验签、确认与应答，显式协议响应不被内部错误格式改写。
- 不假设所有渠道共用同一签名或重试方式，不复制通用异常转换；可靠接收与业务完成分别判断。
