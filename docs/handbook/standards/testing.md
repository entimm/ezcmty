# 测试规范

预期以现行模块规则、本次已确认方案、[API 契约](api.md)和[数据库规范](database.md)为依据。工具与命令见[检查与验证](../development/verification.md)，本规范不复制业务规则。

## 分类与边界

| 分类 | 验证边界                                     | 典型内容                                  |
| ---- | -------------------------------------------- | ----------------------------------------- |
| 单元 | 单组件，协作替身隔离，不启动外部服务或子进程 | 计算、转换、规则及契约检查工具算法        |
| 集成 | 多组件或真实外部依赖协作                     | API、会话、事务、迁移、并发、进程生命周期 |
| 契约 | 权威 OpenAPI 与运行入口一致性                | 接口集合、输入输出、错误、安全与运行归属  |

- 分类按实际验证边界，速度单独判断；使用内存替身的完整 API 流程仍是集成测试。
- 检查工具自身算法归单元，项目运行入口与契约比较归契约。
- 数据库保护用真实隔离 PostgreSQL，Redis 协议与原子行为用真实 Redis；替身不能代替这些保证。

## 组织与用例

- 按分类、业务与稳定职责组织，测试名称说明条件、行为或结果，不按开发日期或执行速度分类。
- Python 用例文件名以 `test_` 开头；公共准备与工厂集中共享，测试文件之间不相互导入。
- 全局准备只做环境和缓存通用清理，业务准备留在所属范围；只在实际需要时创建辅助能力。
- 一个测试围绕一个结果；相同规则多组输入优先参数化，每组可独立报告。
- 断言业务结果、持久状态、副作用和契约行为；仅在顺序、次数有明确要求时断言内部交互。
- 按风险选择层级，缺陷修复补可复现回归；纯文案、格式或文档不机械新增业务测试。
- 跨层覆盖关注不同边界，不镜像实现或重复堆叠；共享变更验证全部受影响端。

## 资源隔离

| 资源                    | 要求                                                                         |
| ----------------------- | ---------------------------------------------------------------------------- |
| 数据库                  | 每用例独立数据库，支持真实提交、回滚、锁和多连接；迁移专项保留从空库执行路径 |
| Redis、会话、环境和缓存 | 按用例隔离可变状态，不依赖执行顺序                                           |
| 进程、目录、端口        | 专用临时资源，只清理当前测试拥有的对象                                       |
| 账号准备                | 普通业务可用最小合法数据与真实会话，认证及密码专项保留真实完整流程           |
| 时间与并发              | 可控时钟、同步信号或有截止时间的条件等待，不用任意固定等待碰运气             |
| 异常退出                | 失败仍关闭连接和进程并清理所属资源，不能改写待验证事务行为                   |

- 不连接既有开发或生产业务数据执行测试写入与清理。
- 高成本服务可按测试进程复用，业务记录仍按用例隔离。现有数据库模板机制见[检查与验证](../development/verification.md)。

## 分级执行与结果

| 场景    | 必需范围                                             |
| ------- | ---------------------------------------------------- |
| 开发中  | 当前变更及相关回归，共享变更覆盖调用端               |
| 每次 PR | 全部单元、快速集成与契约检查                         |
| 合并前  | 完整集成，含真实 PostgreSQL、Redis 和进程生命周期    |
| 发布前  | 默认完整回归和关键业务流程，另核实目标环境与真实渠道 |

- 当前没有免测试发布开关。单次用户明确授权不执行的检查，仅在该次计划和交付中列明未执行范围、影响与限制，不建立通用豁免。
- 开发、PR、合并及发布要求分别满足；本地检查不能替代配置、权限、制品、网关、备份、迁移、健康检查、恢复演练、真机或真实渠道验收。
- 必需真实依赖显式启用；依赖缺失、目标未收集或整组跳过时，承担完整验证的任务必须失败。
- 区分通过、失败、跳过和未执行；预期失败和跳过不计为通过。未选择的本地依赖测试说明原因。
- 支持按业务与用例选择，慢速或专用依赖使用已登记标记；标记不能改变真实分类。

## 维护与评审

- 覆盖率辅助查缺，不代替关键规则、事务和并发验证；保留定位失败所需的报告与脱敏日志。
- 偶发失败应修复隔离、同步或依赖，不靠重跑掩盖；临时跳过须说明原因并关联问题。
- 测试调整保留有效覆盖，评审核对分类、被验证规则、依赖隔离和执行范围。
