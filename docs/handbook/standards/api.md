# API 规范

## 权威契约

- [OpenAPI 入口](../../../openapi/openapi.yaml)及其引用文件是精确接口契约的唯一权威来源，使用 OpenAPI 3.1。
- 先确认契约，再实现接口、输入输出与测试；自动生成的运行端 OpenAPI 只用于校验实现结果。
- 错误响应、权限、幂等性和状态码必须在权威契约中明确。
- 成功响应直接返回资源、数组或查询结果，不加统一包装；错误遵循[错误与异常](errors.md)。

## 组织与构建

| 对象           | 维护要求                                                 |
| -------------- | -------------------------------------------------------- |
| 契约入口       | 人工维护，通过引用组装模块与公共组件                     |
| 业务模块       | 按业务主题拆分，明显膨胀后再拆，不按运行进程集中成大文件 |
| 公共组件       | 复用实际需要的模型、参数、响应与安全方案，不预建空框架   |
| 聚合与生成结果 | 派生产物，不作为另一份人工权威定义                       |
| 运行归属       | 每个操作声明 `x-runtimes`，逐端拒绝缺失和多暴露的接口    |

运行归属使用 `platform_admin_api`、`property_admin_api`、`client_api` 或 `webhook`。Worker 没有业务 HTTP 接口，不要求每个 API 端实现全部契约。

检查覆盖接口集合、契约版本、错误目录、参数、请求体、状态、媒体类型、模型、响应头和安全方案。命令集中见[检查与验证](../development/verification.md#契约与前端类型)。

## 前端类型

- 两个前端均从权威契约生成类型，HTTP 字段、空值、枚举与请求参数不手写重复维护。
- 本地视图、表单草稿和会话状态由所属端维护；生成类型不能代替运行时校验或服务端授权。
- 类型生成在内存聚合契约，使用锁定版本工具，保持必填性、日期字符串和固定数组长度；默认值不自动将请求字段变成必填。
- 引用旁的属性约束等价转换为组合约束，兼容生成器并保留细化含义，原契约仍是权威来源。
- 安装依赖时生成声明；开发、类型、Lint、测试、构建及 API 检查消费前重新生成，失败即停止后续步骤。
- 小程序直接构建和原生检查同样生成类型；声明供编辑器使用，不提交、不手改。
- 输出使用原子替换，支持并发入口；内容不变时保留原文件。错误目录同样通过契约生成并检查一致性。

## 路径与格式

| 项目        | 要求                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------ |
| 路径        | 小写复数资源名词，多词用连字符；业务路径 `/v1/<resources>`                                 |
| 外部入口    | `/api/<audience>/v1/<resources>`；健康接口保留 `/healthz`、`/readyz`，Webhook 服从渠道协议 |
| JSON 与参数 | 字段、路径与查询参数用 `snake_case`；`operationId` 用 `verbObject`                         |
| 操作        | 标准资源操作优先 REST；不能表达时采用资源加明确动作                                        |
| 标识        | 遵循[数据库主键设计](database.md#主键设计)                                                 |
| 时间戳      | 带时区 RFC 3339，响应 UTC `Z`；有偏移输入转换 UTC，无时区输入拒绝                          |
| 日期        | 单独使用 `YYYY-MM-DD`，不当作时间戳转换                                                    |

| 方法        | 用途                 | 常用成功状态                       |
| ----------- | -------------------- | ---------------------------------- |
| GET         | 读取                 | 200                                |
| POST        | 创建或明确的业务操作 | 创建 201，异步受理 202，其余按契约 |
| PUT / PATCH | 完整替换 / 部分修改  | 200 或无响应体 204                 |
| DELETE      | 删除                 | 按契约，通常 204                   |

就绪依赖不可用是运维状态：503、`application/json`，不转换为业务错误包装。

## 分页、筛选与排序

- 分页输入 `page` 默认 1、最小 1；`page_size` 默认 20、范围 1–100。输出 `items/total/page/page_size`。
- 排序仅接受契约声明字段，使用稳定唯一键收尾；降序字段以负号表达。
- 筛选逐项声明类型和允许值，拒绝任意字段名、表达式或 SQL 输入。
- 记录、总数、汇总执行一致的授权与数据范围，不能先取全量再在前端隐藏。

## 版本与兼容

- 路径 `v1` 为业务主版本，`info.version` 为契约修订版本；运行时版本与生成目录一致，配置不能声明另一版本。
- 新增兼容字段仍评估消费者；客户端容忍新增响应字段，未知错误码按 HTTP 状态兜底。
- 删除或更名、增加必填、收紧值域、改变结构、媒体类型、状态或业务语义均按破坏性变更评审。
- 破坏性变更先确认影响与迁移；已发布版本需要兼容时通过新主版本过渡，不静默覆盖。
