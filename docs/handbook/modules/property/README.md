# 物业接入与工作台

本模块维护当前物业公司、小区、房屋档案及居民房屋授权。主题入口：[房屋与业主](housing.md)、[账单与线下账务](billing.md)、[认领与绑定](resident.md)。精确接口见[物业契约](../../../../openapi/modules/property.yaml)。

## 接入与归属

```mermaid
flowchart LR
    P[平台登记公司] --> D[公司初始停用]
    D --> A[开通公司超级管理员]
    A --> E[启用公司]
    D --> C[登记所属小区]
    E --> W[物业登录与工作空间]
    C --> B[房屋、账单和居民服务]
```

| 对象           | 当前规则                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 公司           | 新建时停用；启用前须有启用的系统超级管理员角色及至少一个有效超级管理员。没有小区也可启用。                             |
| 小区           | 新建时启用，固定归属一家物业公司；不提供跨公司迁移或物理删除。                                                         |
| 编码           | 公司、小区编码分别全局唯一且创建后固定；字母或数字开头，其后允许字母、数字、下划线及连字符，统一大写。名称不作为身份。 |
| 物业账号与角色 | 固定属于一家公司的物业后台，跨公司任职使用不同账号，角色不能跨公司分配；当前不配置指定小区授权。                       |
| 公司停用       | 撤销全部物业账号的旧会话，不改写账号、小区等对象自身启停；重新启用不恢复旧会话。                                       |

名称、地址等必填资料去首尾空白后不能为空；联系人和联系电话可空、可清空。联系电话只是联系资料，不是已验证手机号或认证依据，详细边界见[资料规格](../../../../openapi/components/property-schemas.yaml)。

公司停用期间可在平台补齐资料、小区和管理员。开通的公司管理员初始启用且须首次改密，账号、系统角色关联和审计共同提交；最后一个有效公司超级管理员不能被停用。

## 权限与数据范围

| 能力                   | 权限或前提                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------ |
| 平台接入读取／维护     | `platform.onboarding.read`／`platform.onboarding.manage`，维护包含读取。             |
| 平台启停公司           | `platform.onboarding.toggle`；同次修改资料还须接入维护权限。                         |
| 平台读取／管理公司账号 | `platform.system.read`／平台超级管理员管理能力，接入维护不授予账号管理。             |
| 物业基础上下文         | 完整会话即可取得公司标识、名称及可访问小区选项。                                     |
| 物业完整公司、小区资料 | 至少有房产、账单、居民授权、线上收款或系统资料的一种读取权限。                       |
| 物业系统资料／日志     | `property.system.read`／`property.audit.read` 分别授权；管理写入限本公司超级管理员。 |

公司来自已认证账号，请求不能切换公司。筛选只能缩小范围，越界详情按不存在处理；最小选项不授予完整房产、业主等业务读取。通用账号授权及会话见[身份模块](../identity/README.md)。

## 业务归属与操作者

业务所属公司与真实操作者分别表达。账单操作、认领审核和管理员撤销绑定的操作者关联只要求账号存在，不要求该账号与目标数据属于同一家公司；公司、小区、房屋、账单和认领来源的归属约束继续保留。

当前物业请求仍由认证账号确定公司，按本公司有效权限执行。平台账号公司归属仍为空，平台和小程序尚未接入本次共享物业业务；解除数据库操作者关联限制不授予跨公司访问。

审计保留真实来源、操作者和目标公司，与业务共同提交。业务历史的操作者名称仅从已授权记录关联的账号读取，不扩大账号资料或管理日志范围。系统入账保留系统来源，不将漏查的人工账号显示为系统。

## 接入操作一致性

公司启停、账号开通按共同公司保护顺序协调，写入前复核身份、权限及组织状态；业务与审计共同提交，唯一约束兜底并发创建。响应未知时按原对象、编码及审计核实，不换编码重复建档；唯一性冲突不能单独证明原请求成功。

## 工作台指标

工作台为**公司范围**，按北京时间当前月计算，不随顶部小区选择变化。

| 指标       | 口径                                                             | 读取权限                        |
| ---------- | ---------------------------------------------------------------- | ------------------------------- |
| 待审认领   | 本公司待审申请数。                                               | `property.resident_access.read` |
| 当月应收   | 本公司当月有效账单应收合计。                                     | `property.bill.read`            |
| 当月已缴   | 同一批当月有效账单净已缴合计，包含部分已缴，不按收款发生日统计。 | `property.payment.read`         |
| 待核对差异 | 可关联本公司支付订单、处于 `open` 或 `observing` 的差异数。      | `property.payment.read`         |

无权限指标为空，不显示为零或从其他数据推算；差异计数不授予平台完整账户数据读取。

- 房屋、账单等业务使用明确小区，公司范围页面另行标明。
- 切换小区先保护未保存内容，再清理失效选择与编辑状态；公司、小区选项逐页读取，不把首屏当全部。
- 当前物业端“小区资料”“收款信息”独立页面关闭，必要上下文及平台对应入口保留；页面开放不替代权限和后端范围校验。
