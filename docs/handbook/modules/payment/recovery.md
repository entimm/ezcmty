# 资金恢复与核对

恢复核实原事实并安排工作，受理不表示到账、分账或解冻完成。权限见[支付模块](README.md)，原子性见[数据与事务](data.md)。

## 持久任务

| 任务                 | 处理边界                                                         |
| -------------------- | ---------------------------------------------------------------- |
| 支付下单、查询和关闭 | 原业务号及输入不变，未知发送先核实原单，超时或面板取消不释放占用 |
| 通知                 | 验签、解密和持久去重后应答，异步处理；分账通知安排完整原执行查询 |
| 分账提交和查询       | 核实逐接收方结果，未知先查询，明确失败才补未履行部分             |
| 解冻提交和查询       | 独立核实实际结果；明确失败后保留历史继续解冻，不重启分账         |
| 核对                 | 保存可信来源，比较内部和渠道事实，完整发布本轮判定               |

同类型同目标任务合并；`ready` 领取为 `running`，完成、退避调度或暂停。过期租约可接管，业务提交检查代次及有效租约；可重试错误退避，身份、证据及资金矛盾暂停，不把未知当失败重做。

## 异常处理

| 现象                 | 恢复方式                                                       |
| -------------------- | -------------------------------------------------------------- |
| 面板取消、断网或超时 | 恢复原订单或请求，终态明确前不换键重付                         |
| 已收款待入账         | 保留证据及占用，修复后重入统一确认，不再次收款或手工记成功     |
| 未知分账、解冻       | 查原执行，无法确定就保留未知，不建替代单冒充失败重试           |
| 分账未履行或受理上限 | 保留义务及成功事实，阻止提前解冻，必要时核实外部处置           |
| 通知身份或金额不符   | 隔离并保留受控证据，不猜归属或补单                             |
| 暂停新单             | 已有通知、查询、入账、分账、解冻及核对继续，不能停全部资金任务 |

证据只存受控投影；密钥、签名、预支付凭证及下载凭据不得进入普通查询、诊断日志或客户端恢复存储。

## 核对流程

```mermaid
flowchart LR
    A[历史商户和平台账户] --> B[北京时间补齐缺日]
    B --> C[交易 / 分账 / 平台资金账单]
    C --> D[先保存可信来源]
    D --> E[比较收款、入账、应分和解冻]
    E --> F[原子发布判定、差异和公司汇总]
    F --> G[恢复原业务或外部处置]
```

- 截至前一业务日有界补缺日，包含停用历史商户；服务商身份已配置时，无商户绑定也可生成平台账户批次，不依赖进程内上次日期。
- 交易、分账和平台账户分开核对；跨日分账及记账按原业务号和执行关联，不强制落在支付日。
- 金额、状态和手续费独立判定；手续费以首次可信来源为准，未知不估算；解冻另核原执行实际金额。
- 来源先持久化，最终判定、差异、公司汇总、完成时间和任务确认共同封存；缺文件不是零交易，失败或失租约不发布半成结果。
- 差异为 `open`、`observing`、`resolved`，后续可重新打开；历次判定及处置依据保留，物业仅取得本公司可归属投影。

## 平台人工处理

| 动作                 | 权限和条件                                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 原支付或关联差异恢复 | `platform.payment.recover`；须关联原支付，合并原任务；成功支付只继续未完资金工作，关闭支付不恢复付款                    |
| 重新核对             | `platform.payment_reconciliation.manage`；恢复同批任务，不创建替代资金事实                                              |
| 外部处置             | 同时具备 `platform.payment_reconciliation.read`、`platform.payment.recover`；普通恢复已无法处理，差异未解决且核对未运行 |

写入须原因及当前 `expected_state_token`，复核权限和状态，与审计共同提交。旧令牌冲突后重读事实，不自动刷新令牌继续提交。

外部处置还需依据引用，只记录核实结论，不改订单、账单、占用、应分、执行或解冻事实。完整依据留受限审计，普通差异仅有摘要引用。精确能力见 [OpenAPI 资金管理](../../../../openapi/modules/payment-funds.yaml)。
