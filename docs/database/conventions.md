# 数据库规范

## 设计原则与文档要求

1. **先概览，后明细**：数据库设计应先提供表级概览，逐表说明职责、设计思路及主要关联关系，再给出各表的完整字段明细，包括字段名、类型、可空性、默认值及约束。除已有规范统一定义的基础字段外，其余字段均须说明含义和用途；基础字段通过引用统一约定说明，避免重复。
2. **字段保持必要、精简**：每个字段都应有明确的业务用途或工程必要性。缺乏具体使用场景、收益有限或仅为假设中的未来需求预留的字段，原则上不纳入设计。冗余存储应说明必要性及一致性维护方式。
3. **兼顾简洁性与可演进性**：保持表职责、数据关系和约束清晰，降低不必要的耦合，使后续业务扩展能够通过局部调整完成。对已知或可合理预见的变化，说明扩展方式及限制，避免以扩展性为由引入过度抽象或大量预留字段。

## 基础约定

- 使用 PostgreSQL 18.x，数据库编码为 UTF8，字符串使用确定性、大小写敏感的排序规则。
- 使用 SQLAlchemy 2.x 同步 Session 和 Psycopg 3，连接协议为 `postgresql+psycopg`。
- 金额统一使用整数分，禁止浮点数；需要大范围整数时使用 `BIGINT`，正值范围通过 CHECK 约束表达。金额字段名称必须以 `_cents` 结尾，例如 `amount_cents`、`balance_cents`、`rebate_cents`、`property_fee_cents`。费率、比例及数量字段不适用此后缀。
- 所有表示时间点的字段统一使用 `timestamptz(6)`，应用生成带时区的 UTC 时间，应用和迁移连接均显式设置 UTC。日期字段使用 `date`。
- JSON 文档使用 `jsonb`，索引按实际查询需求建立。
- 数据库结构变更统一通过 Alembic 迁移，利用 PostgreSQL 事务性 DDL；不在应用启动时自动执行结构变更。
- 已发布、已应用的迁移保持不可变。当前建库基线面向空 PostgreSQL 数据库，不承接其他数据库的数据或版本记录。
- 当前 MVP 使用单数据库，暂不拆库或读写分离。

数据库访问与事务边界的分层职责见 [系统架构](../architecture/overview.md#后端分层)。异常回滚、并发冲突及提交结果不确定时的处理见 [错误与异常规范](../api/errors.md#事务与并发)。

## 主键设计

1. 所有实体表必须定义主键，优先使用单列代理主键，统一命名为 `id`。
2. 默认采用应用层生成的 UUIDv7，使用 PostgreSQL 原生 `uuid` 存储；业务层、会话与 API 使用小写标准 UUID 字符串。
3. 纯内部、高写入量的表可采用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`；小型字典表可采用 `INTEGER`。
4. 纯关联表可采用复合主键，是否使用代理主键根据实际需求决定。
5. 外键类型必须与被引用主键保持一致，审计中的 UUID 引用同样使用 `uuid`。
6. 输入校验接受带连字符的 UUIDv4 和 UUIDv7，不接受无连字符或带大括号的形式；新建实体默认值禁止使用 UUIDv4。
7. 主键必须唯一、非空、不可变，不承载业务含义；业务唯一性通过 UNIQUE 约束保证。
8. 保留独立、非空的 `created_at` 字段，不依赖 UUIDv7 判断精确创建顺序；角色及关联表同样遵循此要求。

## 字符串与约束

- 标识按所属业务规则在校验允许字符后规范化，数据库用 CHECK 约束规范形式，再以普通唯一约束保证唯一性；登录名规则见 [后台账号设计](../design/admin/foundation.md#账号归属与授权上下文)，组织编码规则见 [物业接入设计](../design/property/onboarding.md#物业公司与小区)。
- 普通字符串保持大小写敏感；名称保留原始大小写，名称包含搜索显式使用 ILIKE，并转义用户输入中的 `%`、`_` 和转义字符。按实际执行计划决定是否使用 `pg_trgm` 索引。
- 布尔字段使用原生 `boolean`，数据库默认值使用 `true`、`false`。
- 可空字段参与唯一性约束时必须明确 NULL 语义；平台和公司角色编码使用 `UNIQUE NULLS NOT DISTINCT (property_company_id, code)`。
- 保留承担后台和公司隔离职责的复合外键及其被引用唯一约束；外键引用端按实际查找和删除检查需要建立索引，不能依赖数据库自动建立。

## 连接、事务与查询

- 默认事务隔离级别为 READ COMMITTED。分页记录与总数使用同一 SQL 语句读取，保证同一语句快照下的一致性，空页同样返回准确总数。
- 写操作使用稳定的父记录或系统角色行协调并发，并保持固定锁顺序；加锁查询显式限定必要的目标表。不存在记录的创建竞争由唯一约束保证。
- 应用连接超时为 3 秒，语句超时为 10 秒，锁等待超时为 3 秒，空闲事务超时为 60 秒；连接池等待超时为 3 秒。迁移连接只设置连接超时及 UTC，不套用应用的短语句超时。
- 唯一性业务冲突通过 SQLSTATE `23505` 及明确约束名识别；连接故障与服务器不可用按明确的 SQLSTATE 或驱动连接状态分类。死锁、语句取消和未知约束错误不能一律当作依赖不可用或允许重试。
