# 账单支付开发实施计划

## 用途与执行边界

本文件是账单支付的分阶段执行清单，用于跟踪实施任务和验收；业务、数据、API 和架构规则仍以对应权威文档为准，不在本文件重新定义。

计划落盘不代表开发授权。实施须等待用户明确授权；只授权部分阶段时，完成该范围后停止。迁移执行、真实渠道操作和部署按后续明确授权范围进行。各阶段通过不等于可以开放真实收款。

所有任务初始未勾选。实施任务完成后才勾选，验收项须有实际验证结果；未执行、失败、跳过或仅由替身验证的真实渠道能力不得记为通过。阶段交付说明列出完成范围、检查结果、未完成项及后续依赖；详细日志和运行结果不追加到长期设计文档。

### 权威依据

- [居民账单支付与资金处理](../../design/payment/bill-payments.md)：业务、权限、资金流程及交互。
- [支付与分账数据设计](../../design/payment/bill-payments-and-profit-sharing.md)：表、约束、状态、锁序及恢复。

- [管理后台架构](../../architecture/admin-web.md)、[小程序架构](../../architecture/miniapp.md)：前端目录、状态、权限及请求隔离。

范围保持单公司一个有效商户、单账单全部余款支付、当前平台一个接收方。退款、线上进件、合并支付、部分付款、按小区收款和返利抵扣不在本次开放范围。

## 阶段 4：支付、原子入账与安全关闭

代码归属：居民支付、Webhook 及 Worker 的 `orders.py`、`confirmation.py`，共享账单入账和支付 Domain。

### 4A：订单与支付资格

- [ ] P4-01 提取居民公共 HTTP 依赖和路由组装，接入支付路由，不从其他业务路由导入身份处理。
- [ ] P4-02 实现本人订单列表、详情、固定账单摘要及授权；本人历史读取与当前房屋绑定分开判断。
- [ ] P4-03 实现幂等创建、账单版本和全部余款校验，原子创建订单、明细、占用及恢复任务。
- [ ] P4-04 实现下单、主动查询、调起参数签发、刷新和关闭，未知结果始终恢复原号原参数。
- [ ] P4-05 实现到期或房屋授权失效订单的有界周期扫描，按固定锁序安排原单核实和关闭，不直接清占用。
- [ ] P4-06 签发参数及下单前重新核验当前授权；解绑或停用后不再签发，旧商户绑定停用不错误替换原订单配置。

### 4B：可信收款与唯一入账

- [ ] P4-07 实现支付成功通知原文验签、可靠去重、隔离、处理任务及渠道专用 ACK，保存失败按渠道协议处理。
- [ ] P4-08 通知与主动查询共用唯一 `confirmation.py`，核对原订单身份、交易号、金额和可信支付事实。
- [ ] P4-09 实现按冻结规则计算应分，覆盖 half-up、零应分及多接收方结构；同事务提交支付成功、逐明细系统账务、汇总与版本、应分、首笔执行及任务、原占用释放，零应分同事务创建解冻单及任务。
- [ ] P4-10 实现证据先持久、`awaiting_posting` 派生及原子入账失败恢复，不将“已收款待入账”误记为完成。
- [ ] P4-11 实现基础管理支付记录查询，支持追溯支付、账单与确认状态。
- [ ] P4-12 补齐应分舍入边界、零应分、多接收方计算、多付款人及线下竞争、通知查询竞争、未知响应、进程中断、入账回滚、授权失效和关单竞态测试。

### 阶段验收

- [ ] P4-A1 同账单只允许一个占用，同键同输入恢复原订单，网络未知或客户端取消不换单付款。
- [ ] P4-A2 通知与查询并发仅入账一次；逐明细幂等和任一步失败整体回滚均通过验证。
- [ ] P4-A3 已收款待入账保留证据与占用，当前解绑、撤权或停用不能拒绝真实收款。
- [ ] P4-A4 支付关单竞争正确，仅可靠终态或可靠阻止发送后才能关闭并释放原占用。
- [ ] P4-A5 普通 GET 不调渠道、不安排任务、不签发参数；Webhook ACK 只表示可靠接收。

## 阶段 5：分账与独立解冻

代码归属：Worker 的 `profit_sharing.py`、`unfreezing.py`，资金 Domain、Repository 和管理接口。

### 实施任务

- [ ] P5-01 基于阶段 4 已生成的不可变应分实现履行核验，区分应分义务和执行结果，支持多接收方结构；当前公开配置仍仅平台接收方。
- [ ] P5-02 实现首次分账延迟调度、提交、查询及逐接收方结果，区分执行结束与接收成功。
- [ ] P5-03 实现明确失败后的未履行部分补足、未知原单查询、有界恢复及渠道受理次数限制，不把调用次数当作受理次数。
- [ ] P5-04 实现解冻前置条件、支付父记录锁和永久解冻屏障，建立解冻单及任务。
- [ ] P5-05 实现独立解冻提交、查询、实际金额确认和零应分直接解冻，不推算物业到账金额。
- [ ] P5-06 接入分账动账通知佐证，不能以此替代整单分账或解冻查询。
- [ ] P5-07 补齐管理分账、解冻记录与原资金流程恢复接口，恢复权限、原因、任务和审计一致提交。
- [ ] P5-08 补齐部分成功、未知、重复恢复、资金不足、受理限制、解冻屏障及真实数据库竞态测试。

### 阶段验收

- [ ] P5-A1 成功部分不重复分配，未知及在途金额不另建执行，累计成功不超过应分。
- [ ] P5-A2 任一解冻单建立后不能新增分账，解冻失败只恢复解冻。
- [ ] P5-A3 `no_remaining` 不冒充服务费到账；无可信金额时保持未知，资金异常不撤销居民缴费。
- [ ] P5-A4 分账与解冻竞争、租约接管及重复恢复均符合资金不变量。

## 阶段 6：资金核对、自动补齐与差异处置

代码归属：Worker 的 `reconciliation.py`、账单 Integration、核对 Domain/Repository 及管理端支付 Service/API。

### 实施任务

- [ ] P6-01 实现内部一致性、交易账单、分账账单、平台基本账户资金账单及解冻按单核验。
- [ ] P6-02 实现启动与周期生产者，按实际账户、业务日历和历史绑定生成首次批次、分页补齐停机漏日，多个 Worker 安全合并。
- [ ] P6-03 实现下载、来源摘要核验、文件解析、跨日关联和同口径比较；文件缺失或失败不视为零交易。
- [ ] P6-04 实现批次唯一性、稳定差异键、不同核对维度、公司汇总及物业受限投影。
- [ ] P6-05 实现差异新建、观察、解决和重开，保存必要判定依据及管理员历史关联，不覆盖旧处置依据。
- [ ] P6-06 独立保存可信下载来源，再在受任务代次保护的事务中封存判定快照、批次、差异、任务确认和 `finished_at`，不发布部分结果。
- [ ] P6-07 实现重核对和差异恢复，进入原支付、入账、分账或解冻能力，不新增另一条资金成功路径。
- [ ] P6-08 实现独立外部处置接口，核验读取与恢复权限、差异令牌、依据引用和适用条件，处置与审计同事务保存，不改资金或猜测关联。
- [ ] P6-09 补齐跨日、漏日、历史停用商户、重复触发、文件缺失、判定回滚、租约接管、差异重开及外部处置测试。

### 阶段验收

- [ ] P6-A1 停机多日及多 Worker 触发可补齐漏日，停用历史绑定不遗漏资金，已完成日期不盲目重跑。
- [ ] P6-A2 文件缺失不作为零交易，支付、分账及资金记账跨日可正确核对。

## 分支集成与阶段交付规则

使用一个支付集成分支承载分阶段提交，阶段任务与对应验证一起交付。迁移、共享账单、生成目录、权限及路由装配由同一集成人协调，其他工作按模块并行，保持单一迁移链。

开发初期契约领先实现，阶段内执行定向测试和受影响回归，报告剩余完整契约缺口。中间提交用于阶段审查，不能在完整契约未收敛时作为可合并或可发布版本。不删契约、不弱化检查、不加绕过、不用空壳路由制造通过；完整门禁遵循测试规范。

每阶段交付至少说明：对应任务编号和完成范围、实际检查结果、未完成项及原因、下一阶段依赖。任务受阻时只保留必要状态与依据引用，不把未完成或仅通过替身的真实能力勾选为完成。

阶段 8 的工程验收、真实渠道验证及发布准备分别判断；只有后续明确授权包含相应操作时才执行迁移到目标环境、真实资金操作或部署。本清单本身不扩大授权。
