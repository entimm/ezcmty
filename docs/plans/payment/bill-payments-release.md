# 账单支付发布与恢复准备

本清单用于[实施计划阶段 8](bill-payments.md#阶段-8完整验收真实渠道验证与发布准备)。部署边界沿用[部署约定](../../architecture/deployment.md)，业务及恢复规则沿用[支付设计](../../design/payment/bill-payments.md)，接口以 OpenAPI 为准。本次只准备和隔离演练，不执行目标环境写入、真实资金操作或部署。实际检查结果见[实施证据](bill-payments-evidence.md)。

## 发布顺序

1. 核准目标环境、维护窗口、操作人及独立发布授权；记录当前应用版本、迁移 revision、数据库备份位置和恢复验证结果。冻结未经评审的支付配置修改。
2. 保持 `APP_PAYMENT_NEW_ORDERS_ENABLED=false`。停止旧 Worker 并排空执行，保留四个 API 的维护方式；不能在新表尚未迁移时启动新支付 Worker。
3. 通过现有依赖方式安装锁定依赖，构建管理后台、小程序和后端发布包；发布包排除 `.dev/`、测试密钥、原始账单和开发 seed 工具。
4. 使用受控连接取得 PostgreSQL 一致性备份，在独立环境实际恢复并验证。确认能够读取旧账单、线上流水、应分、执行、任务和迁移版本；只完成备份文件生成不足以开放新单。
5. 经单独授权，将目标数据库从 `20261017_house_claims` 升级至 `20261019_bill_payments`。不执行 seed；核对迁移单一 head、Model 注册和旧账单可读。此步骤不是本次执行命令。
6. 注入受控商户配置并启动五个既有运行入口。检查 Worker 的 `scheduler=running task_handlers=9` 就绪标记、存储连接及两个周期检查；仅进程存在不算就绪。缺少商户材料时 Worker 可以调度，但渠道任务不能据此验收通过。
7. 在新单开关关闭时验证旧账单与线下收款，以及已有支付通知、查询、入账、分账、解冻和核对。发布期间仍保持 HTTPS Webhook 可达；不能为暂停新单而停止所有资金任务。
8. 完成独立授权的真实渠道验收、回调域名和小程序真机验收，复核商户绑定、平台接收关系、冻结费率及渠道比例。仅当这些条件与工程验收均满足，才按后续开放授权启用新订单。

## 回退与备份恢复

尚无新支付写入时，可以在维护窗口按已验证的应用兼容条件回退。出现任何支付、通知或资金任务后，优先关闭新单、保留兼容新表的四个 API 与 Worker，并修复前进；不能使用删除支付表、回退成功状态、清除占用或换单号的方式恢复。

数据库整库恢复需要独立事故授权和停写协调。备份时间点之后可能已有渠道收款或分账，恢复旧备份本身不能撤销这些外部事实。恢复后必须用原商户、原业务单号和已有可信证据重新查询及核对，再决定业务恢复顺序。PostgreSQL 与 Redis 的恢复含义不同：Redis 会话丢失要求重新登录，不能据此重建支付订单。

隔离演练使用临时 PostgreSQL 的 `pg_dump --format=custom --no-owner --no-privileges` 和 `pg_restore --exit-on-error --no-owner --no-privileges`，目标为另一个全新临时数据库。验证完整支付链、账单余额、唯一收款流水、应分履行、实际解冻金额及不可变数据库保护；不会读取或写入现有业务库。

## 日常检查与恢复

以下检查由有对应权限的平台人员执行。页面及接口响应保持禁止缓存，记录工单号和管理员审计请求 ID。普通读取不生成任务、不签发支付凭证、不调用渠道。

| 检查对象           | 判断依据                                                                                                        | 恢复方式                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 持久任务积压       | 按 `task_type/status` 查看数量、最早 `next_run_at`、过期租约和有界 `last_error`；核对 Worker 就绪及周期检查日志 | 修复依赖后由 Worker 领取或接管；需人工操作时使用带原因和当前令牌的原目标恢复入口                     |
| 未知支付与长期占用 | 支付状态、原请求是否发送、固定过期时间、原商户查询证据；超时不等于关闭                                          | 查询原单，必要时原单关单再核实；只有可靠不可支付终态或未发送取消才能释放                             |
| 已收款待入账       | 管理支付筛选 `confirmation_status=awaiting_posting`，核对账单及持久可信来源                                     | 修复入账冲突或数据库问题后恢复原单；唯一确认用例再次原子应用，不手工补记成功                         |
| 通知隔离           | 通知类型、隔离状态、身份及金额核验失败诊断；禁止输出解密原文和 OpenID                                           | 修复正确关联或配置后核实原业务；未知归属不能猜测补单。可信证据保留，不靠再次收到通知恢复             |
| 分账未履行         | 不可变应分减逐方累计成功；在途、未知、失败分别识别                                                              | 未知先查原执行；只有可靠失败金额可补执行。受理次数已达上限或存在解冻屏障时转外部异常处理             |
| 解冻异常           | 独立解冻状态和可信实际金额；`no_remaining` 不证明服务费取得                                                     | 查原解冻单；失败后仅恢复解冻。任何解冻单都永久禁止新建分账；未知金额不估算                           |
| 核对缺日或来源缺失 | 历史真实账户范围、最近应核日期、批次状态及来源摘要；缺文件不视为零交易                                          | 周期生产有界补齐；来源晚到时恢复原批次。判定失败保留先存来源，不发布部分结果                         |
| 资金差异           | 当前维度、来源请求、应有/实际、稳定关联及历次审计                                                               | 优先恢复关联原业务并重核对；无法正常恢复时，双权限核实外部依据后单独记录处置。处置记录不改变资金事实 |
| 接近渠道期限       | 已付款时间、未履行应分、在途执行及预计 30 天自动解冻期限                                                        | 持续查询并提前处理资金异常；自动解冻后保留缺失服务费义务，不再次向居民收款                           |

只读数据库诊断示例（使用受控只读连接，不输出渠道凭证）：

```sql
SELECT task_type, status, count(*) AS count,
       min(next_run_at) AS earliest_due,
       min(lease_expires_at) FILTER (WHERE status = 'running') AS earliest_lease
FROM payment_tasks
GROUP BY task_type, status
ORDER BY task_type, status;

SELECT status, count(*) AS count, min(created_at) AS oldest_created
FROM payment_channel_notifications
GROUP BY status;

SELECT status, count(*) AS count, min(paid_at) AS oldest_paid
FROM payment_orders
GROUP BY status;
```

日志只保留有界错误码、请求 ID 和任务生命周期，不复制私钥、APIv3 密钥、签名、预支付凭证、原始通知或下载 URL。完整原因及外部依据通过受限管理员审计追溯。恢复请求响应未知时先重新读取详情和审计，不自动换令牌重试。

## 尚待独立授权的检查

- 真实商户材料、平台接收关系、分账能力和实时上限。
- 受控小额付款、可信回调与主动查询、唯一入账、分账到账和实际解冻。
- 真实渠道交易、分账及平台账户账单的跨日核对。
- 小程序真机交互、HTTPS 回调和合法域名。
- 目标环境备份恢复、迁移、部署及新单开放。

本地工程通过、发布清单准备完成和真实资金验收分别判断；任何一项不能替代其余条件。
