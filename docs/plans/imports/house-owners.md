# 业主登记批量导入实施计划

依据 [业主登记导入设计](../../design/property/house-owner-imports.md)、[共享业主登记能力](../../design/property/housing.md#共享业主登记能力) 及 [通用导入架构](../../design/imports/architecture.md) 实施。用户已确认方案并授权落盘及实施；仅实施本次范围，不部署或导入真实业务数据。每项完成并验证后才勾选。

## P0：设计与基线

- [x] P0-01：建立独立实施分支，核对手工、初始业主和通用导入基线。
- [x] P0-02：落盘业务设计及共享能力边界，核对 API 契约，先维护所需契约说明。

## P1：共享登记能力

- [x] P1-01：依赖 P0，提取普通登记命令、规范化、业务身份、判重及固定目标复核，不依赖导入或 HTTP Schema。
- [x] P1-02：提取参与调用方事务的共享编排、写入和审计，接入独立新增及建房初始业主，保留原响应及整体事务。
- [x] P1-A1：业务单元及手工回归通过，覆盖字段边界、手机号、重复、权限、启停及审计原子性。

## P2：导入类型接入

- [x] P2-01：依赖 P1，新增不可变 `house_owners` 模板、薄适配器及生产注册，仅物业端、小区范围、创建模式。
- [x] P2-02：接入共享房屋定位、预检及执行，完成重复、停用跳过、固定目标重跑、结果复用和未知结果核实。
- [x] P2-03：成功或跳过结果复用、未知跳过恢复使用共享保护性只读复核，验证与手工编辑交错时完整锁序和固定目标保护。
- [x] P2-A1：API 及隔离 PostgreSQL 验证通过，覆盖 CSV/XLSX、严格模板、预检无写入、并发、回滚、失权与读取隔离。

## P3：管理后台

- [x] P3-01：依赖 P0，增加小区房屋列表业主导入入口、范围提示、业务预览及返回和缓存刷新。
- [x] P3-A1：前端回归通过，覆盖独立创建权限、当前小区、整小区范围、敏感字段投影和跳过提示。

## P4：验证与交付

- [x] P4-01：依赖 P1–P3，完成后端 Ruff、mypy、单元、API、真实 PostgreSQL、认领、导入及 wheel 资源回归。
- [x] P4-02：完成前端格式、类型、Lint、测试及构建，运行 API 契约与文档引用检查。
- [x] P4-A1：核对共用调用链及任务范围，报告实际验证、未执行项及遗留风险，完成后停止。
