# 通用批量导入实施计划

## 范围与验收边界

依据 [设计总览](../../design/imports/overview.md)、[数据库设计](../../design/imports/database.md)、[API 设计](../../design/imports/api.md)、[交互设计](../../design/imports/interaction.md) 和 [技术架构](../../design/imports/architecture.md) 实施通用能力。

范围包括八张运行表、版本配置注册、文件解析、持久任务、预检确认、执行幂等、原任务恢复、错误文件、保留清理、平台与物业 API 和后台页面。生产导入类型目录为空，不新增房屋、业主、账单等业务模板、适配器或列表按钮，不提取或重构其写入流程。

完整流程通过测试目录中的适配器和隔离数据验证；测试类型不进入生产注册表，不增加 HTTP 或环境配置方式开放的生产测试入口。生产空目录正确展示与拒绝未注册类型，属于正式验收条件。

本计划记录实施依赖与验收，不代表未完成项已经实现。仅在对应实现和检查均完成后勾选。

## P0：设计与契约准备

- [x] P0-01：同步八表、请求幂等、批次行结果、统一状态与版本、确认策略及敏感数据清理设计，消除跨文档未决定义。
- [x] P0-02：固定通用能力边界、空生产注册表和仅用于测试的适配器验收方式。
- [x] P0-03：完成 [OpenAPI 导入模块](../../../openapi/modules/imports.yaml) 及共享组件的精确 Schema、权限、错误、状态和文件协议，由 [根入口](../../../openapi/openapi.yaml) 引用。
- [x] P0-04：核对本计划的依赖、工作拆分和验收条件，明确 OpenAPI First 及实施后的各运行端一致性检查要求。

根契约通过模块与共享组件表达导入设计；P0 只确认契约准备。运行端 Schema、路由、错误映射及各端一致性由 P5 验收，不得放宽检查以忽略未实现接口。

## P1：领域、数据与迁移

依赖 P0。验收以真实隔离 PostgreSQL 为准。

- [x] P1-01：实现普通领域类型、批次流转、阶段与操作结果规则、配置摘要、操作键及阶段 checkpoint 校验。
- [x] P1-02：实现八表模型与 Alembic 迁移，落实公司、后台、批次复合归属、NULL 语义、状态 CHECK、唯一约束及必要索引。
- [x] P1-03：实现 `import_requests` 持久请求幂等，同键异输入拒绝、并发竞争回滚后恢复首次响应；上传外部文件不伪装成数据库原子事务。
- [x] P1-04：实现输入行、当前逻辑操作、本批次结果与统计的独立职责，验证重跑不改原批次历史，取消不改共享操作。
- [x] P1-05：实现预检代次分配、成功发布、解析问题可见性和阶段问题去重，验证半成预览不被确认。
- [x] P1-06：更新测试 Harness 表集合及 seed 表覆盖判定，验证空库升级、数据库原生约束和全部现有数据模型回归。

## P2：文件、配置与安装制品

依赖 P1 的身份和元数据模型。

- [x] P2-01：补齐明确的文件上传与 XLSX 读取运行依赖和锁文件；CSV 与 JSON 配置使用标准库，不依赖间接安装的配置解析包。
- [x] P2-02：实现私有本地存储，开发和测试使用独立临时目录；校验完整性、稳定对象键、权限、安全文件名、孤儿对象和失败删除重试。
- [x] P2-03：实现 CSV 完整记录与多字节安全偏移、XLSX 工作表行恢复，落实大小、行列、解压和公式等文件限制。
- [x] P2-04：实现不可变配置注册与适配器协议、启动校验、摘要比对；生产注册表为空，测试注册表只由测试组装注入。
- [x] P2-05：将配置资源显式装入 wheel，以安装制品验证可加载性、旧版本与摘要一致性；不以源码目录可读代替发布验证。

## P3：Worker 与清理调度

依赖 P1，文件访问依赖 P2。

- [x] P3-01：以窄任务来源和租约接口扩展既有 Runner，保留支付任务的领取、续租、停止、恢复和周期生产语义。
- [x] P3-02：实现导入任务领取、分块让出、续租、接管与提交前代次保护；验证支付及时领取且导入不会长期饥饿。
- [x] P3-03：复用现有 Worker 周期检查执行有界清理，不新增清理 phase；保护活动任务、未知结果和必要恢复证据。
- [x] P3-04：验证正常停止、崩溃接管、旧执行者回写拒绝、独立会话及网络和文件 I/O 期间无长事务。

## P4：通用导入处理链

依赖 P1–P3。使用测试适配器验证，不接入实际业务。

- [x] P4-01：实现解析、暂存、规范化、问题和操作计划，分块进度与 checkpoint 同事务更新。
- [x] P4-02：实现重新预检、确认令牌、持久执行策略、警告选择和选中行集合；错误边界不能通过跳过行绕过。
- [x] P4-03：实现确认后执行、当前业务操作账本及本批次行结果原子提交，验证并发重复和提交响应未知恢复。
- [x] P4-04：实现协作取消、明确可重试失败行的新批次、重新预检和再次确认；未知结果仅按原任务和原操作核实恢复。
- [x] P4-05：实现指定预览版本的错误文件分片、稳定生成代次、最小安全字段投影及最终发布；半成文件不开放下载。
- [x] P4-06：验证清理后的历史展示、输入不可用提示、重跑和重建关闭、敏感自然键处理及原统计可重算。

## P5：API 实现与契约一致性

依赖 P0 契约及 P4 用例边界，按已落盘契约实现。

- [x] P5-01：依据根契约实现请求响应 Schema、权限及错误映射；登记已实现的领域错误并生成错误目录，维护契约版本与生成目录的一致性，不提前登记未实现领域码。
- [x] P5-02：实现平台、物业各自的授权与范围 Service、HTTP 组装和白名单投影；不通过公共导入权限扩大实际业务授权。
- [x] P5-03：实现批次、上传、预检、确认、取消、重跑、恢复、行、问题、时间线及文件接口，所有写请求按原键恢复。
- [x] P5-04：验证生产空目录、未注册类型拒绝、后台与公司隔离、CSRF、文件字段权限、流式下载和禁止缓存。
- [x] P5-05：完成各运行端契约一致性检查；不得使用测试适配器注册生产类型或跳过接口集合校验。

## P6：管理后台

依赖 P5 契约和响应投影。

- [x] P6-01：注册两端导入中心、创建、详情和权限菜单，复用当前端请求与 QueryClient；业务列表保持本次范围之外。
- [x] P6-02：实现类型和范围选择、模板字段、上传、进度、预览、确认、结果、时间线、错误文件与恢复交互。
- [x] P6-03：实现空类型目录提示和禁用新建；通过前端替身及隔离集成环境验证非空目录流程。
- [x] P6-04：实现复用会话隔离的上传下载客户端、请求取消、超时原键核实、活动轮询及身份变化清理。
- [x] P6-05：通过类型、Lint、前端测试及构建，验证行定位、统计分组、旧历史稳定、策略显式确认与权限失效。

## P7：完整验收

依赖 P1–P6 全部完成。

- [x] P7-01：执行数据库并发及故障注入：重复确认、操作键竞争、取消与提交竞争、租约接管、部分成功、未知结果恢复和原历史稳定。
- [x] P7-02：执行真实文件及容量验证：CSV 跨行和编码、XLSX 恢复、文件损坏、解压限制、错误分片、30 天清理、私有下载和磁盘故障。
- [x] P7-03：执行安装后配置、缺失或漂移阻断、旧版本恢复与发布回滚兼容检查。
- [x] P7-04：执行支付与导入混合负载、Worker 生命周期及现有支付回归，确认运行内存、领取和续租要求。
- [ ] P7-05：完成 Ruff、格式、mypy、pytest、TypeScript、ESLint、Vitest、构建、OpenAPI lint/bundle 与各端契约检查；运行项目要求的完整隔离测试。
- [x] P7-06：核对生产没有业务导入类型、模板、适配器或业务列表改动，报告实际验证、未完成项及交付边界后停止本阶段。

实施及专项验收已完成，实际命令、结果与边界见 [验收记录](verification.md)。P7-05 的各专项检查和完整隔离测试均通过；全仓 `make check` 被未修改的 `deploy/staging/README.md` 既有 Prettier 问题阻断，因此该项暂不勾选。不在本任务内修改该文件，也不将全仓门禁报告为通过。

本计划不包含部署执行、业务数据导入或后续业务接入。发布准备遵循现有部署约定；真实环境写入不作为本地验收的一部分。
