# 测试服务器关键配置归档实施计划

范围：按用户确认的精简方案，将关键配置统一归档到根目录 `deploy/staging/`：`nginx/`、`systemd/`、`certbot/`、`env/`、`postgresql/`、`redis/`，并提供简短安装映射 README。沿用当前独立工作树，保留已完成 IP 入口改动。只读访问服务器，不改动实际配置、服务、数据或证书；用户已授权目录迁移及提交当前部署相关改动，不合并或推送。

依据：[部署设计](../../architecture/deployment.md#测试服务器关键配置归档)、[基础环境指南](../../guidelines/staging-environment.md)、[发布指南](../../guidelines/staging-release.md)。

- [x] 归并原 IP 入口文件，补齐域名 Nginx、五个应用服务、域名证书 hook / 依赖锁与两套签发参数模板、PostgreSQL / Redis 项目片段。
- [x] 补齐应用、迁移、DNSPod 脱敏模板；核对字段、环境值、Origin、Cookie、数据库角色及占位符，排除真实密钥与账号凭据。
- [x] 编写唯一文件安装映射 README，修正原路径引用；设计、发布、维护流程继续复用现有权威文档。
- [x] 完成源文件与服务器只读比对、配置静态验证、模板与依赖检查、文档格式和链接检查；只在完成验证后勾选并交付实际结果。

验收条件：关键配置分类清晰、无重复来源；原 IP 文件完整迁移且所有引用有效；非模板配置与当前服务器一致，模板无真实敏感值且字段可用；README 标明路径、权限、前置条件和生效验证方式；不改变服务器运行状态。

完成结果：原 9 个 IP 文件完整归类，新增 11 个服务器配置源、域名依赖锁及 5 个脱敏示例；共 26 份配置、模板和锁，另有索引及忽略规则。19 个实际配置源逐一通过服务器 SHA-256 比对。Nginx 配置检查、systemd 单元校验、两个 hook 的 shell 语法检查通过；PostgreSQL 项目片段均已应用且无解析错误，Redis include 和有效参数符合归档片段。8 个常驻服务的主进程未变。

模板验证：运行及迁移示例均能被现有 Settings 解析，未连接数据库或 Redis；四端 API 和 Worker 可构造。DNSPod 示例由现有插件解析通过；域名和 IP 签发示例分别由 Certbot 4.0 / 5.8 纯 CLI parser 解析通过，禁用默认配置读取，未执行签发或续期。两套依赖锁的 20 / 17 个包与离线 wheel 哈希匹配，24 / 21 条依赖边闭包完整。真实凭据及证书运行状态不进入归档，忽略规则检查通过。

文档与范围：格式、变更空白、本地链接及锚点检查通过，已清除旧配置目录引用；只读复审通过。systemd 检查提示云代理与发行版 XFS 单元的既有兼容警告，未涉及本项目单元且未扩展修复。检查证据保留在操作机忽略目录 `build/deployment-verification/staging-config-archive-checks-20261020.json`、`staging-certbot-*-20261020.json`。初次归档阶段未改动服务器配置、重启服务、执行数据库迁移或提交代码。
