# 测试环境应用发布实施计划

范围：将 GitHub 项目仓库的默认分支或用户指定版本部署至 `xcmty`，通过 `github-deploy` SSH 别名及现有部署密钥取码。用户已授权程序部署及 sudo；真实资金验收、支付新单开放和小程序上传不在本次范围。

依据：[部署约定](../../architecture/deployment.md#测试环境应用发布)、[测试规范](../../conventions/testing.md)、[账单支付发布与恢复准备](../payment/bill-payments-release.md)。

- [x] 盘点目标服务器，确认无既有业务库、应用进程及发布版本；保留基础环境配置和默认拒绝站点。
- [x] 验证部署密钥、GitHub 主机身份及仓库访问，确定默认分支或指定版本并固定提交 SHA；直连不可用时采用受控临时回环转发。
- [x] 完成目标版本发布门禁；相同 Git tree 复用证据，差异部分独立验证；记录真实失败、跳过和未执行项。
- [x] 服务器取码并准备排除敏感文件及开发工具的版本目录，按锁文件安装 Linux 运行依赖；构建并传输对应版本的后台静态产物。
- [x] 创建受限运行角色、迁移角色和独立 UTF8 业务库，生成受控配置；执行已有 Alembic 迁移并核对唯一 head，完成备份及独立恢复验证。
- [x] 配置并启动五个 systemd 服务，验证四端就绪、Worker 调度、实际运行身份、监听范围、配置权限和资源余量。
- [x] 部署固定网关和受限 SSH 入口；核对 `deployer` 的四个命令白名单、禁止 Shell / TTY / 转发 / 通用 sudo、发布包路径与哈希、root 封存记录及 Alembic head；确认 `activate` 不自动迁移。
- [x] 域名明确后配置后台同源路由及 HTTPS，核对跨端隔离、CSRF、缓存和实际访问；域名缺失时保留待配置状态并交付内部部署验证结果。
- [x] 完成部署指南、文档检查和实际交付，关闭临时转发，不继续真实资金或其他后续阶段。

依赖顺序：目标与取码 → 回归 / 发布产物 → 依赖安装 → 数据库迁移与恢复验证 → 五入口启动 → 已明确的域名入口 → 验收交付。后台最终域名构建在回归构建结束后执行，避免复用其他域名产物。

发布目标为默认分支 `main` 的固定提交 `224e91516ebcb5d872aa7dc901249e4d27335170`。目标版本的后端、后台、小程序回归及锁定依赖构建验证完成；迁移、受限数据库权限、独立备份恢复、五个运行服务、受限发布入口及证书签发验证完成。`ubuntu` 的免密 sudo 已恢复，SSH 仍仅允许公钥认证。支付新单保持关闭，真实渠道、小程序上传和真实资金操作未执行。

自动续期已完成非交互演练、限定 Nginx hook 验证及现有定时服务切换，见[续期计划](staging-certificate-renewal.md)。更换公网 IP 后，服务器应用、本机 HTTPS 及经自身公网 IP 的 HTTPS 检查通过；来自独立外部网络的入口复核尚未通过，不能复用旧 IP 的公网检查结果作为当前结论。

详细运行记录保留在操作机的 `build/release-verification/`、`build/deployment-verification/`，不随文档提交。临时 GitHub / ACME 通道及测试状态已清理，受控服务器备份保留用于恢复。
