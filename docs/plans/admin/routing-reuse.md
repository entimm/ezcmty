# 后台路由能力复用实施计划

## 范围与约束

按本次已选定的路由复用范围，使用现有 Umi 的 `history`、`matchPath` 和 `generatePath`，替换应用自行维护的浏览器历史索引、事件分发和路径匹配、插值机制。继续由 `app/routes.ts` 维护路由、权限及页面归属，Umi 仅注册应用入口。

沿用[后台前端架构](../../architecture/admin-web.md)和[开发规范](../../conventions/admin-frontend.md)。保持双后台域名和精确端口边界、本地与旧前缀、页面开放开关、UUID v4/v7 校验、安全回跳和查询恢复；不升级依赖或改变页面与接口。

## 实施顺序

- [x] 使用 Umi 路径匹配和生成能力，保留大小写、尾斜杠、参数编码及业务白名单约束。
- [x] 使用同一个 Umi history 完成导航、地址订阅及离开拦截，删除自维护的历史索引与 popstate 恢复。
- [x] 仅在存在未保存内容时安装拦截；取消保持原 URL、组件和输入，确认后重试原历史操作；会话卸载时解除拦截。
- [x] 使用真实的锁定版本路由与 history 实现运行测试，补充路径严格性、参数编码与别名、replace 和拦截清理回归。
- [x] 执行后台格式、Lint、类型、全部测试与构建检查，并在浏览器核对关键前进后退和取消离开流程。

## 验收条件

两端及精确端口入口继续隔离；关闭页和非法资源地址不能成为直达或回跳目标；列表查询和详情返回参数保持可恢复。浏览器前进、后退及跨多条历史移动可取消、可确认，确认不新增历史条目，取消不丢失草稿；干净页面不安装离开拦截。全部适用检查通过，未执行的验证明确报告。
