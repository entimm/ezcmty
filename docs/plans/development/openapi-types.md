# OpenAPI 前端类型生成实施计划

## 范围

使用 `openapi-typescript` 从现有权威 OpenAPI 生成共享的 TypeScript 声明，管理后台和原生小程序通过各自现有类型入口引用。保留请求传输、会话隔离、权限、缓存、幂等和恢复逻辑，不变更公共 API 或数据库。

## 任务与依赖

- [x] 接入固定版本生成工具与共享声明。
- [x] 迁移后台基础、物业、平台、系统、导入和支付 HTTP 类型；保留明确的界面投影。
- [x] 迁移小程序居民 HTTP 类型；仅允许显式纯类型引用共享声明，保持运行时模块边界。
- [x] 将生成声明排除出 Git，保留本地文件并从暂存区移除。
- [x] 在安装、后台开发、两端类型检查、Lint、测试与构建入口自动生成；覆盖直接启动脚本。
- [x] 用检查前生成替代已提交产物的同步比较，更新 API 规范和本地开发命令。
- [x] 验证声明缺失时自动恢复、内容未变时不写入、并发生成安全，两端检查与构建通过。

生成命令先于类型迁移；两端迁移可并行。全部验证完成后核对改动范围，再勾选对应项。

## 验收条件

- HTTP 字段类型来自权威契约，保留必填、空值、枚举与已声明的固定数组长度。
- 仅提交契约、生成器及锁文件，生成声明不纳入版本管理，不人工修改。
- 新检出项目安装依赖后具备 IDE 类型；各受支持检查与构建入口会重新生成声明，生成失败时终止后续步骤。
- 小程序产物不包含生成器、声明文件或对仓库外层模块的运行时引用。
- 既有请求路径、会话、权限与写入恢复行为保持通过现有回归验证。
