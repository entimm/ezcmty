# 本地管理后台 HTTPS 实施计划

## 范围与依据

按已确认方案，在现有 dnsmasq 和用户级 Homebrew Nginx 上为两个后台域名启用 8443 HTTPS，使用现有 OpenSSL 建立本地 CA 和域名证书。设计依据见 [部署约定](../../architecture/deployment.md#本地管理后台-https)，操作集中维护于 [本地开发指南](../../guidelines/local-development.md#本地域名站点)。

本任务不修改业务代码、公共 API 或数据库。保留工作区原有账单 Hook 改动。证书、私钥、配置备份和运行验证输出存放在仓库外或已忽略的 `.dev/` 中。

## 实施顺序与验收

- [x] 1. 落盘正式设计与本计划；建立独立分支，核对既有改动和服务批次。
- [x] 2. 备份 Nginx 站点配置及前后端环境文件；记录当前服务及其他站点可用性，确认恢复方式。
- [x] 3. 生成本地 CA 和双域名服务端证书；验证证书链、SAN、用途、有效期及私钥权限。
- [x] 4. 导入 CA 到 macOS 系统钥匙串并验证系统信任；依赖第 3 步，需要系统管理员认证。
- [x] 5. 更新仓库 Nginx 示例和本机站点配置，增加 8443 TLS；追加 HTTPS 可信 Origin，改为同源 WSS；依赖第 2、3 步。
- [x] 6. 通过现有开发入口重启所属服务批次，检查 Nginx 并重载；确认所选服务就绪，其他本地站点可用；依赖第 5 步。
- [x] 7. 使用指定 CA 验证两个 HTTPS 页面、证书主机名、API Origin 校验、域名与路由隔离、WSS 握手及连接消息；依赖第 3、6 步。
- [x] 8. 验证系统证书信任及浏览器安全上下文、UUID、页面与同源热更新；依赖第 4、6 步。
- [x] 9. 更新本地开发操作文档，完成相关格式、配置及变更范围检查，报告入口、备份与验收结果。

仅在完成并验证后勾选。HTTPS 验证期间保留 8080 HTTP；是否启用后续 HTTP 重定向不影响本次 HTTPS 入口验收。

## 恢复方式

恢复备份的 Nginx 站点配置和两个本地环境文件，检查并重载 Nginx，通过开发入口恢复原服务批次。只处理本任务的配置及证书；若需要移除信任，按本任务 CA 的 SHA-256 指纹准确定位。
