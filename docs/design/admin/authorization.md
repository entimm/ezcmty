# 管理后台业务权限与岗位模板设计

## 范围与职责

本设计定义平台、物业后台的业务授权单元、固定依赖、岗位模板和配置交互。认证、账号及角色的数据模型、会话撤销与审计事务见 [基础框架设计](foundation.md)；页面视觉、导航及弹层遵循 [后台产品体验设计](experience.md)。

权限按全新授权配置设计，不承担历史角色、权限数据迁移，不保留旧原子权限码的兼容映射。沿用 RBAC、现有数据库模型和双后台进程边界，不引入新的权限引擎或基础设施。精确权限码、请求响应和各操作的权限声明以 [OpenAPI 契约](../../../openapi/openapi.yaml) 为唯一权威来源，按 [API 规范](../../api/conventions.md) 在代码实施前同步。

## 授权模型与边界

- 账号关联多个角色，有效权限取启用角色的权限并集；未授权默认拒绝。不引入账号直接授权、角色继承或拒绝规则。
- 业务权限同时作为配置与服务端校验的授权单元。合并创建、编辑等同职责操作，不在其下继续维护可分配的原子权限。具体操作仍分别记录审计，不因权限合并而合并操作事实。
- 固定权限目录由代码维护，包含所属后台、可读名称、模块、授权级别、可分配性和必要包含关系。只接受本端明确目录项，不接受任意权限字符串或通配符。
- 平台与物业权限独立，账号、角色和公司归属沿用 [账号归属与授权上下文](foundation.md#账号归属与授权上下文)。操作权限不能扩大公司数据范围；物业端覆盖本公司小区，不增加逐个小区授权。
- 普通角色可获得业务权限、系统资料查看和操作日志查看。账号、角色、密码重置及授权配置等管理写操作只允许所属范围内的系统角色 `super_admin`，统一归入仅系统角色可用的系统管理能力。
- 系统角色固定、不可编辑或启停，使用当前后台完整目录。平台使用平台系统角色，物业公司各有自己的系统角色；完整目录不授予跨后台、跨公司访问能力。
- 本人资料和本人密码按本人完整认证访问，不需要岗位权限。公司名称、标识和可访问小区选项作为最小基础上下文提供，不设置独立权限；受限改密会话仍不得读取这些业务上下文。

超级管理员可以在所属范围内给其他账号分配或撤销系统角色，但不能停用自己的账号或撤销自己的超级管理员资格。平台按后台、物业按公司保护最后一个有效超级管理员；有效数量按账号及系统角色均启用计算，公司停用不解除保护。资格变化时锁定所属系统角色行，在同一事务内校验数量，防止并发绕过。

## 业务权限目录

常规模块以“无权限／查看／维护”配置；只读模块只提供前两项，经办、审核和登记使用明确的业务名称。下表不把“无权限”计为目录项。

### 平台后台

| 模块     | 授权选项   | 授权范围                                                                                           |
| -------- | ---------- | -------------------------------------------------------------------------------------------------- |
| 物业接入 | 查看／维护 | 公司、小区资料查询；维护包含创建、编辑资料及小区现有启停操作，不包含物业公司启停和公司管理员管理。 |
| 支付资金 | 查看       | 支付、入账、分账、解冻等业务结果，合并支付和资金处理的读取。                                       |
| 资金核对 | 查看／经办 | 查看核对批次及差异；经办包含重新核对。                                                             |
| 收款配置 | 查看／维护 | 查询、维护商户绑定、费率及既有收款配置，保留不可变版本和并发规则。                                 |
| 系统资料 | 查看       | 平台账号、角色、权限目录和公司管理员资料；不包含管理写操作。                                       |
| 操作日志 | 查看       | 平台来源的管理员操作记录，按既有范围过滤。                                                         |

公司管理员开通、资料修改、账号启停及密码重置继续由平台超级管理员通过 [物业接入入口](../property/onboarding.md) 执行，不能由接入资料维护权限取得。

### 物业后台

| 模块         | 授权选项   | 授权范围                                                                               |
| ------------ | ---------- | -------------------------------------------------------------------------------------- |
| 房产资料     | 查看／维护 | 合并空间、房屋、业主资料查询；维护包含新增、编辑及现有启停操作。                       |
| 物业费账单   | 查看／经办 | 查看账单、收款历史及计费依据，允许既有依据查询与试算；经办包含建账和修改普通账单资料。 |
| 计费依据     | 维护       | 新增不可变计费依据版本，调整后续建账使用的标准；不能修改历史版本或重算已有账单。       |
| 线下收款     | 登记       | 登记线下收款，包含建账时录入正金额初始已缴；不包含收款纠正、撤销或实际退款。           |
| 居民房屋授权 | 查看／审核 | 查看认领申请及现有绑定；审核包含认领申请审核，不包含撤销已有授权。                     |
| 线上收款     | 查看       | 本公司支付、资金处理、核对结果及收款配置，继续使用物业受限投影。                       |
| 系统资料     | 查看       | 本公司账号、角色及权限目录。                                                           |
| 操作日志     | 查看       | 本公司物业来源的管理员操作记录。                                                       |

账单经办不包含计费依据维护、收款登记或作废。房产资料维护不授予居民登录身份或房屋访问授权；这两类资料仍遵守 [居民接入规则](../resident/identity-and-house-claims.md)。

### 独立关键操作

| 后台 | 操作             | 必需查看能力               | 边界                                                                                             |
| ---- | ---------------- | -------------------------- | ------------------------------------------------------------------------------------------------ |
| 平台 | 物业公司启停     | 物业接入查看               | 停用撤销公司账号会话；启用仍校验有效超级管理员，不能借资料编辑改变公司状态。                     |
| 平台 | 资金异常处理     | 支付资金查看、资金核对查看 | 恢复原支付、入账、分账、解冻流程及记录既有外部差异处置；不强制成功、改写资金事实或产生退款能力。 |
| 物业 | 账单作废         | 物业费账单查看             | 继续满足收款、支付占用及账单状态等限制。                                                         |
| 物业 | 收款纠正或撤销   | 物业费账单查看             | 沿用既有线下收款纠正流程，不允许冲掉真实线上收款或代替退款。                                     |
| 物业 | 居民房屋授权撤销 | 居民房屋授权查看           | 只撤销既有绑定，不改变房产档案或居民账号。                                                       |

关键操作独立勾选，不随普通维护、经办或审核隐含授予。收款配置维护、计费依据维护本身已是明确选择的业务权限，展示影响说明，不再增加同义开关。

## 依赖与最小查询

业务包含关系固定维护，不提供管理员编写依赖表达式的入口：

- 维护、经办或审核包含对应模块查看；计费依据维护、线下收款登记及账务关键操作包含账单查看。
- 公司启停及资金异常处理包含上表列明的查看能力；包含关系不隐含其他业务写权限。
- 账务查询、试算、计费依据维护和建账所需房屋选项，仅返回已授权公司、小区内的定位标识、位置及必要状态，不要求房产资料查看，也不能借此读取完整房产、业主姓名或手机号。
- 平台资金、收款配置及系统资料查询所需的公司定位和选项按最小上下文提供，不要求额外授予完整接入资料查看。公司详情内的配置或管理员入口按实际业务权限开放相应区块，不能因父页面权限造成断链或借此返回其他区块。
- 公司、小区业务资料在既有数据范围内随实际使用它的业务模块授权；基础上下文不能成为读取完整房产、业主或系统资料的入口。精确字段及端点权限在契约中声明。
- 建账或导入含正金额初始收款时，额外要求线下收款登记。权限需求独立于其他字段是否校验通过，不能通过排除错误行绕过；无法解释的金额保留数据错误，不能默认为零。

服务端规范化并校验保存的权限集合，纳入固定必需查看项；前端使用相同目录展示自动包含项并说明原因。删除必要查看能力时，应同步移除依赖它的操作或阻止保存并说明冲突，不能保存无法完成所选业务的组合。

账号有效权限按角色并集计算，角色摘要与账号最终权限分别展示。移除单个角色或该角色中的能力，不代表账号已失去其他角色仍授予的同一能力。

## 导入授权

不设置独立的导入动作权限。导入跟随具体类型的目标业务授权，不能凭导入中心入口扩大业务范围。

| 类型               | 读取能力       | 写入能力                                       |
| ------------------ | -------------- | ---------------------------------------------- |
| 房屋、业主资料导入 | 房产资料查看   | 房产资料维护。                                 |
| 账单导入           | 物业费账单查看 | 账单经办；正金额初始收款额外要求线下收款登记。 |

读取覆盖批次、进度、行结果及错误文件生成与下载；写入覆盖新建、上传、预检、确认执行、取消、失败重跑及恢复原任务。生成错误文件虽然属于写请求，仍以对应业务读取能力授权，并执行 CSRF、投影、保留期及资源状态校验。

每个请求、执行分块及成功结果复用仍重新校验当前授权和数据范围。任务恢复仅核实或继续原操作，不强制成功、不替换目标、不跳过确认，也不延长敏感数据读取期限。文件字段不能超过对应业务读取投影，失权后不能复用此前生成的文件。

各端只暴露已注册且允许本端使用的业务类型。新建类型目录及新建模板下载按维护或经办权限过滤；历史批次所需的固定字段说明随批次读取提供，按对应业务查看授权，不依赖新建目录或维护权限接口，精确响应由契约定义。当前账号无可新建类型时隐藏新建导入入口并禁止创建，已授权的历史查询继续可用；本端未注册生产类型时隐藏导入中心入口。平台目录完整也不能取得物业业务写能力。状态机、幂等、确认策略、租约和未知结果处理遵循 [统一导入设计](../imports/overview.md)。

## 岗位模板

模板由代码维护，只作为创建普通角色时的表单预填，不是系统角色。未列出的模块和独立关键操作默认无权限。

| 后台 | 模板       | 默认授权                                                 |
| ---- | ---------- | -------------------------------------------------------- |
| 平台 | 接入运营   | 物业接入维护。                                           |
| 平台 | 财务查询   | 物业接入查看、支付资金查看、资金核对查看、收款配置查看。 |
| 平台 | 财务经办   | 财务查询全部能力，加资金核对经办。                       |
| 物业 | 资料专员   | 房产资料维护，包含房屋和业主资料导入。                   |
| 物业 | 收费员     | 账单经办、线下收款登记、线上收款查看。                   |
| 物业 | 客服审核员 | 房产资料查看、账单查看、居民房屋授权审核。               |

模板由操作者选用并调整，服务端再次校验本端目录、可分配性及依赖。角色创建及初始权限、审计同事务提交，不能先创建空角色再要求第二次配置才能使用。

创建后角色独立维护，不保存模板订阅或升级关系，不建立模板版本表、同步任务或升级界面。模板调整只影响以后创建角色的预填；本次创建结果仍由普通角色审计记录。

新增业务模块和关键操作默认不进入已有普通角色。既有维护能力可覆盖原职责内新增的普通步骤；扩大业务职责或增加敏感操作时另行定义授权，不能通过变更映射隐式扩权。系统超级管理员继续使用当前后台完整目录。

## 配置交互

账号日常授权通过分配岗位角色完成，角色创建流程为“选岗位模板或自定义 → 调整模块级别和关键操作 → 查看授权摘要 → 一次保存”。角色名称及稳定编码沿用基础框架规则。

配置页面展示模块与业务级别，不展示原子权限树或仅以权限数量概括角色。必要查看项说明自动包含原因；关键操作说明影响和现有限制。已有角色调整以业务能力为单位，模板不覆盖已经调整的角色。

保存前展示可完成的工作、独立关键操作、新增和移除能力、受影响账号数量，以及既有授权变更后重新登录要求。新角色创建没有关联账号时，影响数量按实际值展示。预览用于解释，服务端保存时重新核验权限及资源，不能信任客户端提交的预览结论。

只读角色可以查看系统资料和日志，写入口仍只对超级管理员显示。系统角色显示固定标记，不提供编辑、启停或权限修改入口。

## 物业端管理入口

物业端提供本公司账号、角色权限及操作日志入口，路由和菜单沿用 [后台产品体验设计](experience.md)。界面复用基础框架的账号管理、角色管理与日志查询流程，本端请求固定走物业进程。

- 物业超级管理员可创建、编辑、启停、重置本公司账号密码，分配本公司角色，并创建、编辑、启停普通角色及配置其权限。
- 公司归属由服务端身份解析，创建和查询不能由客户端指定其他公司；列表、详情、分页总数、角色选项、权限预览及审计使用相同公司过滤。
- 普通角色只有系统资料查看、操作日志查看等明确授予的读取能力，不能借只读页面、模板或直接调用接口获得管理写权限。
- 自身及最后一个有效超级管理员保护、强制改密和会话撤销规则同样适用于物业管理请求。
- 平台继续负责公司初始超级管理员开通及既有公司管理员管理；物业内部普通人员通过本公司管理入口维护，不开放跨公司角色或指定小区授权。

管理接口的两端运行归属及公司约束在 OpenAPI 中明确；共用请求结构不表示共用授权上下文或平台账号可以调用物业管理接口。

## 工程保障与验证

认证、Origin、CSRF、资源状态、数据范围、版本和业务不变量在服务端校验，权限合并不能绕过既有保护。权限和角色变更同事务写入审计、递增关联账号会话版本；事务和结果未知恢复沿用 [基础框架](foundation.md#会话撤销与授权生效) 和 [错误规范](../../api/errors.md#事务与并发)。

前端路由、菜单、查询、操作和字段投影与后端使用同一目录语义；角色、账号或公司失效时清理本端旧身份、缓存、请求和表单。Worker 在正式业务写入和结果复用前重新校验当前业务权限，不能依赖创建批次时的授权快照。

验证遵循 [测试规范](../../conventions/testing.md)，覆盖：

- 六类模板分别完成职责内实际流程；仅有必要依赖时建账和审核可完成，未授予的关键操作仍被拒绝。
- 导入完整流程及错误文件读取无需逐项授权；初始收款缺权整批阻断，失权、越界和过期文件拒绝访问，未知结果仍按原操作恢复。
- 账单最小房屋查询不泄露完整房产或业主信息；物业线上收款继续不暴露平台资金、渠道原文和技术快照。
- 双后台、两家公司、公司与账号停用、多角色并集，以及物业管理列表、总数、选项和审计隔离。
- 角色创建及初始权限原子提交；账号角色、角色权限变化的审计、会话撤销，以及并发最后一个有效超级管理员保护。
- 模板更新不修改既有角色，新增模块和关键操作不扩权；接口拒绝被替代的旧目录项、未知项、通配项及不可分配的系统管理能力。
- 前后端权限、原子操作替换后的契约声明及实际运行端一致，通过对应 API 契约、后端集成及前端流程检查。
