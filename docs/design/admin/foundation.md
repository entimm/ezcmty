# 管理后台基础框架设计

## 范围与职责

本设计确定平台和物业后台共用的认证、管理员、角色权限及审计规则，以及平台后台的页面与交互。运行组件和分层职责沿用 [系统架构](../../architecture/overview.md)，前端模块、路由组织和请求状态沿用 [管理后台前端设计](../../architecture/admin-web.md)。

平台后台基础框架覆盖登录、退出、会话恢复、首次登录强制改密、个人资料、管理员管理、角色管理和审计日志查询。

物业后台复用公共能力，并在接入时补齐物业公司归属和小区数据范围。完成组织归属和数据范围约束是启用物业登录及管理接口的前提。

平台的物业公司、小区和公司管理员接入管理见 [物业接入管理设计](../property/onboarding.md)。

物业端登录、本人资料和公司范围内的基础工作台见 [物业管理端登录与基础工作台设计](../property/workbench.md)。

## 账号归属与授权上下文

- 后台作用域使用 `platform_admin` 和 `property_admin`，由对应后端进程确定。登录、创建账号和授权请求不能自行指定所属后台。
- 一个管理员账号属于一个后台，登录名在所属后台内唯一，显示名称可以重复。两端相同登录名不代表同一个账号。
- 物业账号归属一家物业公司；同一人跨公司任职时使用不同账号。
- 物业角色归属一家物业公司，账号只能关联所属公司的角色。平台账号和角色没有物业公司归属。
- 管理员身份、会话和角色授权仅在所属后台生效。
- 公共授权上下文包含后台、账号、组织和数据范围。权限校验与数据范围校验分别执行，拥有操作权限不能扩大可访问的数据范围。
- 物业公司的 `super_admin` 数据范围覆盖本公司全部小区，并随本公司新增小区扩展；完整权限目录不授予跨公司访问能力。
- 资源在当前授权范围内解析，越界资源按不存在处理。

## 数据模型

平台基础框架使用以下五类数据：

| 表                       | 内容与约束                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| `admin_accounts`         | 所属后台、登录名、显示名称、密码哈希、启停状态、强制改密标记、`session_version`；登录名在后台内唯一。 |
| `admin_roles`            | 所属后台、角色名称、稳定角色编码、启停状态和系统角色标记。                                            |
| `admin_account_roles`    | 账号与角色关联；禁止跨后台关联。                                                                      |
| `admin_role_permissions` | 角色与权限码关联；权限码必须存在于所属后台的权限目录。                                                |
| `admin_audit_logs`       | 来源后台、关联物业公司、操作者、操作、目标、结果、请求标识和时间。                                    |

账号、角色及关联关系的后台归属同时通过数据库约束和服务端校验保证。账号与角色使用启停管理，保留历史关联和审计记录。

物业账号和角色必须通过外键归属一家物业公司，账号与角色关联的公司一致性同时由数据库约束和服务端校验保证。平台角色编码在平台内唯一，物业角色编码在公司内唯一。物业公司与小区业务模型见 [物业接入管理设计](../property/onboarding.md#物业公司与小区)，公共服务执行物业授权时必须有明确的组织和数据范围。

数据库、时间存储和迁移遵循 [数据库规范](../../database/conventions.md)。

### 公司归属数据库扩展

`admin_accounts`、`admin_roles`、`admin_account_roles` 均增加可空的 `property_company_id BINARY(16)`，使用 CHECK 约束限定：平台后台必须为 `NULL`，物业后台必须非空。账号和角色的公司字段外键指向 `property_companies.id`，不级联删除。

- `admin_accounts` 保留 `UNIQUE(scope, login_name)`，增加 `UNIQUE(property_company_id, id)` 及 `(property_company_id, created_at, id)` 索引。
- `admin_roles` 增加 `UNIQUE(property_company_id, id)`。原 `UNIQUE(scope, code)` 替换为 `UNIQUE(property_company_id, code)` 和 `UNIQUE(platform_code)`；内部生成列 `platform_code VARCHAR(64)` 使用 `CASE WHEN scope = 'platform_admin' THEN code ELSE NULL END`，采用 STORED，不进入 API。不能用包含可空公司字段的单一联合唯一索引代替平台唯一性约束。
- `admin_account_roles` 保留 `(scope, account_id, role_id)` 主键及原后台复合外键，增加 `(property_company_id, account_id)` 和 `(property_company_id, role_id)` 分别引用账号和角色的 `(property_company_id, id)`。CHECK 与两类外键共同防止跨后台、跨公司及空公司绕过。
- `admin_role_permissions` 通过角色 ID 确定归属，无需增加公司字段；审计日志规则见 [审计与代码组织](#审计与代码组织)。关联表保留原有非空 `created_at`。

迁移使用新增 Alembic 版本，不修改历史迁移。存在尚未确认公司归属的存量物业账号、角色或关联时，迁移前置检查必须停止，不任意分配公司。迁移验证在隔离数据库中执行。

## 认证与会话

### 密码与登录

使用账号密码登录，通过成熟的 `argon2-cffi` 库进行 Argon2id 哈希和校验，数据库仅保存密码哈希。初始密码和重置密码都要求首次登录修改。

登录按账号和来源 IP 限制尝试次数。失败响应不区分账号不存在、密码错误和账号停用，避免暴露账号状态。

物业登录和已登录请求的认证必须从服务端账号归属解析公司，并校验公司存在且启用；组织缺失或公司停用时不能签发或接受物业会话。公司停用的登录失败仍使用统一登录失败响应，已登录请求返回认证失效。

### Cookie 与 Redis

Cookie 名称沿用 [OpenAPI 安全方案](../../api/openapi/components/security-schemes.yaml) 中的 `AdminSession`，即 `admin_session`。

| 配置     | 规则                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| Path     | 平台使用 `/api/platform`，物业使用 `/api/property`；路径随部署 API 前缀配置。设置和清除 Cookie 使用同一路径。 |
| Domain   | 使用 Host-only Cookie。                                                                                       |
| HttpOnly | 开启。                                                                                                        |
| SameSite | 使用 `Lax`。                                                                                                  |
| Secure   | 生产 HTTPS 环境开启。                                                                                         |

Redis 会话按后台作用域隔离，登录成功创建新的随机会话标识。会话丢失策略沿用 [系统架构的会话约定](../../architecture/overview.md#会话)。

默认空闲有效期为 30 分钟，绝对有效期为 12 小时，两者均允许配置。空闲续期不能超过绝对有效期。

允许多个设备同时登录，退出只撤销当前会话。会话响应使用 `Cache-Control: no-store`。

### 写请求与受限会话

所有写请求校验可信 Origin；已认证的写请求还必须校验绑定当前会话的 CSRF Token。

首次登录需要改密时，签发受限会话，仅允许读取当前会话、修改本人密码和退出。其他接口返回明确的需要修改密码错误。

## 会话撤销与授权生效

账号表中的 `session_version` 是撤销旧会话的依据。Redis 会话保存创建时的账号版本，后续请求将其与数据库中的当前版本比较；版本不一致即返回 401。

以下变化在同一数据库事务中递增受影响账号的版本：

| 变化                       | 受影响账号             |
| -------------------------- | ---------------------- |
| 账号启停                   | 该账号。               |
| 修改或重置密码             | 该账号。               |
| 调整账号角色               | 该账号。               |
| 调整角色权限或角色启停状态 | 关联该角色的账号。     |
| 停用物业公司               | 该公司的全部物业账号。 |

旧会话失效不依赖 Redis 记录是否清理成功。即使 Redis 仍保留旧记录，后续请求也不能继续使用旧版本会话。

授权调整后的相关账号需要重新登录；修改本人密码成功后，退出并重新登录。

公司停用不改写其账号的启停状态。重新启用公司不恢复旧会话，物业账号仍须自身启用并重新登录。

事务失败和提交结果不确定时的处理沿用 [错误与异常规范](../../api/errors.md#事务与并发)。

## 角色与权限

采用 RBAC：账号可以关联多个角色，有效权限取启用角色的权限并集，未授权默认拒绝。

权限码按资源与操作定义，例如 `admin.account.read`、`admin.account.create`、`admin.account.reset_password`、`admin.account.assign_roles`、`admin.role.read`、`admin.role.update`、`admin.role.assign_permissions` 和 `admin.audit.read`。

权限目录由代码维护并标明所属后台。普通角色只能选择目录中允许分配的权限，接口不接受任意权限字符串或通配符。

管理员、角色和授权配置的管理写操作仅开放给系统角色 `super_admin`。普通角色可以获得查询权限及业务权限。个人资料和本人密码通过本人接口管理，按本人认证访问。

系统角色 `super_admin` 使用当前后台的完整权限目录，角色本身保持固定。平台使用平台系统角色，每家物业公司使用各自的系统角色。其他具有管理权限的超级管理员可以在所属授权范围内给账号分配或撤销该角色，但必须遵守以下规则：

- 不能通过管理页面停用自己的账号或撤销自己的超级管理员资格。
- 平台按后台、物业按公司分别保护最后一个有效超级管理员；有效数量按账号和系统角色均启用计算。
- 物业公司的数量保护在初始管理员开通后生效，公司停用不解除该保护。
- 涉及该资格变化时，锁定所属系统角色行，在同一事务内校验有效数量，防止并发操作绕过保护。

平台初始超级管理员通过受控命令创建，密码交互输入。重复初始化不能覆盖已有账号。物业公司的初始超级管理员通过平台物业接入入口开通，流程及事务规则见 [物业接入管理设计](../property/onboarding.md#接入流程与公司管理员)。

## 接口范围

以下表格确定平台基础框架的资源与操作范围。请求和响应 Schema、状态码、错误码、权限声明及幂等性以 [OpenAPI 契约](../../api/openapi/openapi.yaml) 为唯一权威来源，必须在对应功能实现前按 [API 规范](../../api/conventions.md) 定义。

路径为后端路径，通过平台入口访问时使用 `/api/platform` 前缀。本期新增管理接口的 `x-runtimes` 只声明 `platform_admin_api`。

| 方法         | 路径                                              | 职责                       |
| ------------ | ------------------------------------------------- | -------------------------- |
| POST         | `/v1/admin-sessions`                              | 登录并创建会话。           |
| GET / DELETE | `/v1/admin-sessions/current`                      | 恢复当前身份 / 退出。      |
| GET / PATCH  | `/v1/admin-accounts/me`                           | 查看 / 修改个人资料。      |
| POST         | `/v1/admin-accounts/me/password-changes`          | 校验旧密码并修改本人密码。 |
| GET / POST   | `/v1/admin-accounts`                              | 查询 / 创建管理员。        |
| GET / PATCH  | `/v1/admin-accounts/{account_id}`                 | 查看 / 编辑及启停管理员。  |
| POST         | `/v1/admin-accounts/{account_id}/password-resets` | 重置他人密码并要求改密。   |
| PUT          | `/v1/admin-accounts/{account_id}/roles`           | 完整替换账号角色。         |
| GET / POST   | `/v1/admin-roles`                                 | 查询 / 创建角色。          |
| GET / PATCH  | `/v1/admin-roles/{role_id}`                       | 查看 / 编辑及启停角色。    |
| PUT          | `/v1/admin-roles/{role_id}/permissions`           | 完整替换角色权限。         |
| GET          | `/v1/admin-permissions`                           | 查询本端权限目录。         |
| GET          | `/v1/admin-audit-logs`                            | 分页查询审计日志。         |

查询接口要求相应读取权限；个人账号和当前会话接口按本人身份访问。登录和恢复会话提供当前账号、所属后台、权限、是否需要改密及 CSRF 校验所需数据。

接口沿用项目的分页、成功响应和错误规则，并明确认证失败、强制改密、CSRF 校验失败、登录限流和超级管理员保护等错误行为。

### 页面信息与契约要求

页面使用上述接口，契约需提供以下信息并明确相应行为：

- 账号列表和详情的角色摘要、创建时间，以及详情中的强制改密标记；本人资料中的登录名和显示名称。
- 创建账号支持可选初始角色集合，账号与所选角色关联在同一事务内提交；审计事务规则见 [审计与代码组织](#审计与代码组织)。
- 角色基本资料、系统角色标记和权限概要，以及角色详情中的权限集合。
- 权限目录中的可读名称、功能分组及可分配标记。
- 各列表实际支持的筛选、排序字段和允许值，以及可分页加载的启用角色选项；角色分配行为见 [管理员管理页面](#管理员管理页面)。
- 密码校验失败、需要改密、限流和保护规则的错误语义，使操作错误与会话失效可以分别处理。

字段、响应结构和错误码仍以 OpenAPI 为唯一权威来源，本设计记录页面所需的信息与行为。

## 平台路由与导航

平台页面注册到平台路由元数据中，入口与守卫层级见 [作用域入口与路由组织](../../architecture/admin-web.md#作用域入口与路由组织)。

下表维护平台域名下的基础框架路由，域名选择与直连开发服务器的路径映射见 [域名与页面路径](../../architecture/admin-web.md#域名与页面路径)；物业接入路由、菜单和交互见 [物业接入管理的页面设计](../property/onboarding.md#平台页面与交互)。

| 路径                 | 页面       | 访问条件                                 | 菜单位置                |
| -------------------- | ---------- | ---------------------------------------- | ----------------------- |
| `/`                  | 平台首页   | 完整登录。                               | 首页。                  |
| `/login`             | 登录       | 未登录时显示，已有身份时按身份状态跳转。 | 独立页面。              |
| `/change-password`   | 强制改密   | 需要改密的受限会话。                     | 独立页面。              |
| `/profile`           | 个人中心   | 完整登录，本人访问。                     | 用户菜单。              |
| `/system/accounts`   | 管理员管理 | 完整登录且有 `admin.account.read`。      | 系统管理 → 管理员管理。 |
| `/system/roles`      | 角色管理   | 完整登录且有 `admin.role.read`。         | 系统管理 → 角色管理。   |
| `/system/audit-logs` | 审计日志   | 完整登录且有 `admin.audit.read`。        | 系统管理 → 审计日志。   |
| `/*`                 | 404        | 未匹配到有效页面。                       | 不进入菜单。            |

管理员和角色的详情、创建、编辑使用抽屉或弹窗，归属于各自列表页。

身份与导航规则：

1. 首次进入后台读取当前会话，只有初始化响应 401 才判定未登录；其他初始化失败按 [异常与空状态](../../architecture/admin-web.md#异常与空状态) 展示可重试状态。
2. 未登录访问已知受保护路由时，跳转登录页，保留本后台内的目标路径。未知路径直接显示 404。
3. 登录成功后，需要改密的会话进入强制改密页；完整会话进入有效目标路径或首页。
4. 受限会话访问其他已知页面时，引导到强制改密页，页面只提供改密和退出操作。
5. 完整登录访问登录页时跳转有效目标路径或首页；访问强制改密页时跳转个人中心的修改密码标签。
6. 回跳目标经过本端路由白名单校验，排除登录、强制改密和循环跳转；最终页面继续执行权限守卫。
7. 修改密码成功、退出成功或认证失效时，按 [请求、缓存与表单状态](../../architecture/admin-web.md#请求缓存与表单状态) 清理本端状态并返回本端登录页。

## 布局与菜单

平台后台采用 ProLayout：左侧导航、顶部标题和用户菜单、内容区 PageContainer。列表页面保持“标题与操作区 → 查询区 → 数据表格与分页”的顺序。

左侧菜单按路由表组织，用户菜单提供个人资料、修改密码和退出。个人中心使用基本资料、修改密码两个标签，标签选择可通过非敏感 URL 参数恢复。

菜单过滤、路由标题和面包屑按 [作用域入口与路由组织](../../architecture/admin-web.md#作用域入口与路由组织) 执行。窄屏收起侧栏，宽表格在内容区横向滚动，表单和抽屉适配可用宽度。

## 登录与密码页面

### 登录页

采用独立居中表单布局，明确显示后台名称。包含登录名、密码和登录按钮，提交中防止重复操作。

登录失败在表单内显示安全说明并保留登录名。登录接口的认证失败和初始化时的未登录响应，不弹出会话过期通知。登录限流遵循服务端响应，只有服务端提供等待时间时显示对应等待提示。

密码输入不进入 URL 或持久化存储。成功后由认证模块更新身份，并执行回跳或强制改密流程。

### 强制改密页

显示当前账号和必须改密说明。表单包含当前密码、新密码、确认新密码；确认项只用于前端一致性校验。

提供退出入口。密码规则按 OpenAPI 契约校验，密码值不自动截断或改变。成功后按导航规则清理状态，引导使用新密码重新登录。

普通改密与强制改密复用 `PasswordChangeForm`，由外层页面提供不同说明与布局。

## 首页与个人中心

### 首页

首页显示当前登录账号、后台名称及可访问功能快捷入口。快捷入口复用菜单权限过滤结果，并提供个人资料和修改密码入口。数据使用当前会话与本人资料。

### 个人中心

基本资料标签显示只读的登录名和所属后台，允许修改显示名称。保存成功同步个人资料与用户菜单中的名称。

修改密码标签复用密码表单，提交前说明保存后需要重新登录。旧密码校验失败作为该操作错误展示，会话过期才执行认证失效流程。

## 管理员管理页面

采用 ProTable 展示列表，查询区包含登录名和账号状态，分页和筛选可通过 URL 恢复。主要列为登录名、显示名称、账号状态、角色、创建时间和操作。

| 交互        | 展示方式           | 字段与行为                                                                                                                              |
| ----------- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 查看详情    | 只读抽屉。         | 通过详情接口读取账号资料、状态、角色及是否需要改密。                                                                                    |
| 创建管理员  | 创建抽屉。         | 登录名、显示名称、初始密码、确认密码和初始角色。初始角色可为空，通过一次创建请求提交。                                                  |
| 编辑资料    | 编辑抽屉。         | 登录名只读，修改显示名称。                                                                                                              |
| 启用 / 停用 | 行操作与确认弹窗。 | 明确说明账号状态变化会使旧会话失效，停用期间不能登录。                                                                                  |
| 分配角色    | 多选抽屉。         | 加载完整当前角色集合，使用 PUT 保存最终集合；可选角色按分页接口加载启用角色。已分配的停用角色显示停用标签并允许移除，不能新增停用角色。 |
| 重置密码    | 密码弹窗。         | 输入临时密码及确认项，说明目标账号需要重新登录并强制改密，成功后清空密码输入。                                                          |

具有读取权限的账号可以查看列表和详情。管理写按钮按对应权限显示，其授权边界见 [角色与权限](#角色与权限)。

本人停用和撤销自身超级管理员资格的操作在前端阻止并说明原因，服务端继续执行约束。最后一个有效超级管理员保护失败时，展示服务端业务说明并刷新记录。

保存后的列表、详情刷新及本人授权变化处理按 [请求、缓存与表单状态](../../architecture/admin-web.md#请求缓存与表单状态) 执行。

## 角色管理页面

采用 ProTable 展示角色列表，查询区包含角色名称和启停状态。主要列为角色编码、名称、状态、系统角色标记、权限概要和操作。

| 交互        | 展示方式           | 字段与行为                                                                    |
| ----------- | ------------------ | ----------------------------------------------------------------------------- |
| 查看详情    | 只读抽屉。         | 读取角色基本资料和权限集合。                                                  |
| 创建角色    | 创建抽屉。         | 填写稳定角色编码和名称，创建成功后可继续配置权限。                            |
| 编辑资料    | 编辑抽屉。         | 角色编码只读，修改名称。                                                      |
| 启用 / 停用 | 行操作与确认弹窗。 | 提示关联账号需要重新登录。                                                    |
| 配置权限    | 权限抽屉。         | 读取角色详情和本端权限目录，按功能分组显示复选项，使用 PUT 保存最终权限集合。 |

权限分组是展示组织方式，最终保存明确的权限码集合。权限名称、分组和是否可分配由本端权限目录提供，选项遵循 [角色与权限](#角色与权限) 的分配规则。

系统角色显示固定标记和只读权限，编辑、启停、权限修改入口不可用。普通角色的写操作按相应权限显示。

保存角色权限或状态前说明关联账号需重新登录；成功后的会话确认和数据刷新按 [请求、缓存与表单状态](../../architecture/admin-web.md#请求缓存与表单状态) 执行。

## 审计日志页面

使用 ProTable 提供时间范围、操作类型、结果和请求标识筛选，查询条件与分页可恢复。表格显示操作时间、操作者、操作、目标、结果和请求标识。

只读详情抽屉展示当前审计条目提供的关联公司标识和元数据，并支持复制请求标识。页面数据来源于审计查询接口，展示内容限定在后端允许公开的审计字段中。

时间筛选转换为契约要求的 UTC 时间，展示时转换为浏览器时区，并在筛选区标明时区。

## 审计与代码组织

管理员、角色和授权变更与对应审计记录在同一 MySQL 事务内提交。登录结果另行记录。

审计内容使用明确的字段白名单。密码、Cookie、会话标识和 CSRF Token 不进入审计或诊断日志。

`admin_audit_logs` 的 `scope` 标识操作来源后台，`property_company_id BINARY(16)` 记录关联物业公司，允许为空，外键指向 `property_companies.id`，不级联删除。公司归属在写入日志时确定。

- 物业正常操作从服务端认证上下文获取公司 ID，必须有明确公司归属；成功登录及能够识别账号的失败登录从服务端账号归属获取公司 ID。未知账号的失败登录允许公司字段为空。
- 平台管理公司、小区和公司管理员时，通过目标资源解析并显式记录公司 ID；平台全局操作允许公司字段为空。
- `metadata` 保存修改字段、角色集合和权限集合。
- 审计查询校验 `admin.audit.read` 权限和后台、公司上下文。平台按 `scope = platform_admin` 查询，物业按 `scope = property_admin` 和当前账号所属公司查询。物业公司上下文缺失时拒绝查询；列表与 `total` 使用相同过滤条件，并在过滤后分页。
- 物业审计接口的启用前提见 [范围与职责](#范围与职责)。
- 联合索引为 `(scope, property_company_id, created_at, id)`。审计按 `(created_at, id)` 同方向稳定排序，默认两者降序，使用页码分页。

后端各端应用 Service 分别编排认证、本人操作和已开放的管理用例，共享身份、RBAC、审计和数据访问能力；各端 API 保持薄层并显式组装本端接口。分层与复用边界见 [后端业务边界与公共能力](../../architecture/backend-services.md)。菜单配置和页面组件按实际相似程度复用，业务规则不依赖前端传入的身份信息。

## 验证要求

实施验收覆盖以下行为，并执行 [开发规范](../../guidelines/development.md#质量检查) 要求的相关检查：

- 登录、退出、刷新恢复身份和首次登录强制改密流程完整；受限会话只能进入允许的页面和接口。
- 未登录直接打开受保护页面，登录后返回有效目标；已登录访问登录页不出现循环跳转。
- 初始化失败可以重试，页面不提前展示管理数据。
- 同一后台的路由、菜单、快捷入口和按钮权限一致，只读账号无法看到管理写入口。
- 管理员和角色的列表、查询、分页、抽屉、确认与保存后刷新完整，系统角色和本人保护交互明确。
- 账号、角色和会话不能跨后台使用；两端 Cookie 不相互覆盖。
- 物业账号、角色和资源关联不能跨公司使用，拥有完整权限目录仍须执行公司和小区数据范围。
- 审计写入与查询遵循后台和公司范围，列表与总数一致，排序和分页稳定。
- CSRF 防护和登录尝试限制生效。
- 账号状态、密码和授权变化使旧会话失效，即使 Redis 中仍保留旧记录。
- 并发修改不能绕过平台或所属公司最后一个有效超级管理员保护；管理变更和审计记录保持事务一致。
- 物业公司停用阻止新登录并撤销已有会话，重新启用不恢复旧会话，也不改变账号自身的启停状态。
- 修改本人密码、本人授权变化和 401 只清理本端身份、请求、缓存和表单，旧身份响应不能回填。
- 两端相同 Query Key、选择项、表单和路由切换不串用身份或数据。
- 写入失败不自动重复提交，业务保护和表单错误能定位到当前操作。
- URL 查询状态可在刷新和返回时恢复，密码及认证数据不进入 URL 或持久化存储。
- 实现与所属进程的 OpenAPI 契约一致。
