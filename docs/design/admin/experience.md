# 后台产品体验设计

## 设计依据与边界

本设计以用户确认的 [ChatGPT Sites 预览](https://xlife-admin-review-20261024.swiftswift256.chatgpt.site) 为整体布局、信息架构与交互依据，源版本 `b5da13ae7e3aef9ce322d262c4a965260f331857`。两端采用按后台区分的深色顶栏、浅色业务区、白色分组导航及统一中文办公排版，身份色以本文视觉规范为准。

本设计取代旧页面设计对布局、导航、组件和交互的约束。已有业务设计中的数据规则、权限、异步状态、并发及资金语义继续有效，API 以 [OpenAPI 契约](../../../openapi/openapi.yaml) 为准。预览模拟数据、评审控制、模拟角色和虚构汇总不进入正式产品。接口不支持的聚合只展示当前页统计并明确范围，查询只发送已定义字段。

工程、域名、会话、API 和缓存边界见 [前端架构](../../architecture/admin-web.md)，工程质量见 [开发规范](../../guidelines/development.md)。

## 信息架构

| 后台 | 一级业务域 | 菜单                         |
| ---- | ---------- | ---------------------------- |
| 物业 | 日常工作   | 工作概览                     |
| 物业 | 收费管理   | 物业账单、线上收款、对账结果 |
| 物业 | 房屋住户   | 房屋档案、认领审核、房屋绑定 |
| 物业 | 资料工具   | 导入中心、小区资料、收款信息 |
| 物业 | 系统管理   | 账号管理、角色权限、操作日志 |
| 平台 | 日常工作   | 工作概览                     |
| 平台 | 物业接入   | 物业公司、小区管理           |
| 平台 | 支付资金   | 支付记录、资金对账           |
| 平台 | 系统管理   | 账号管理、角色权限、操作日志 |
| 平台 | 资料工具   | 导入中心                     |

分组与主菜单统一使用四字名称，页面标题保留必要的完整业务名称，如“物业费账单”“房屋认领审核”“居民房屋绑定”。页面标题、面包屑与快捷入口使用一致术语。命令搜索兼容原菜单名称，且仍按当前后台及权限过滤。平台收款配置由公司详情进入，相应区块及必要公司定位按业务权限独立开放，不强制完整接入资料查看。本端未注册生产导入类型时隐藏导入中心入口；当前账号只有历史读取授权时保留历史入口，不展示新建操作。

详情继承父菜单、面包屑和返回路径，返回保留筛选与分页。登录、首次改密独立布局，个人中心归当前账号。平台公司管理员接入管理仍由公司详情进入；物业账号、角色和日志入口限定本公司，管理写入仅限本公司超级管理员，普通角色按系统资料或操作日志查看授权只读访问。

### 页面开放控制

物业端通过 `app/page-availability.ts` 集中配置页面开放开关。“小区资料”和“收款信息”默认关闭，页面实现和路由定义保留；恢复对应开关并重新构建发布后即可开放。

关闭页面同时从菜单和命令搜索移除，地址直达显示404，登录回跳不进入已关闭页面，且不挂载其业务页面或执行页面查询。开关只作用于物业端，平台小区管理与公司收款配置保持可用。

页面开放状态与业务权限分别判断。关闭“小区资料”不影响已完整登录用户的必要公司和小区上下文，业务资料仍按对应业务授权读取。页面开关不改变后端权限、API或数据可读范围。

## 小区业务上下文

物业业务区顶部固定小区上下文，不放普通筛选栏。只列当前账号可读的小区，按账号隔离保留选择；切换时清理页面关联选择并读取目标数据，避免旧响应回填。无可读小区显示引导，不请求无范围资源。

房屋、账单及其详情使用明确小区；认领、绑定、收款与导入按契约可缩小到所选小区。工作台汇总、小区资料、公司收款配置、公司核对结果明确标记公司范围，不受顶部选择影响。表单未保存时切换先确认。直达详情同步解析真实资源小区，不悄悄把记录替换成其他小区对象。

## 视觉规范

两端侧栏直接从分组导航开始，顶部不显示组织信息区块或组织按钮。

### 业务上下文栏与面包屑

两端面包屑统一放在固定的55px业务上下文栏左侧，右侧展示业务范围。物业端保留“当前小区”选择器；公司范围页面同时明确显示“公司范围 · 不受小区选择影响”。平台端右侧显示“平台管理范围”。不再重复展示所选小区的范围说明或授权范围文案。

小区选择器使用标准有边框下拉框，所选小区与下拉箭头位于同一边框内；公司范围说明作为独立静态文字展示，避免与选择器混淆。

面包屑沿用当前路由、父菜单及受保护导航，详情返回继续恢复筛选、分页和小区。未保存提示保留在上下文栏内。长路径和小区名可省略，但须能查看完整内容；空间不足时优先保证小区选择、公司范围说明和未保存提示可读，不增加上下文栏高度。

内容区从页面标题开始，保留顶部留白；标题、说明、返回入口及主操作仍由页面标题区承载。验证覆盖两端代表列表和详情、公司范围页面，以及1280/1366/1920桌面宽度、三套主题和标准/紧凑密度，确保无溢出、范围提示清晰且导航和小区切换保护有效。

### 后台身份色

登录及首次改密页的左侧背景、登录后的顶栏背景使用固定身份色，由当前后台 `scope` 决定：

| 后台         | 顶栏背景（纯色） | 登录及首次改密页左侧基础渐变 | 左侧主光晕       |
| ------------ | ---------------- | ---------------------------- | ---------------- |
| 平台管理中心 | 深蓝 `#10284F`   | `#101A30` → `#080F1D`        | 蓝色 `#2563EB52` |
| 物业工作空间 | 靛青 `#24294D`   | `#111326` → `#080C18`        | 靛紫 `#713DE85C` |

登录及首次改密页左侧以深暗渐变为底，叠加局部柔和的径向主光晕，以及共用的弱冷蓝辅助光晕 `#0891B224`。平台偏蓝、物业偏靛，亮部自然向深暗边缘衰减；低对比网格局部淡出，白色文字与社区插画保持清晰可读。光晕及网格仅用于认证页展示背景，不用于登录后顶栏。

身份色独立于用户选择的强调主题，切换主题或信息密度时保持不变。两端保留“平台管理中心”“物业工作空间”名称，不能只靠颜色识别。白色侧栏、浅色业务区、白色卡片及状态语义色保持统一。

### 强调主题与排版

主题通过 Ant Design Token 配置蓝、靛青、岩蓝三套强调色，用于导航选中、主操作和数据强调。成功、警告和错误使用统一语义色，不随后台身份色改变。标准/紧凑密度由用户设置保留。中文优先使用系统字体，正文14px，标题24/18px，辅助内容12px；表格正文13px。间距采用4/8/12/16/24px，统一圆角、阴影、状态标签和金额对齐。状态同时显示文字、色彩和必要图标。

菜单、工作台、表格、详情、弹窗和复杂流程按确认预览实现，常见1280/1366桌面宽度无页面级横向溢出，宽表格在自身容器内滚动。

## 操作与流程

- 新增账单使用弹窗，保存后保留当前业务页面并刷新数据。房屋列表可快捷登记业主，弹窗明确目标小区及房屋；登记档案不授予居民权限。
- 轻操作、简单详情使用弹窗；并排参考、问题行及审计使用抽屉；导入、支付资金和复杂业务详情使用独立页面。禁止嵌套确认弹窗。
- 点击遮罩、ESC、关闭按钮或取消走相同关闭规则。未修改、空白或新输入还原后直接关闭；有未保存内容时在当前弹层提示继续/放弃，提交中禁止关闭和重复提交。既有数据被清空仍属于修改。
- 日期/月份/时间区间统一RangePicker，并按契约转换边界及带时区时间戳。
- 导入用Steps展示范围、文件、预检、确认、执行结果。预检不写正式业务；范围/模板锁定，错误与警告策略显式确认，依据实际任务及行结果呈现进度和统计。未知结果先核实原批次；失败行重跑为新批次；取消不回滚成功记录。
- 支付、入账、分账、解冻分别展示可信事实。物业资金与配置只读；平台恢复需原因及状态令牌，异步受理仅表示已安排。外部处置只记录结论，不能显示为资金到账。未知金额显示待核对，不推算到账。
- 计费依据追加不可变版本；建账引用服务端试算。账单支付占用时禁止线下收款、纠错、撤销和作废，线上收款不能用线下纠错冲正。

## 权限与恢复保障

页面读取、菜单、快捷操作、按钮与字段使用同一业务权限目录，模块级别、关键操作、岗位模板及配置交互统一遵循 [后台授权设计](authorization.md)。服务端执行权限与数据范围。命令面板仅搜索本端授权页面和可执行操作，继承小区及返回上下文。公司/账号/角色安全操作后核实会话，失效时清理当前端身份、缓存、表单和进行中请求。

网络失败、403、404、422、409、限流及未知写入结果分别展示；读取可重试，写入不自动重试。资金和账单请求保留原幂等键及输入，先核实再恢复，不因未知结果新建操作。加载、无记录、无匹配、读取失败、处理中与成功状态统一呈现；禁止残留旧身份数据。

## 验证依据

旧页面测试不作为新实现验收依据。新验证覆盖预览还原、路由/权限/域名隔离、真实接口参数与状态、弹窗关闭和空白免确认、半全局小区保留、幂等未知结果恢复、导入与资金关键链路。真实渠道不可由浏览器模拟代替，未完成项需在交付时明确报告。

身份色验证覆盖两端登录、首次改密和登录后工作区；切换蓝、靛青、岩蓝主题后背景仍按后台固定，顶栏文字、图标及交互状态保持可读，后台名称清晰可见。
