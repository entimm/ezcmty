# 后台产品体验设计

## 设计依据与边界

本设计以用户确认的 [ChatGPT Sites 预览](https://xlife-admin-review-20261024.swiftswift256.chatgpt.site) 为视觉、信息架构与交互依据，源版本 `b5da13ae7e3aef9ce322d262c4a965260f331857`。两端采用深蓝顶栏、浅色业务区、白色分组导航及统一中文办公排版。

本设计取代旧页面设计对布局、导航、组件和交互的约束。已有业务设计中的数据规则、权限、异步状态、并发及资金语义继续有效，API 以 [OpenAPI 契约](../../../openapi/openapi.yaml) 为准。预览模拟数据、评审控制、模拟角色和虚构汇总不进入正式产品。接口不支持的聚合只展示当前页统计并明确范围，查询只发送已定义字段。

工程、域名、会话、API 和缓存边界见 [前端架构](../../architecture/admin-web.md)，工程质量见 [开发规范](../../guidelines/development.md)。

## 小区业务上下文

物业业务区顶部固定小区上下文，不放普通筛选栏。只列当前账号可读的小区，按账号隔离保留选择；切换时清理页面关联选择并读取目标数据，避免旧响应回填。无可读小区显示引导，不请求无范围资源。

房屋、账单及其详情使用明确小区；认领、绑定、收款与导入按契约可缩小到所选小区。工作台汇总、小区资料、公司收款配置、公司核对结果明确标记公司范围，不受顶部选择影响。表单未保存时切换先确认。直达详情同步解析真实资源小区，不悄悄把记录替换成其他小区对象。

## 视觉规范

主题通过 Ant Design Token 配置蓝、靛、灰蓝三套主色。深蓝顶栏、浅背景和白色卡片保持一致；标准/紧凑密度由用户设置保留。中文优先使用系统字体，正文14px，标题24/18px，辅助内容12px；表格正文13px。间距采用4/8/12/16/24px，统一圆角、阴影、状态标签和金额对齐。状态同时显示文字、色彩和必要图标。

菜单、工作台、表格、详情、弹窗和复杂流程按确认预览实现，常见1280/1366桌面宽度无页面级横向溢出，宽表格在自身容器内滚动。

## 操作与流程

- 新增账单使用弹窗，保存后保留当前业务页面并刷新数据。房屋列表可快捷登记业主，弹窗明确目标小区及房屋；登记档案不授予居民权限。
- 轻操作、简单详情使用弹窗；并排参考、问题行及审计使用抽屉；导入、支付资金和复杂业务详情使用独立页面。禁止嵌套确认弹窗。
- 点击遮罩、ESC、关闭按钮或取消走相同关闭规则。未修改、空白或新输入还原后直接关闭；有未保存内容时在当前弹层提示继续/放弃，提交中禁止关闭和重复提交。既有数据被清空仍属于修改。
- 日期/月份/时间区间统一RangePicker，并按契约转换边界及带时区时间戳。
- 导入用Steps展示范围、文件、预检、确认、执行结果。预检不写正式业务；范围/模板锁定，错误与警告策略显式确认，依据实际任务及行结果呈现进度和统计。未知结果先核实原批次；失败行重跑为新批次；取消不回滚成功记录。
- 支付、入账、分账、解冻分别展示可信事实。物业资金与配置只读；平台恢复需原因及状态令牌，异步受理仅表示已安排。外部处置只记录结论，不能显示为资金到账。未知金额显示待核对，不推算到账。
- 计费依据追加不可变版本；建账引用服务端试算。账单支付占用时禁止线下收款、纠错、撤销和作废，线上收款不能用线下纠错冲正。

## 权限与恢复保障

页面读取、菜单、快捷操作、按钮与字段使用同一权限目录，服务端执行权限与数据范围。命令面板仅搜索本端授权页面和可执行操作，继承小区及返回上下文。公司/账号/角色安全操作后核实会话，失效时清理当前端身份、缓存、表单和进行中请求。

网络失败、403、404、422、409、限流及未知写入结果分别展示；读取可重试，写入不自动重试。资金和账单请求保留原幂等键及输入，先核实再恢复，不因未知结果新建操作。加载、无记录、无匹配、读取失败、处理中与成功状态统一呈现；禁止残留旧身份数据。

## 验证依据

旧页面测试不作为新实现验收依据。新验证覆盖预览还原、路由/权限/域名隔离、真实接口参数与状态、弹窗关闭和空白免确认、半全局小区保留、幂等未知结果恢复、导入与资金关键链路。真实渠道不可由浏览器模拟代替，未完成项需在交付时明确报告。
