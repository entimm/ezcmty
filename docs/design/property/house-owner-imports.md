# 业主登记批量导入设计

## 范围与依据

物业端在本公司一个小区内批量新增业主登记，每行对应一套既有房屋下的一名业主，仅支持创建模式。空间及房屋须提前建立。登记规则及共享能力以 [房屋资料管理设计](housing.md#共享业主登记能力) 为准，流程及可靠性复用 [通用导入设计](../imports/overview.md) 和 [适配器协议](../imports/architecture.md#适配器协议与扩展)。实施依赖及验收见 [实施计划](../../plans/imports/house-owners.md)。

导入不更新、覆盖、迁移或启停已有登记，不创建房屋、居民账号或房屋授权。资料纠错使用现有编辑入口，更换业主使用停用旧登记后新增的流程。认领匹配及授权遵循 [居民接入设计](../resident/identity-and-house-claims.md)，不重新匹配历史申请或改变其快照。

## 一套业务逻辑、两个入口

```mermaid
flowchart LR
    M[手工新增及建房附带业主] --> B[普通登记命令及共享业务能力]
    I[导入表格] --> A[业主导入适配器]
    A --> B
    B --> D[(业主登记与业务审计)]
```

| 位置         | 职责                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| 手工入口     | 请求转换、会话复核、HTTP 响应和提交。                                                    |
| 导入适配器   | 文件表示转换，调用共享房屋定位及登记能力，将普通结果映射为准备数据、计划、行问题和结果。 |
| 共享业务能力 | 普通命令、规范化、字段边界、房屋归属及可用性、业务身份、重复分类、目标复核、写入和审计。 |
| 通用框架     | 文件、批次、文件内重复检测、预览确认、权限执行、操作账本、逐行事务、租约、恢复及统计。   |

业务不依赖导入包、批次、行号、框架上下文、计划、导入错误码、HTTP Schema 或会话存储。适配器不另写关联 SQL、业务判重、字段边界、写入和审计，不调用自行提交的手工 Service。通用引擎不增加业主分支。

## 类型、范围与模板

类型键为 `house_owners`，仅允许 `property_admin`、`community` 范围及 `create` 模式。公司由身份解析，小区经服务端授权后固定。模板不接受公司、小区、房屋 ID、登记 ID 或启停列，未知列沿用严格模板校验。

模板以不可变版本随应用发布，API 与 Worker 加载相同版本及摘要。首版字段如下，业务边界引用共享能力，不在适配器重复维护。

| 字段编码              | 列名         | 必填 | 规则                                                      |
| --------------------- | ------------ | ---- | --------------------------------------------------------- |
| `phase_name`          | 分区         | 否   | 没有分区层级时留空。                                      |
| `building_name`       | 楼栋         | 是   | 既有楼栋的完整名称。                                      |
| `unit_name`           | 单元         | 否   | 房屋直接属于楼栋时留空。                                  |
| `room_no`             | 房号         | 是   | 文本，保留大小写、前导零和内部字符。                      |
| `house_external_code` | 房屋外部编号 | 否   | 仅辅助核验按完整位置定位的既有房屋。                      |
| `name`                | 业主姓名     | 是   | 去首尾空白，长度及内容规则复用登记命令。                  |
| `phone`               | 手机号       | 是   | 文本，接受大陆手机号及 `+86`、`0086` 前缀，统一为 11 位。 |

定位复用 [完整位置定位与复核](housing.md#房屋完整位置定位与复核)，不猜测缺失层级，不将空层级作为通配，不以外部编号回退定位。手机号不从浮点数、科学计数法或丢失字符的值猜测还原。姓名和手机号声明为敏感字段。

## 准备、判重与执行

预检只读正式业务表，保存稳定房屋 ID、位置快照、普通登记命令、自然键、输入指纹及已有登记 ID。自然键和指纹由业务能力维护，位置展示名称、外部编号、批次及行号不作为业务身份。

自然键为 `house_id + name + 规范化手机号`，与既有数据库唯一约束一致。跨房屋分别登记，同手机号异姓名及同姓名异手机号属于不同组合，不隐式合并或纠错。创建内容仅包含这三个业务字段，启停状态和时间戳不参与比较；不新增原始创建快照。

| 情况                               | 行为                                                     |
| ---------------------------------- | -------------------------------------------------------- |
| 文件内规范化后自然键重复           | 全部重复行报错，不取首行或末行。                         |
| 系统没有同组合登记                 | 计划新增，登记自身初始启用。                             |
| 系统已有同组合登记，含自身停用记录 | 计划跳过，固定原登记 ID 并显示其状态；不修改或自动启用。 |
| 手工重复新增                       | 保留现有重复创建冲突。                                   |

预检和执行均复核房屋完整路径及可用性；业主登记自身停用不阻止同组合跳过。共享能力完成重复分类，入口仅表达手工冲突或导入跳过。跳过不新增登记或业务创建审计。

执行在既定业务锁内重新核验身份、权限、范围、路径、状态和唯一性。计划新增时若其他入口已创建同组合，则返回既有结果并跳过。计划跳过或复用成功操作时固定原登记 ID；原登记房屋、姓名或手机号变化时报告冲突，不改绑、新增或恢复旧资料。逐行执行期间的成功或跳过结果复用、未知跳过恢复同样调用共享保护性只读复核，在完整锁序内重新授权并保护固定目标直至调用方提交；不能仅依赖先前无锁读取。适配器按框架显式阶段区分预检与执行：预检含既有目标的检查、普通执行前检查均保持无锁，避免多行预检与执行交错时逆转操作锁和公司锁的顺序。

未确认的普通重预检可以重新定位并生成新预览；确认后的恢复与失败重跑固定原房屋 ID、位置快照、命令、已有登记 ID、操作键及指纹，仅重新核验当前条件。房屋改号、空间改名或路径关系变化时拒绝原计划，不用旧地址重新寻找其他房屋。

## 权限、事务与恢复

类型处理采用“房产资料维护”，历史、结果及错误文件生成和下载采用“房产资料查看”，权限目录与动作归属见 [后台授权设计](../admin/authorization.md#导入授权)。空间、房屋及业主资料使用统一的查看、维护权限，不再叠加逐阶段导入权限或单独的业主创建权限；其他业务获得的最小房屋引用查询不授予完整业主资料及本类型历史读取能力。预检、确认、逐行执行、重跑、恢复及成功结果复用前重新核验当前授权与范围。具体权限码及接口声明在实施契约阶段同步，本设计不表示相关契约或代码已经调整。

锁序、数据库唯一冲突识别及审计遵循 [房屋事务约定](housing.md#事务审计与验证)。共享能力不提交或回滚；Worker 逐行共同提交业主登记、业务审计、导入操作结果、当前行结果和进度。复用现有业主表和唯一约束，不增加导入批次或行号字段，不修改数据库结构。

提交结果未知时先核实原操作账本及同事务结果；当前存在同组合登记不能单独证明本操作创建成功。计划跳过的未知结果，仅在固定目标、位置、资料及当前授权仍符合时恢复为跳过，否则保留待核实。原成功结果当前复核失败只记录本批次问题，不改写原成功事实或创建替代操作。

姓名、手机号及自然键按通用敏感快照读取、30 天保留与清理规则处理；原值不进入日志、异常详情、审计元数据或 checkpoint。错误文件沿用最小安全字段及公式注入防护。业务问题映射为既有导入问题，权限和范围问题阻断批次，不将任意异常归为可重试。

## 页面与预览

小区房屋列表提供独立的业主登记批量导入入口，按房产资料维护权限控制，固定当前小区和类型；导入中心也可选择。空间树及列表筛选不缩小批次范围，向导明确显示目标小区；范围和关联信息按 [依赖与最小查询](../admin/authorization.md#依赖与最小查询) 提供，不另授完整关联业务权限。

预览使用现有受控 `business_preview` 和 `business_values` 展示完整房屋位置、姓名、规范化手机号、已有登记状态、动作及问题，不返回内部命令或位置快照。确认提示仅新增登记、已有同组合跳过且停用记录不自动启用。完成后可返回小区房屋列表，并刷新房屋、业主及审计缓存。部分失败、取消及清理后展示沿用通用页面。

## 验证要求

- 手工与导入使用同一普通登记命令、校验、判重、写入和审计调用链，业务不依赖导入包或 HTTP Schema。
- 独立新增保持原请求响应及重复冲突；建房附带多业主复用相同底层规则，保留整体原子性。
- 覆盖字段边界、手机号前缀、一房多人、跨房登记、规范化后文件重复、停用跳过及同手机号异姓名。
- 覆盖完整路径、前导零、辅助编号、缺失房屋、跨公司小区隔离，预检不写业务表。
- 隔离 PostgreSQL 验证手工与导入及跨批次并发、唯一约束、业务和导入结果整体提交及回滚。
- 覆盖确认后路径或登记变化、停用、失权、固定输入重跑、成功历史稳定、未知结果及敏感读取隔离。
- 房产资料查看可查询本类型历史及生成、下载授权错误文件，但不能处理批次；房产资料维护可完成全流程，最小房屋引用查询不能替代业主资料读取授权。
- 验证 CSV/XLSX、严格模板、wheel 配置与适配器加载、契约、入口权限、预览确认和返回；执行房屋、业主、认领及导入相关回归。
