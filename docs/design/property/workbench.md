# 物业管理端登录与基础工作台设计

## 范围与职责

物业端接入平台开通的公司管理员，提供登录、会话恢复、首次登录强制改密、退出、本人资料和基础工作台，完成平台开通到物业使用的流程。

工作台展示当前账号、所属公司资料和可用入口；小区页面提供本公司小区的只读查询。公司、小区和公司管理员的接入管理由 [物业接入管理设计](onboarding.md) 维护。共用账号、角色、认证和审计规则沿用 [管理后台基础框架设计](../admin/foundation.md)，前端作用域和缓存规则沿用 [管理后台前端设计](../../architecture/admin-web.md)。

复用现有公司、小区、账号、角色及审计模型。此功能不新增数据库结构或迁移。

## 身份与公司数据范围

物业后台的作用域固定为 `property_admin`。登录输入只有登录名和密码，公司归属从服务端账号解析，不能通过登录或本人资料输入指定后台、公司、角色或小区范围。

公司超级管理员使用物业后台的完整权限目录，覆盖本公司全部小区，并随本公司新增小区扩展。此功能的业务读取权限为 `property.company.read` 和 `property.community.read`，权限不能扩大公司数据范围。

- 当前公司接口只读取认证上下文确定的公司。
- 小区列表及总数在数据库查询中强制限定本公司，再应用筛选和分页。沿用共用列表契约中的公司筛选参数，该参数只能缩小范围；筛选其他公司时返回空列表和零总数。
- 小区详情在数据库查询中同时限定公司 ID 和小区 ID，越界资源按不存在处理。
- 公司归属缺失时拒绝使用物业身份，不退化为不限定公司的查询。

公司或账号停用后，登录失败沿用统一认证失败响应；已有会话的后续请求返回认证失效。重新启用公司或账号不恢复旧会话。小区停用仍保留只读资料和状态展示；新增业务的限制沿用物业接入设计。

## 登录、密码与事务

Cookie、Redis 命名空间、会话时限、登录限流、Origin 和 CSRF 校验沿用 [认证与会话](../admin/foundation.md#认证与会话)。会话响应复用共用契约，公司资料在完整登录后通过当前公司接口读取。

首次登录及平台重置密码后签发受限会话，仅允许读取当前会话、修改本人密码和退出。受限会话不能读取公司、小区或本人资料。

本人改密校验当前密码，成功后撤销该账号全部旧会话并清除本端 Cookie，使用新密码重新登录。旧密码错误按操作错误展示，不能当作会话失效。本人资料只允许修改显示名称。

物业登录签发会话、本人资料修改和改密按公司、账号的顺序锁定，在事务中重新读取启停状态及账号版本。平台停用公司、启停账号或重置密码与这些操作按同一顺序协调；变更已提交时，旧身份不能继续提交写入。事务和未知提交结果遵循 [错误与异常规范](../../api/errors.md#事务与并发)。

登录结果、本人资料变更和改密使用物业后台审计。公司来源和审计字段沿用 [审计与代码组织](../admin/foundation.md#审计与代码组织)，写入现有独立公司字段；密码、会话和 CSRF Token 不进入日志。平台接入操作保留平台来源和目标公司。

## 接口范围

物业端访问前缀为 `/api/property`，下表为后端路径。请求、响应、错误、权限、幂等性和运行进程归属以 [OpenAPI 契约](../../api/openapi/openapi.yaml) 为唯一权威来源，实施前维护契约。

| 方法         | 路径                                     | 职责                  |
| ------------ | ---------------------------------------- | --------------------- |
| POST         | `/v1/admin-sessions`                     | 登录并签发会话。      |
| GET / DELETE | `/v1/admin-sessions/current`             | 恢复会话 / 退出。     |
| GET / PATCH  | `/v1/admin-accounts/me`                  | 读取 / 修改本人资料。 |
| POST         | `/v1/admin-accounts/me/password-changes` | 修改本人密码。        |
| GET          | `/v1/property-companies/current`         | 读取本公司资料。      |
| GET          | `/v1/communities`                        | 查询本公司小区。      |
| GET          | `/v1/communities/{community_id}`         | 读取本公司小区详情。  |

认证及本人接口复用公共 HTTP 处理和身份能力，各端应用 Service 分别编排身份校验与事务。小区读取操作在平台和物业进程提供相同契约，由各端服务执行对应数据范围，并复用纯响应转换；当前公司接口仅属于物业进程。物业运行入口显式注册上述业务操作，分层与复用边界见 [后端业务边界与公共能力](../../architecture/backend-services.md)。

## 页面与交互

页面注册到物业路由元数据，使用物业作用域的 Provider、请求客户端、布局和身份守卫。下表为物业域名下的路径，直连开发服务器的映射见 [域名与页面路径](../../architecture/admin-web.md#域名与页面路径)。

| 路径               | 页面       | 访问条件                   |
| ------------------ | ---------- | -------------------------- |
| `/login`           | 登录。     | 未登录。                   |
| `/change-password` | 强制改密。 | 需要改密的受限会话。       |
| `/`                | 工作台。   | 完整登录。                 |
| `/communities`     | 小区查询。 | 完整登录且有小区读取权限。 |
| `/profile`         | 个人中心。 | 完整登录，本人访问。       |

登录、强制改密、个人中心和回跳行为复用 [登录与密码页面](../admin/foundation.md#登录与密码页面) 及 [平台路由与导航](../admin/foundation.md#平台路由与导航) 的身份规则，将路径和标题绑定到物业端。登录恢复失败提供重试；回跳目标只能是本端已注册的受保护页面。

工作台显示登录名和显示名称；有公司读取权限时展示只读公司卡片，包含公司名称、编码、联系人和联系电话。可访问入口从路由元数据和当前权限计算，提供小区查询、个人资料和修改密码入口。

小区查询展示名称、编码、地址、启停状态，支持名称、编码和状态筛选以及分页；筛选和分页保存在 URL。公司范围固定，不提供公司选择。详情按需加载，使用只读抽屉。无记录和无匹配结果分别说明，查询失败提供重试，越界详情按不存在展示。

菜单、按钮及数据读取依赖同一套权限。身份失效时取消物业端请求、清理查询缓存和表单并返回物业登录页；平台身份及缓存不受影响。

## 验证要求

实施验收覆盖以下行为，并执行 [开发规范](../../guidelines/development.md#质量检查) 要求的检查：

- 平台建立公司、小区和管理员，启用公司后，该账号能登录物业端；首次登录改密并重新登录后能使用工作台。
- 两家公司之间的列表、总数、分页和详情保持隔离，客户端筛选不能扩大范围。
- 受限会话仅能执行允许的三类操作，接口和页面均限制访问。
- 公司、账号停用和密码重置使旧会话失效，重新启用不恢复旧会话；停用小区保留查询。
- 多设备会话在改密后全部失效，单次退出只撤销当前会话。
- 平台停用、密码重置与物业登录、改密的并发行为符合事务和锁顺序约束。
- Origin、CSRF、登录限流、密码校验错误、失败重试和审计归属符合共用约定。
- 双后台同时登录时，Cookie、会话、请求和缓存隔离，权限不足和未知路由正确展示。
- 物业进程仅暴露约定接口，并通过逐进程 OpenAPI 契约检查。
