# 小区空间、房屋与业主资料管理设计

## 范围与职责

物业后台提供本公司小区内空间节点、房屋档案和业主登记的手工维护，以及按空间层级筛选房屋。支持创建房屋时同时录入多名业主；居民账号、居民与房屋绑定、批量导入和空间迁移不属于本设计范围。

小区和公司沿用 [物业接入设计](onboarding.md)，物业身份和公司范围沿用 [物业工作台设计](workbench.md)。后端分层、前端作用域及事务通用要求分别沿用 [系统架构](../../architecture/overview.md)、[管理后台前端设计](../../architecture/admin-web.md)、[数据库规范](../../database/conventions.md) 和 [错误与异常规范](../../api/errors.md)。请求响应、字段校验、权限码、错误码和幂等行为以 [OpenAPI 契约](../../../openapi/openapi.yaml) 为唯一权威来源。

## 空间与房屋

空间树以现有小区为根，节点分为分区 `phase`、楼栋 `building`、单元 `unit`。分区和单元可省略，最多三层空间节点。楼层作为房屋属性，房屋独立建档。

| 父级 | 可创建的子级 |
| ---- | ------------ |
| 小区 | 分区、楼栋。 |
| 分区 | 楼栋。       |
| 楼栋 | 单元、房屋。 |
| 单元 | 房屋。       |

节点同一父级下名称唯一，不区分节点类型。房屋在所属楼栋或单元内使用完整且唯一的房号，例如 `101`、`B01`；不同节点可以使用相同房号。楼层独立填写，不从房号推算。

名称、房号、外部编号和楼层可修改。节点的小区、父节点、类型，以及房屋的小区、所属节点创建后固定。业务关联使用稳定 ID；完整地址由当前小区名称、祖先节点名称和房号组合生成。

外部编号 `external_code` 是物业提供的可选资料，保留大小写和前导零，空白保存为 `NULL`；可补录、修改或清空，不设唯一约束，不用作实体身份。

## 业主登记

业主登记属于一套房屋，字段为姓名、手机号及启停状态。房屋可暂不录入业主；添加业主时姓名和手机号必须同时填写。一房可登记多人，同一自然人在多套房屋下分别登记，不建立全局人员身份，不按姓名或手机号跨房屋合并。

手机号暂时明文存储。接受大陆 11 位手机号及带 `+86`、`0086` 前缀的形式，统一保存为不带前缀的 11 位字符串，只做格式校验。同一房屋内相同姓名和规范化手机号不能重复登记，停用记录仍参与唯一性约束。

姓名及手机号纠错使用编辑；更换业主时停用旧登记，再新增登记。重新登记同一组合时维护或重新启用已有记录。业主登记所属房屋固定，停用记录保留。

创建房屋可附带业主列表，房屋、全部初始业主及审计在同一事务内提交，任意一条失败均回滚。房屋创建后，业主通过独立接口维护，房屋编辑不替换业主集合。

## 状态与查询

节点、房屋和业主分别保存自身 `enabled`，响应另计算 `effective_enabled`。节点实际可用要求小区、所有祖先及自身启用；房屋还要求自身启用；业主还要求登记自身启用。公司启用是物业身份访问的前提。

上级停用不批量改写下级自身状态。停用期间保留查询、资料修正及下级自身启停维护；新增节点、房屋或业主要求完整所属路径实际可用。重新启用上级后保留下级各自状态。

空间节点列表逐级加载，未传父节点时查询小区根节点，传入时查询直接子节点；按 `sort_order, id` 升序稳定分页。节点详情包含从根到父级的祖先摘要，用于地址、面包屑和树选中状态恢复。

房屋列表按小区限定范围，选中节点时包含该节点及全部后代的房屋。小区和单元可直接筛选房屋；分区和楼栋采用 `WITH RECURSIVE` 取得所属节点集合。递归只处理空间节点，不把房屋加入递归树。

房屋支持房号和外部编号准确匹配、楼层及自身启停筛选，默认按 `created_at DESC, id DESC` 排序。业主按房屋单独分页查询，避免展开业主导致房屋重复和总数失真。列表记录和总数使用同一 SQL 语句读取，同一语句快照下空页仍返回准确总数。

## 数据库设计

使用 PostgreSQL 18.x。三表公共字段如下，应用生成 UUIDv7 和带时区 UTC 时间，`updated_at` 初始等于 `created_at`，本条记录资料或状态变化时更新。普通字符串使用确定性、大小写敏感的排序规则，输入去除首尾空白。外键不级联删除，本功能不提供物理删除。

| 字段         | PostgreSQL 类型  | 约束                   |
| ------------ | ---------------- | ---------------------- |
| `id`         | `uuid`           | 非空，主键，应用生成。 |
| `enabled`    | `boolean`        | 非空，默认 `true`。    |
| `created_at` | `timestamptz(6)` | 非空，应用写入。       |
| `updated_at` | `timestamptz(6)` | 非空，应用写入。       |

`community_space_nodes` 除公共字段外包含：

| 字段            | PostgreSQL 类型 | 约束                             |
| --------------- | --------------- | -------------------------------- |
| `community_id`  | `uuid`          | 非空，外键指向小区。             |
| `parent_id`     | `uuid`          | 可空；空表示直接挂在小区下。     |
| `node_type`     | `varchar(16)`   | 非空，CHECK 限定三种节点类型。   |
| `name`          | `varchar(80)`   | 非空，去除首尾空白后非空。       |
| `external_code` | `varchar(64)`   | 可空，默认 `NULL`。              |
| `sort_order`    | `integer`       | 非空，默认 `0`，CHECK 限定非负。 |

- `UNIQUE(community_id, id)` 供复合外键引用。
- `(community_id, parent_id)` 引用本表 `(community_id, id)`，保证同一小区。
- `UNIQUE NULLS NOT DISTINCT(community_id, parent_id, name)` 同时约束根节点和普通同级名称；不增加根名称生成列。
- CHECK 限定父节点不能等于自身。合法父子类型由 Service 校验，固定类型和父级共同保证有限层级。
- 索引 `(community_id, parent_id, sort_order, id)` 支持逐级加载和外键检查。

`houses` 除公共字段外包含：

| 字段            | PostgreSQL 类型 | 约束                          |
| --------------- | --------------- | ----------------------------- |
| `community_id`  | `uuid`          | 非空，外键指向小区。          |
| `space_node_id` | `uuid`          | 非空，所属楼栋或单元。        |
| `room_no`       | `varchar(32)`   | 非空，去除首尾空白后非空。    |
| `floor_no`      | `smallint`      | 可空，默认 `NULL`，支持负值。 |
| `external_code` | `varchar(64)`   | 可空，默认 `NULL`。           |

- `(community_id, space_node_id)` 引用空间节点 `(community_id, id)`；Service 校验节点类型。
- `UNIQUE(space_node_id, room_no)`，停用记录仍占用房号。
- 索引为 `(community_id, created_at, id)`、`(community_id, space_node_id, created_at, id)`、`(community_id, room_no, created_at, id)`。
- 外部编号索引为 `(community_id, external_code, created_at, id) WHERE external_code IS NOT NULL`。

`house_owners` 除公共字段外包含：

| 字段       | PostgreSQL 类型 | 约束                                     |
| ---------- | --------------- | ---------------------------------------- |
| `house_id` | `uuid`          | 非空，外键指向房屋。                     |
| `name`     | `varchar(80)`   | 非空，去除首尾空白后非空。               |
| `phone`    | `varchar(32)`   | 非空，明文；CHECK 限定规范化大陆手机号。 |

- `UNIQUE(house_id, name, phone)` 保证房屋内登记组合唯一。
- 索引 `(house_id, created_at, id)` 支持分页；唯一索引同样覆盖房屋外键检查。
- 小区和公司从所属房屋解析，不重复保存。

## 权限与接口职责

新增接口仅属于 `property_admin_api`，物业身份和公司由服务端解析。节点必须属于路径小区，房屋必须属于路径小区，业主必须属于路径房屋；越界按不存在处理。列表、总数及选项使用相同公司范围。

空间、房屋和业主分别设置读取、创建、更新权限；公司超级管理员沿用本公司完整权限目录。创建房屋附带业主时同时校验房屋创建和业主创建权限。房屋读取不授予业主读取，房屋接口不返回业主姓名、手机号，创建响应也仅返回房屋资料。

| 方法        | 后端路径                                                             | 职责                            |
| ----------- | -------------------------------------------------------------------- | ------------------------------- |
| GET / POST  | `/v1/communities/{community_id}/space-nodes`                         | 查询直接子节点 / 创建节点。     |
| GET / PATCH | `/v1/communities/{community_id}/space-nodes/{node_id}`               | 节点详情 / 修改资料和启停。     |
| GET / POST  | `/v1/communities/{community_id}/houses`                              | 查询房屋 / 创建房屋及初始业主。 |
| GET / PATCH | `/v1/communities/{community_id}/houses/{house_id}`                   | 房屋详情 / 修改资料和启停。     |
| GET / POST  | `/v1/communities/{community_id}/houses/{house_id}/owners`            | 查询业主 / 新增业主。           |
| GET / PATCH | `/v1/communities/{community_id}/houses/{house_id}/owners/{owner_id}` | 业主详情 / 修改资料和启停。     |

PATCH 仅更新显式提交字段，可空字段允许显式 `NULL` 清空；固定字段和空更新拒绝。读取可安全重试，创建重复提交返回明确冲突；相同 PATCH 重复调用不改变业务结果。写请求沿用 Origin、CSRF 和完整会话检查，不自动重试未知结果。

## 物业页面

房屋管理使用独立一级菜单 `/houses`，按房屋读取权限展示。进入后在页面顶部选择小区；具备小区读取权限时，通过本公司小区列表按名称搜索、分页加载选项，停用小区仍可选择并标明状态。未指定小区且未搜索的小区列表加载成功、总数为 1 时，默认选择该小区并加载空间和房屋资料；自动选择替换当前浏览历史，避免返回时反复进入选择页。已有路径中的小区优先保留；多个小区时由用户选择，不将搜索后只有一项视为只有一个小区。尚未选择小区时展示选择提示，不请求空间或房屋数据。

选择小区后进入 `/communities/{community_id}/houses`，可在当前页直接切换小区。切换时清空空间选择、房屋筛选、分页和编辑状态；小区保存在路径中，刷新及直接访问可恢复。小区列表保留房屋管理入口，房屋列表和详情均选中房屋管理菜单。

房屋页面左侧为空间树，右侧为房屋列表。列表展示完整位置、房号、楼层、外部编号、自身状态、实际可用状态和创建时间。节点列表按需展开，分页提供继续加载入口，停用节点仍展示状态。

节点新增和编辑使用抽屉。房屋新增和编辑使用抽屉，新增房屋表单支持多条业主输入；从小区或分区进入新增时必须继续选择楼栋或单元。房屋详情 `/communities/{community_id}/houses/{house_id}` 展示基本资料，有业主读取权限时查询和展示业主列表；业主新增、编辑使用抽屉。

页面、菜单、按钮及实际请求按同一权限目录控制。启停通过确认交互说明影响。选中节点、房屋筛选及分页存入 URL，业主姓名和手机号不放入 URL 或持久化前端存储。缓存、未保存表单、认证失效和写入未知结果处理沿用共用前端设计；保存后刷新受影响的树、房屋和业主列表及详情。

## 事务、审计与验证

写入由物业 Service 编排，沿用公司、账号顺序锁定并重新校验身份和会话版本，再按小区、祖先从根到叶、房屋、业主的顺序协调业务资源。加锁查询显式限定目标表，等待锁后刷新状态。新增子资源和上级停用使用相同父记录协调。

数据库唯一约束兜底不存在记录的并发创建，通过 SQLSTATE `23505` 和明确约束名识别业务冲突。失败事务回滚后返回错误，不在失败事务继续查询。并发编辑同一字段以最后成功提交为准。

业务变更与审计同事务提交，审计归属物业后台和当前公司，记录操作者、目标、动作、修改字段及请求标识。姓名、手机号原值不进入诊断日志或审计元数据。迁移新增 Alembic 版本，沿用当前 PostgreSQL 迁移链，不改历史迁移。

验收执行 [开发规范](../../guidelines/development.md#质量检查) 和 [测试规范](../../conventions/testing.md) 的相关检查，覆盖：

- 根节点 NULL 唯一语义、普通同级重名、并发重复创建、真实复合外键及规范化字段约束。
- 合法层级、固定归属、跨小区挂接、跨公司查询和嵌套资源隔离。
- 一房多人、重复登记、手机号规范化，创建房屋及全部业主和审计的原子性。
- 上级停用、下级自身状态保留，停用和新增竞争，已撤销身份不能提交写入。
- 各层级筛选、同一语句分页与准确空页总数、业主读取隔离和敏感信息不进入日志。
- 页面路由、树加载和筛选、表单及状态操作、未保存保护、权限和缓存刷新。
- 代表规模下的 `EXPLAIN (ANALYZE, BUFFERS)`、迁移与模型一致、逐进程 OpenAPI 契约。
