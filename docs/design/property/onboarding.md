# 物业接入管理设计

## 范围与职责

本设计确定平台后台的物业公司、小区和公司管理员接入管理规则。平台负责建立组织资料、开通公司管理员及管理接入状态，为居民绑定、物业费抵扣和结算提供组织基础。

本设计中的物业管理员为公司级管理员。物业内部普通人员、指定小区授权及物业端登录页面归属物业端接入范围；物业登录及管理接口的启用前提见 [管理后台基础框架设计](../admin/foundation.md#范围与职责)。

运行组件与后端分层沿用 [系统架构](../../architecture/overview.md)，页面组装、权限守卫、请求和缓存管理沿用 [管理后台前端设计](../../architecture/admin-web.md)。共用账号、角色、认证和会话规则由 [基础框架设计](../admin/foundation.md) 维护。

## 物业公司与小区

| 对象     | 资料                                                         | 约束                                                     |
| -------- | ------------------------------------------------------------ | -------------------------------------------------------- |
| 物业公司 | ID、公司编码、名称、联系人、联系电话、启停状态、创建时间。   | 公司编码全平台唯一，创建后固定；名称和联系资料可以修改。 |
| 小区     | ID、小区编码、名称、地址、所属物业公司、启停状态、创建时间。 | 小区编码全平台唯一，创建后固定；名称和地址可以修改。     |

公司和小区使用独立、稳定的 ID，业务关联不依赖名称或编码。数据结构与迁移遵循 [数据库规范](../../database/conventions.md)，物理字段由下文维护；API 字段、格式和输入校验以 [OpenAPI 契约](../../api/openapi/openapi.yaml) 为准。

一家物业公司可以管理多个小区，一个小区归属一家当前管理物业公司。公司可以暂时没有小区。小区的所属公司在创建后固定，普通编辑不提供公司变更；更换物业涉及历史业务归属，须通过单独确认的移交设计处理。

公司和小区采用启停管理，保留资料、业务关联和历史记录。

### 数据库字段

两张实体表使用应用生成的 UUIDv7 主键及 UTC 时间；`updated_at` 初始等于 `created_at`，资料或状态变更时更新。时间使用 `DATETIME(6)`，外键不级联删除。

`property_companies`：

| 字段            | MySQL 类型     | 空值、默认值与约束                    |
| --------------- | -------------- | ------------------------------------- |
| `id`            | `BINARY(16)`   | 非空，主键。                          |
| `code`          | `VARCHAR(64)`  | 非空，全平台唯一，创建后固定。        |
| `name`          | `VARCHAR(160)` | 非空。                                |
| `contact_name`  | `VARCHAR(80)`  | 可空，默认 `NULL`。                   |
| `contact_phone` | `VARCHAR(32)`  | 可空，默认 `NULL`。                   |
| `enabled`       | `TINYINT(1)`   | 非空，默认 `0`，CHECK 限定为 0 或 1。 |
| `created_at`    | `DATETIME(6)`  | 非空，应用写入。                      |
| `updated_at`    | `DATETIME(6)`  | 非空，应用写入。                      |

除主键和 `code` 唯一索引外，建立 `(created_at, id)` 索引支持稳定分页。

`communities`：

| 字段                  | MySQL 类型     | 空值、默认值与约束                                   |
| --------------------- | -------------- | ---------------------------------------------------- |
| `id`                  | `BINARY(16)`   | 非空，主键。                                         |
| `property_company_id` | `BINARY(16)`   | 非空，外键指向 `property_companies.id`，创建后固定。 |
| `code`                | `VARCHAR(64)`  | 非空，全平台唯一，创建后固定。                       |
| `name`                | `VARCHAR(160)` | 非空。                                               |
| `address`             | `VARCHAR(255)` | 非空。                                               |
| `enabled`             | `TINYINT(1)`   | 非空，默认 `1`，CHECK 限定为 0 或 1。                |
| `created_at`          | `DATETIME(6)`  | 非空，应用写入。                                     |
| `updated_at`          | `DATETIME(6)`  | 非空，应用写入。                                     |

除主键和 `code` 唯一索引外，建立 `(created_at, id)` 及 `(property_company_id, created_at, id)` 索引。

公共账号、角色及关联表的公司归属字段见 [基础框架的数据库扩展](../admin/foundation.md#公司归属数据库扩展)。公司超级管理员覆盖本公司全部小区，本阶段不建立账号与小区关联表。

## 接入流程与公司管理员

接入流程为：创建物业公司 → 建立小区 → 开通公司管理员 → 启用物业公司。

1. 新建公司默认停用。平台可以在公司停用状态下维护资料、建立小区和开通管理员。
2. 公司管理员开通表单填写登录名、显示名称和初始密码。目标后台、公司归属、系统角色及公司级数据范围由服务端确定，不接受客户端自行选择。
3. 公司管理员使用所属公司的 `super_admin` 系统角色，数据范围按 [账号归属与授权上下文](../admin/foundation.md#账号归属与授权上下文) 执行。
4. 启用公司时，必须至少存在一名账号和公司系统角色均启用的超级管理员。没有小区不阻止公司启用。

开通操作以平台管理员身份执行，创建目标物业账号时固定后台为 `property_admin`，公司取自已授权的路径资源。平台操作者的身份、会话和权限上下文保持为 `platform_admin`。

初始管理员开通时，公司系统角色、账号、角色关联和平台审计记录在同一 MySQL 事务内提交。并发开通不能重复创建同一公司的系统角色，失败不留下部分成功的关联。密码和首次登录改密要求沿用 [密码与登录](../admin/foundation.md#密码与登录)。

公司管理员的公司归属固定。编辑只修改显示名称，账号启停和密码重置遵循共用认证与保护规则。平台可在公司停用期间继续管理其管理员；公司停用不解除 [最后一个有效超级管理员保护](../admin/foundation.md#角色与权限)。

## 启停规则

| 操作     | 效果                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 停用公司 | 阻止该公司物业账号登录及继续使用已有会话；保留小区和账号各自的启停状态及业务数据。 |
| 启用公司 | 校验公司管理员条件后恢复公司的接入资格；物业账号自身仍须启用，并重新登录。         |
| 停用小区 | 保留资料和历史查询，阻止该小区新增业务；其他小区继续可用。                         |
| 停用账号 | 只影响该账号，保留公司及其他账号的状态，并执行公司超级管理员保护。                 |

公司和账号状态变化的会话撤销机制由 [会话撤销与授权生效](../admin/foundation.md#会话撤销与授权生效) 维护。公司停用不批量改写小区或账号的启停字段，重新启用时保留各自原有状态。

账单、抵扣和结算使用各自的业务状态，不由公司、小区或账号的启停状态代替。

## 平台权限与接口范围

权限按物业公司、小区和物业管理员分组，读取与写入分别授权。公司与小区的资料管理权限可以分配给平台运营角色；物业管理员创建、启停和重置密码等管理写操作仅开放给平台超级管理员，沿用 [角色与权限](../admin/foundation.md#角色与权限) 的管理写操作规则。

所有接入管理操作属于 `platform_admin_api`。后端路径通过平台入口访问时使用 `/api/platform` 前缀；具体契约须在实施前按 [API 规范](../../api/conventions.md) 定义。

| 方法        | 路径                                                                              | 职责                                  |
| ----------- | --------------------------------------------------------------------------------- | ------------------------------------- |
| GET / POST  | `/v1/property-companies`                                                          | 查询 / 创建物业公司。                 |
| GET / PATCH | `/v1/property-companies/{company_id}`                                             | 查看 / 修改公司资料及启停状态。       |
| GET / POST  | `/v1/communities`                                                                 | 查询 / 创建小区。                     |
| GET / PATCH | `/v1/communities/{community_id}`                                                  | 查看 / 修改小区资料及启停状态。       |
| GET / POST  | `/v1/property-companies/{company_id}/admin-accounts`                              | 查询 / 开通公司管理员。               |
| GET / PATCH | `/v1/property-companies/{company_id}/admin-accounts/{account_id}`                 | 查看 / 修改公司管理员资料及启停状态。 |
| POST        | `/v1/property-companies/{company_id}/admin-accounts/{account_id}/password-resets` | 重置公司管理员密码。                  |

公司路径下的账号必须同时属于目标公司和物业后台，不符合时按不存在处理。账号开通入口不使用客户端传入的后台、公司、角色或小区集合扩大目标范围。

本设计维护资源职责和业务约束；请求与响应 Schema、字段校验、权限码、状态码、错误码及幂等性以 OpenAPI 为唯一权威来源。

## 平台页面与交互

页面注册到共用路由元数据中，菜单分组为“物业管理”。所有页面要求平台完整登录及对应读取权限。

| 路径                                        | 页面           | 查询与交互                                                       |
| ------------------------------------------- | -------------- | ---------------------------------------------------------------- |
| `/platform/property/companies`              | 物业公司列表。 | 按名称、编码和状态查询；创建和编辑使用抽屉，详情进入独立页面。   |
| `/platform/property/companies/{company_id}` | 物业公司详情。 | 展示基本资料、关联小区和公司管理员；提供各自权限允许的管理入口。 |
| `/platform/property/communities`            | 小区列表。     | 按名称、编码、所属公司和状态查询；创建和编辑使用抽屉。           |

公司详情中的关联小区和管理员按各自读取权限查询与展示，公司读取权限不自动授予其他资源权限。公司、小区和管理员管理写入口按对应权限显示。

公司和小区编辑表单中的编码只读，小区所属公司只读。管理员编辑表单中的登录名和公司只读，角色与公司级数据范围由接入规则固定。

启停使用确认交互并说明实际影响。初始密码和重置密码表单使用共用密码校验，确认密码只用于前端一致性校验；提交成功后清空密码输入。

筛选和分页通过 URL 恢复。保存后刷新受影响的公司、小区或管理员列表及详情，并使平台审计查询失效。重复提交、离开未保存表单、认证失效和写入结果不确定时的处理沿用 [请求、缓存与表单状态](../../architecture/admin-web.md#请求缓存与表单状态) 与 [异常与空状态](../../architecture/admin-web.md#异常与空状态)。

## 审计与事务

公司、小区和公司管理员的管理变更与对应审计记录在同一 MySQL 事务内提交。公司停用涉及的会话版本递增遵循基础框架的事务规则。

接入管理审计归属平台后台，记录平台操作者、操作、目标、结果、请求标识，并将目标公司标识写入独立的 `property_company_id` 列。公司归属、查询范围、响应字段及敏感信息处理沿用 [审计与代码组织](../admin/foundation.md#审计与代码组织)。

业务规则、授权、状态流转和事务由 Service 执行，API 只绑定平台身份并处理请求与响应。数据库约束、状态竞争和提交结果不确定时的处理沿用 [错误与异常规范](../../api/errors.md#事务与并发)。

## 验证要求

实施验收覆盖以下约束，并执行 [开发规范](../../guidelines/development.md#质量检查) 要求的相关检查：

- 平台可以完成公司创建、小区建立、初始管理员开通和公司启用；未满足管理员条件时不能启用公司。
- 公司及小区编码唯一且固定，小区所属公司不能通过普通编辑变更。
- 不同公司的账号、角色和资源关联不能混用，公司路径中的越界账号按不存在处理。
- 公司系统角色并发开通不重复，管理员开通与关联、审计保持事务一致。
- 并发停用或撤销授权不能绕过所属公司的最后一个有效超级管理员保护。
- 公司、小区和账号的启停各自生效；公司重新启用保留各自状态，并不恢复旧会话。
- 密码重置要求重新登录和强制改密，密码不进入 URL、持久化存储或日志。
- 页面、菜单、按钮和服务端权限一致，平台运营角色不能执行物业管理员管理写操作。
- 列表、筛选、分页、抽屉、公司详情、确认交互和保存后的数据刷新符合本设计及共用前端约定。
- 接口只暴露在契约声明的进程，实现与 OpenAPI 契约一致。
