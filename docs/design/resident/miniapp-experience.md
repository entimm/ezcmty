# 美好社区小程序体验设计

## 范围与基准

产品名称为“美好社区”。居民端使用原生微信小程序，以[交互预览](assets/miniapp-review.html)的紧凑布局、配色和页面层级为视觉验收基准；认领流程以本文的两步流程为准。预览中的身份、状态和支付模拟工具仅用于评审，不进入正式产品。

业务规则继续引用[居民身份与房屋认领](identity-and-house-claims.md)、[居民账单支付](../payment/bill-payments.md)与[OpenAPI](../../../openapi/openapi.yaml)。不新增商家、物业审批、成员管理、返利抵扣或退款能力。

## 视觉与导航

- 浅灰底、白色内容区、暖黄点缀和深色主操作，浅蓝、青绿、柔橙用于功能图标。状态同时用文字与颜色表达。
- 页面与卡片内边距 14px；卡片间距 8–10px；信息行距 9px。正文 14–16px、输入 16px、主金额 34px；中文地址分层换行。小程序使用 375px 设计宽度换算为 rpx。
- 首页、缴费、房屋、我的四个居民主入口固定在底部，适配安全区。切换主入口替换导航栈；详情、表单、登录和本人历史页保留返回流程。
- 白卡圆角 14px；主要按钮高约 46px。所有关键点击区域至少 44px。列表使用紧凑信息行，不重复显示导航栏已有标题。
- 自定义顶栏避开状态栏和微信胶囊。正文独立滚动，底部导航及弹层操作不遮挡内容；输入时可滚动到输入区域。

## 页面与流程

| 页面                     | 行为                                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| 启动、登录               | 恢复统一客户端会话及完整身份目录；网络失败可重试；主动微信登录后回到有效白名单目标；手机号按需授权 |
| 首页                     | 当前有效房屋与待缴汇总；认领申请、本人缴费记录；无房突出认领、待审突出进度                         |
| 手机号                   | 本人有效与解绑历史；两行卡片；底部添加弹层、微信快速验证及手填核对                                 |
| 房屋、详情               | 当前/历史；授权状态、时间；当前账单入口；主动解绑需确认                                            |
| 认领、申请、详情         | 填写资料、提交前核对两步；表单内选房，多号码明确选择；人工审核；撤回、驳回重申及授权历史           |
| 账单、详情               | 房屋切换、待缴/全部；紧凑账期/状态/金额行；分、余款及脱敏流水                                      |
| 确认、支付详情、本人记录 | 单账单全部余款；原订单恢复；取消、未知、待入账、成功、关闭分别引导                                 |
| 个人中心                 | 本人房屋/缴费/申请、手机号、服务说明、关于、退出                                                   |

统一微信登录、身份目录、选择与切换、回跳及全局退出遵循 [客户端交互设计](../client/interaction.md)。居民由有效微信用户派生，选择键固定为 `resident`，不写入通用关联表，不要求手机号或房屋，也不能单独撤销。匿名介绍不伪造已登录身份；首次多身份由用户选择，只有居民时在完整目录与详情确认后直接进入。

## 抽屉与状态

所有产品弹窗均从底部呈现，内容自然撑高。正文过长时内部滚动，确认和取消并列。关闭、遮罩和返回只取消当前临时操作；提交忙碌时防止重复操作。

选房按小区→分区→楼栋→单元→房号逐层深入，层级可省略；单元和直属房屋分组。面包屑、逐层返回、搜索、分页、空结果和失败重试均可用。认领时点击房号即回填房屋并关闭抽屉，直接填写资料；取消未完成的路径不改变原房屋，重选保留姓名、号码与说明。房屋、姓名和已验证号码在提交前统一核对。已授权房屋切换使用独立抽屉，确认前不改变当前房屋。

加载、首次空数据、筛选空结果、网络异常、登录失效、无权限、服务不可用、成功和禁用状态均有明确中文说明及下一步。加载更多失败保留已有行。底部导航在主页面状态下仍可用。

## 权限与恢复

小程序统一访问 `/api/client` 并使用同一客户端 Token。本人账号、手机号及身份目录不依赖当前业务身份；居民业务请求显式携带 `X-Client-Identity: resident`。额外业务接入时使用其通用关联 UUID；前端身份选择只改变工作场景，不授予角色权限。资源范围由服务端校验，客户端按当前有效授权展示房屋账务；本人历史支付只读固定快照，不重新授予房屋权限。

退出、当前客户端 401、用户变化、身份切换和页面卸载按客户端交互规则取消所属任务，阻止迟到响应回填。切换重建业务导航、清理敏感草稿，不撤销统一会话；额外身份失效只影响对应上下文，可切回服务端确认的居民。目录失败或不完整保留会话重试，不以已加载部分自动选身份。缓存按 API 环境、用户和业务身份隔离，固定居民键不表示跨用户共享数据。姓名、号码输入、微信 code、预支付凭证及签名不持久化、不进入 URL 或日志。

创建认领、号码验证和支付使用稳定幂等键。未知结果先恢复原请求，不换键重复创建；身份切换及同用户会话重建保留原支付的非敏感恢复依据，退出与换用户按客户端交互规则分别处理。付款前核对最新金额和版本，仅使用服务端允许的操作。微信支付 SDK 的成功、取消和失败只触发核实，只有服务端确认成功且已入账才显示缴费成功。房屋授权失效不妨碍关闭支付面板；本人原单在有效客户端会话与居民上下文中查询，不重新授予房屋权限。

## 验收

居民业务页面逐页与预览对照，公共身份选择按客户端交互设计验收，不以固定旧页数限制框架页面；验证 320/360/390/414px、长中文、底部安全区、弹层和键盘。测试以本设计、业务规则和契约为预期，覆盖派生居民身份、完整身份目录、未知类型、切换与原支付恢复。运行类型、Lint、构建、原生 WXML/WXSS 编译、核心流程与权限回归。真实微信登录、手机号授权和实际支付须以体验版真机验收，替身结果不得声明为真实支付或后端越权验收。
