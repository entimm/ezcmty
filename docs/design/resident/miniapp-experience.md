# 美好社区小程序体验设计

## 范围与基准

产品名称为“美好社区”。居民端使用原生微信小程序，以[交互预览](assets/miniapp-review.html)的紧凑布局、配色、页面层级和交互为视觉验收基准。预览中的身份、状态和支付模拟工具仅用于评审，不进入正式产品。

业务规则继续引用[居民身份与房屋认领](identity-and-house-claims.md)、[居民账单支付](../payment/bill-payments.md)与[OpenAPI](../../../openapi/openapi.yaml)。不新增商家、物业审批、成员管理、返利抵扣或退款能力。

## 视觉与导航

- 浅灰底、白色内容区、暖黄点缀和深色主操作，浅蓝、青绿、柔橙用于功能图标。状态同时用文字与颜色表达。
- 页面与卡片内边距 14px；卡片间距 8–10px；信息行距 9px。正文 14–16px、输入 16px、主金额 34px；中文地址分层换行。小程序使用 375px 设计宽度换算为 rpx。
- 首页、缴费、房屋、我的四个居民主入口固定在底部，适配安全区。切换主入口替换导航栈；详情、表单、登录和本人历史页保留返回流程。
- 白卡圆角 14px；主要按钮高约 46px。所有关键点击区域至少 44px。列表使用紧凑信息行，不重复显示导航栏已有标题。
- 自定义顶栏避开状态栏和微信胶囊。正文独立滚动，底部导航及弹层操作不遮挡内容；输入时可滚动到输入区域。

## 抽屉与状态

所有产品弹窗均从底部呈现，内容自然撑高。正文过长时内部滚动，确认和取消并列。关闭、遮罩和返回只取消当前临时操作；提交忙碌时防止重复操作。

选房按小区→分区→楼栋→单元→房号逐层深入，层级可省略；单元和直属房屋分组。面包屑、逐层返回、搜索、分页、空结果和失败重试均可用。临时路径最终确认后才回填；重选保留姓名、号码与说明。已授权房屋切换使用独立抽屉，确认前不改变当前房屋。

加载、首次空数据、筛选空结果、网络异常、登录失效、无权限、服务不可用、成功和禁用状态均有明确中文说明及下一步。加载更多失败保留已有行。底部导航在主页面状态下仍可用。

## 权限与恢复

居民、后台和未来其他业务身份独立；前端不提供角色选择来授予权限。所有请求只访问居民 API。资源范围由服务端校验，客户端按当前有效授权展示房屋账务；本人历史支付只读固定快照，不重新授予房屋权限。

退出、401、用户变化和页面卸载使旧请求失效，取消任务并阻止迟到响应回填。缓存按 API 环境和用户隔离。姓名、号码输入、微信 code、预支付凭证及签名不持久化、不进入 URL 或日志。

创建认领、号码验证和支付使用稳定幂等键。未知结果先恢复原请求，不换键重复创建。付款前核对最新金额和版本；仅使用服务端允许的操作。微信支付 SDK 的成功、取消和失败只触发核实；只有服务端确认成功且已入账才显示缴费成功。授权失效不妨碍关闭支付面板或查询本人原单。

## 验收

全部 15 个页面逐页与预览对照；验证 320/360/390/414px、长中文、底部安全区、弹层和键盘。重新编写测试，以本设计、业务规则和契约为预期，不沿用旧页面布局或旧测试断言。运行类型、Lint、构建、原生 WXML/WXSS 编译、核心流程与权限回归。真实微信登录、手机号授权和实际支付须以体验版真机验收，替身结果不得声明为真实支付或后端越权验收。
