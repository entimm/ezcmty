# 后台前端开发规范

## 范围与依据

本规范适用于 `apps/admin-web/` 的平台管理端、物业管理端，以及两端共享组件。新增页面、扩展功能和修复问题均须保持当前产品的视觉、操作习惯和业务边界一致。

| 内容                             | 权威依据                                                                                |
| -------------------------------- | --------------------------------------------------------------------------------------- |
| 菜单、页面归属、布局及交互选择   | [后台产品体验设计](../design/admin/experience.md)                                       |
| 模块、域名、会话、请求和缓存边界 | [管理后台前端设计](../architecture/admin-web.md)                                        |
| 模块授权、岗位模板及配置交互     | [业务权限与岗位模板设计](../design/admin/authorization.md)                              |
| 业务规则、权限、数据与资金语义   | 对应业务设计、[API 规范](../api/conventions.md)及 [OpenAPI](../../openapi/openapi.yaml) |
| 开发方法与交付检查               | 本规范、[开发规范](../guidelines/development.md)和[测试规范](testing.md)                |

旧页面设计中的布局、导航和交互不再作为实现依据，仍有效的业务约束继续遵循。模板示例、预览模拟数据和旧测试断言不能代替上述依据。设计调整遵循[设计工作流](../standards/documentation.md#设计工作流)，不得通过局部样式或单页实现悄悄改变已确认设计。

## 开发顺序与代码归属

开始开发时，先明确页面所属后台、业务域、公司或小区范围、读取与操作权限、接口能力，以及适用的页面或弹层模式。核对相邻的已确认页面，优先扩展现有组件和流程。

- `app/` 负责壳层、导航、主题和业务上下文；业务页面不另建顶栏、侧栏、小区选择器或整套布局。
- `features/platform/`、`features/property/` 分别持有本端业务 API 和用例，不互相导入，也不通过动态导入绕过边界。
- `shared/` 放确有复用的基础能力及一致契约流程，不反向依赖业务模块或应用组装。共享流程通过窄接口接收本端能力，不自行切换后台或扩大权限。
- 优先使用现有 React、Ant Design、ProComponents、React Query 和 Day.js 能力；依赖引入、公共能力提取及变更范围遵循开发规范，不为单个页面建立另一套组件体系。

模块职责和目录以[前端架构](../architecture/admin-web.md#模块组织)为准。表单和页面可按业务需要拆分，不以行数、组件数量或形式上的复用作为拆分依据。

## 导航、名称与页面开放

路由、读取权限、父页面和公司范围标记统一维护在 [routes.ts](../../apps/admin-web/src/app/routes.ts)；菜单、图标及搜索别名统一维护在 [menus.ts](../../apps/admin-web/src/app/menus.ts)。不得在页面中另建菜单或维护第二份路径映射。

- 业务分组和主菜单沿用四字名称；页面标题保留必要的完整业务名称。新增术语应与同业务页面一致，旧名称需要兼容搜索时使用菜单别名。
- 详情继承父菜单选中态和面包屑，提供明确的返回入口。业务导航使用 `useAdmin().go`，页面离开保护使用现有导航机制；不直接拼接地址或跳过未保存检查。
- 筛选、分页和详情返回条件使用 URL 中可恢复的状态。返回列表恢复原查询；修改筛选时回到第一页；切换小区时清理原范围的筛选、选中行和资源标识。
- 菜单、快捷入口和命令面板使用同一套当前端权限与页面开放判断。空分组隐藏；命令搜索继承当前小区，不提供跨端或无权操作。
- 页面开放开关统一维护在 [page-availability.ts](../../apps/admin-web/src/app/page-availability.ts)。关闭页面须同步覆盖菜单、搜索、直达和登录回跳，并阻止业务页面挂载及查询。开关不替代权限，不通过阻断必要小区上下文隐藏页面。

现有菜单和页面开关的具体状态见[体验设计](../design/admin/experience.md#信息架构)，不在本规范维护第二份清单。产品名称和工作空间名称沿用当前壳层文案。

## 布局与视觉

主题入口是 [App.tsx](../../apps/admin-web/src/app/App.tsx) 的 `ConfigProvider`，共同样式位于 [styles.css](../../apps/admin-web/src/app/styles.css)。页面继承主题色、组件状态和密度；主操作及强调色使用 Token、`--brand` 或 `--primary`，不在页面中固定为某个主题色。

登录及首次改密页左侧背景、登录后顶栏背景按当前后台 `scope` 使用固定身份色，具体色值见[后台身份色设计](../design/admin/experience.md#后台身份色)。身份色独立于可切换的强调主题；保留后台名称，不能只靠颜色区分两端。

下表为现行共享组件的标准桌面基线，用于核对一致性；窄屏和紧凑模式按共享样式的断点调整。页面应复用这些组件和样式，不逐页复制数值。

| 项目         | 现行基线及使用要求                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 工作区骨架   | 64px 深色顶栏，背景按后台身份固定；216px 白色侧栏、55px 业务上下文栏、浅色内容背景；宽度不超过1350px时侧栏为200px。业务页只填充内容区。                            |
| 主题与语义色 | 蓝、靛青、岩蓝三套强调色，不改变后台身份色；成功、警告和错误使用统一语义色。绿色用于成功状态，不新增松绿主主题。                                                   |
| 中文排版     | 继承系统中文字体；基础字号14px，页面标题24px，面板标题14px，标准表格正文13px、紧凑表格12px。辅助信息沿用共享样式，不能靠缩小关键字段腾出空间。                     |
| 内容留白     | 标准工作区左右28px，宽屏36px；紧凑模式24px。标准密度且宽度不超过1350px时为22px；`Panel` 标准内边距22px。局部内容间距优先使用4/8/12/16/24px，保留共享组件已有节奏。 |
| 控件与表格   | 标准控件高度34px；筛选项默认间隔12px，操作按钮间隔8px。由全局密度控制紧凑模式，不逐个表格自行设定密度。                                                            |
| 圆角与层次   | 基础控件6px、面板9px、弹窗10px；边框和轻阴影沿用共享样式。避免每个页面自行添加渐变、阴影和装饰卡片。                                                               |

页面使用 `PageHeader` 表达标题、说明、返回及主操作，使用 `Panel` 组织业务区块。沿用 `.filter-bar`、`.filter-actions` 等现有布局类；页面专属样式以业务类名限定作用范围，不新增无范围的 `.ant-*` 覆盖或用 `!important` 修补单页布局。

以桌面办公为主要场景。至少核对1280×720、1366×768和1920×1080：主操作、分页与弹层按钮可达，长名称可读，筛选可换行；宽表格在容器内滚动，不能撑宽整页。弹层内容按视口高度滚动，不靠放大浏览器窗口才能完成操作。

## 列表、筛选与详情

- 先呈现业务对象及其当前位置，再呈现状态、金额、时间和操作；同类列表保持相同列名、顺序习惯与操作位置。主操作放在页面标题区，行操作使用明确动词，次要操作按需收进“更多”。
- 查询框说明实际搜索字段及匹配方式。资源选择优先展示名称或完整业务路径；UUID 可用于精确定位、复制及诊断，不作为普通用户唯一的识别方式。
- 日期、月份和时间区间统一使用 `DatePicker.RangePicker`；单个日期使用对应 Picker。复用 [共享 DatePicker](../../apps/admin-web/src/shared/DatePicker.ts)，时区遵循[后台体验设计](../design/admin/experience.md#操作与流程)，按契约转换日期边界并保留区间语义，不要求用户手写时间戳。
- 服务端分页使用真实 `items/total/page/page_size`，优先复用现有分页配置。选项需要完整加载时逐页读取或采用明确的服务端搜索分页，不能将首100条当作全部选项。
- 只发送契约支持的筛选、排序和字段。不支持的搜索不得伪装成服务端能力；仅筛选当前页时必须明确范围。
- 汇总明确公司、小区或当前页范围。金额单位标清，分与元显式转换，沿用现有精度校验和格式化函数；`0`、缺失与未知值分别处理，不能把未知金额显示为零或推算为已到账。
- 详情突出当前状态、关键事实、可执行操作和来源记录。状态使用中文文字和语义色共同表达；复用 `Status` 或现有业务状态映射，含歧义的文案应明确指定语义色。

## 表单、弹层与流程

### 选择合适的交互容器

| 场景                                     | 使用方式                                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| 简单详情、轻量编辑、单次业务操作         | 弹窗，完成后刷新当前页面并保留查询条件。新增账单保持弹窗形式。                              |
| 需要保留列表参照的侧览、审计详情、问题行 | 抽屉。                                                                                      |
| 导入、复杂详情、需要持续跟踪的多步任务   | 独立页面；有真实阶段的多步任务使用 `Steps` 呈现校验、进度和结果，普通复杂详情不添加步骤条。 |

复用 [shared/ui.tsx](../../apps/admin-web/src/shared/ui.tsx) 的页面和反馈组件；编辑按业务选择 [PlatformFormDialog](../../apps/admin-web/src/features/platform/components.tsx)、[PropertyEditor](../../apps/admin-web/src/features/property/Editor.tsx)、[FormDialog](../../apps/admin-web/src/shared/forms.tsx) 或资金 [ActionDialog](../../apps/admin-web/src/shared/payments/ActionDialog.tsx)。提交锁、并发版本和未知结果恢复由所属业务流程负责；复用弹层不表示自动具备这些保障。沿用适用的业务封装，调用方补齐尚未覆盖的保障；不为统一外观抹掉业务差异，也不复制一套关闭逻辑。

房屋列表保留“登记业主”快捷入口，弹窗明确小区及房屋；登记资料与居民授权分别管理。页面不能把轻量操作改成无必要的独立页面，也不能在一个弹窗中再打开确认弹窗。

### 表单与关闭规则

- 字段使用清楚的中文标签、必填标识及就近校验；占位文本不能代替标签。只验证当前模式需要的字段；隐藏或切换字段时清理不再适用的输入，避免提交旧值。
- 以打开时的初始业务值为比较基线，复用 `hasFormChanges`。未修改、空白或新输入还原后直接关闭；清空既有值仍属于修改。不能仅用“字段是否触碰”或固定 `dirty=true` 判断。
- 点击遮罩、ESC、关闭按钮和取消执行同一关闭规则。有实际未保存修改时，在当前弹层内提示“继续填写／放弃并关闭”；继续编辑或恢复原值后更新提示。
- 编辑流程须通过 `setDirty` 登记实际变更；页面跳转、浏览器前进后退、小区切换和刷新沿用全局未保存保护，页内离开编辑使用 `confirmLeave`，不能假定导航自动识别所有输入。保存成功后先清理草稿状态再导航；取消离开或继续编辑时保留输入，确认放弃或身份失效时清理草稿。
- 提交前完成校验；请求在途时锁住重复提交及关闭入口，必要时使用同步提交锁防止快速双击。失败保留可修正的输入，成功反馈对应的实际业务结果。
- 危险操作说明对象、影响及原因要求，使用明确的确认文案。已有确认表单承担确认职责，不额外叠加通用确认层。

多步流程按真实任务状态推进；允许回退的步骤保留仍有效的输入，范围、模板或资源变化后清理失效结果。导入与资金的状态语义继续遵循对应[导入设计](../design/imports/overview.md)和[支付设计](../design/payment/bill-payments.md)。

## 业务上下文、权限与数据状态

小区是物业端的半全局业务上下文，统一从 `useAdmin()` 获取，不放入普通筛选栏，不在页面再维护一个默认小区。公司范围页面须明确说明不受选择影响；既有批次和订单展示其锁定范围与完整事实。直达记录时核对所属范围，不把记录静默替换为当前小区的其他对象。

- 业务查询只有在完整会话、页面开放、读取权限和必需范围满足时才能执行。无可读小区时提供引导，不回退为公司或全平台列表。
- 基础上下文及业务最小选项遵循 [依赖与最小查询](../design/admin/authorization.md#依赖与最小查询)，不能因为建账需要选择房屋就授予完整房产或业主资料读取。
- 读取使用当前端请求客户端和 QueryClient，优先复用 `useResource` 及现有业务 Hook。查询键和生命周期必须隔离后台、身份、业务范围及筛选；新增轮询须有处理中状态、停止条件和失败反馈。
- 组件优先消费受控查询数据，避免 Table/ProComponents 内建请求与 React Query 重复取数。写入成功后刷新相关查询，不用乐观显示虚构资金结果。
- 前端权限控制页面、操作及查询入口，服务端仍执行权限和数据范围。物业资金运行环境只提供本端受限读取能力，不能先取得平台完整数据再隐藏字段。
- 会话失效、身份或权限变化时沿用现有取消请求、清理缓存及卸载表单机制，不能保留旧身份结果。Cookie、CSRF和安全回跳遵循[前端架构](../architecture/admin-web.md#双后台与会话边界)。

涉及写入结果不确定、幂等或并发令牌时，沿用[请求与变更机制](../architecture/admin-web.md#请求缓存与变更)：保留原请求身份和输入，先核实再恢复，禁止自动换键、换令牌或重发。受理、处理中、已完成和结果未知分别显示；资金受理与外部处置记录均不能显示为到账成功。

## 反馈、文案与可访问性

每个新增页面和流程都应按实际适用场景处理以下状态，复用现有 `Loading`、`ReadError`、`NoAccess`、`NotFound`、`ListEmpty` 或业务反馈组件：

| 状态                         | 用户必须能理解或执行的内容                                         |
| ---------------------------- | ------------------------------------------------------------------ |
| 加载中                       | 当前正在读取什么；不能短暂显示为“暂无数据”或旧范围结果。           |
| 无业务上下文、无记录、无匹配 | 区分原因，给出选择小区、调整筛选或有权限的创建入口。               |
| 读取失败、无权限、记录不存在 | 清楚说明，提供适用的重试、关闭或返回路径；错误不能伪装成空列表。   |
| 校验失败、业务冲突、限流     | 定位可修正内容，保留输入；冲突先重新核对，等待时间依据服务端响应。 |
| 已受理、处理中               | 显示当前阶段和下一步，使用真实进度；总量未知时不编造百分比。       |
| 已完成、部分完成、结果未知   | 展示实际结果、失败原因及可安全执行的下一步，不一律提示“操作成功”。 |

文案使用业务中文和具体动词。必要诊断信息可复制或展开，不能用裸错误码、技术栈术语或原始 JSON 代替业务说明。模拟数据仅用于明确标识的预览或隔离测试，不进入正式页面逻辑。

状态不能只靠颜色识别；图标按钮提供可读名称或 `aria-label`，键盘焦点保持可见，表单可按合理顺序操作。长名称、手机号、日期及金额不能挤压主操作；截断时提供查看完整内容的方式。

Ant Design 用法以锁定版本和现有实现为准。新增代码使用 `mask.closable`、Drawer `size`、Steps/Timeline 的 `content`、Tag `variant` 等当前 API，不复制已弃用写法。

## 交付评审清单

| 检查项           | 验收要求                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 归属与边界       | 路由、菜单、标题、页面开关、读写权限和公司／小区范围一致；无跨端调用与隐藏页查询。                                                               |
| 视觉与组件       | 复用壳层、标题、面板、表格、表单和反馈；检查代表桌面尺寸、长文本、默认主题及至少另一主题、标准与紧凑密度。共享主题变更覆盖全部主题及两端代表页。 |
| 高频交互         | 筛选、分页、详情返回、小区切换、快捷操作可实际执行；空白、修改、还原、忙碌和结果未知时的关闭行为正确。                                           |
| 数据与恢复       | 加载、空、错误和无权限可区分；实际写入后刷新正确，重复点击、并发冲突与未知结果不产生替代操作。                                                   |
| 自动化验证       | 按变更风险补充有业务价值的用例；共享改动覆盖两端受影响调用方。格式、Lint、类型、相关测试及构建通过。                                             |
| 浏览器验收与说明 | 页面或交互变更在浏览器核对当前设计，关键链路保存可复核截图；说明实际验证、未执行项及真实依赖限制。测试写入使用隔离资源。                         |

检查命令和环境准备统一见[本地开发指南](../guidelines/local-development.md#质量检查)，不在本规范复制另一套命令。纯文档、格式等低影响修改按实际风险验证，不机械新增测试。

不符合既定设计、绕过权限或范围、丢失未保存内容、虚构数据或成功结果的实现不能作为完成交付。发现既有代码与已确认设计不一致时，按任务范围记录或修正，并同步相关权威文档；不能把偶然实现或测试快照自动升级为新规范。
