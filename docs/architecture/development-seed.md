# 开发数据填充

## 边界

开发填充工具位于 `services/backend/devtools/seed/`，不进入仅收集 `src/` 的后端发布包。业务写入遵循「命令生成参数 → 现有应用 Service → 现有持久化逻辑 → PostgreSQL」。只读恢复查询与覆盖检查位于开发工具自己的 Repository，不向业务代码增加 seed 分支，不修改公共 API、数据库结构或 Service 的事务边界。

写入必须显式配置 `APP_ENV=local/test` 和 `SEED_ENABLED=1`，且数据库迁移已到当前 head。生产部署不分发 `devtools/`，生产及 staging 环境不提供绕过开关。工具使用已有 PostgreSQL、Redis，无须启动 HTTP 进程。凭据不进入日志或 Git。

## 场景与数量

场景注册表声明参数、依赖、版本和覆盖表。支持一个或多个场景以及全部场景。当前场景为平台账号角色 `admin`、物业接入 `property`、房屋业主 `housing`。场景覆盖正常、待改密、停用等合法状态，审计和关联数据通过业务操作生成。数量不足时如实报告未覆盖的状态。

参数优先级为默认值、TOML 配置、命令行覆盖。数量参数明确总数或每个父对象的数量，执行前校验范围并展示规模估算。房屋场景自动补齐最小物业前置数据；同批次共享依赖只准备一次。新批次总是追加数据，使用批次唯一编码；续跑固定原参数与场景版本。

## 持久化与恢复

每批次保存在仓库 `.dev/seed/<run_id>/`。`state.json` 保存版本、已解析参数、数据库目标指纹和批次状态；`context.sqlite3` 使用 Python 标准库实现本地步骤与凭据索引，属于开发工具上下文，不承担业务持久化。步骤逐条事务持久化，避免全量重写和把全部数据加载进内存。目录权限为 0700，文件及临时文件为 0600。同批次文件锁拒绝并发续跑。

步骤先保存稳定标识、输入参数及密码，再调用 Service，最后记录结果。Service 自行提交，不能承诺整批原子性。数据库提交后进程中断时，恢复通过本批次步骤的审计 request_id、业务唯一键及实体关系核对；已完成则补记结果，确认未执行才重试，未知结果或外部修改冲突则停止。request_id 是恢复证据，不是业务幂等键。完成步骤也需检查必要实体仍存在，数据库重建或目标变更不能静默重建原批次。

账号创建、改密前保存拟使用密码，成功后确认当前密码；恢复不能重新生成。认证上下文通过正式登录和 authenticate 获取，首次改密走 Service；会话不持久化。已有平台管理员通过环境变量提供凭据，空库复用正式初始化 Service；后续批次可以复用本地工具初始化的管理员凭据。密码人工变更后需提供有效凭据，不自动覆盖已有账号。

## Redis 隔离

seed 执行入口统一使用 `app:seed` Redis 键前缀，构造现有 `AdminSessionStore` 并传给现有认证 Service。会话创建、读取、续期和删除，以及 Lua 限流脚本的全部 KEYS 使用同一前缀派生规则：

- 会话：`app:seed:session:<scope>:<token_hash>`。
- 账号限流：`app:seed:admin-login:<scope>:account:<login_hash>`。
- 来源限流：`app:seed:admin-login:<scope>:ip:<source_hash>`。

`AdminSessionStore` 提供通用的前缀参数，默认值为 `app`，普通后台的现有键名保持不变。seed 固定前缀在新批次、续跑和并发工作单元间一致，不因创建新批次重置限流。继续沿用现有认证、登录名规范化、限流阈值、过期时间、会话版本校验和审计流程；隔离不改变 PostgreSQL 中的账号与业务权限。

## 账号清单

`accounts.json` 与 `accounts.md` 从本地确认成功的凭据导出，仅包含所属批次、场景、登录端、登录名、显示名称、密码、所属物业公司七项。平台账号的公司为空。内部恢复状态不进入清单。密码是工具最后确认设置的密码，人工改密不会自动同步。失败时也导出已确认的账号。

## 效率

按需生成业务参数，复用父实体 ID，按时间间隔报告进度。保留真实业务事务和密码哈希；不通过直接 SQL 写入或篡改提交行为提速。物业接入顺序执行；不同公司的房屋填充允许有上限的并发，各工作单元独立 Session 和身份上下文。同公司操作有序，停止后等待已经开始的操作结束再释放批次锁。

## 覆盖与验证

覆盖检查比较实际迁移数据库、ORM 元数据与场景声明，技术表明确排除，未知业务表失败。新增表必须增加场景或明确排除理由。独立 PostgreSQL/Redis 验证全部已声明表、关系、关键状态、数量、重复新增、断点恢复、凭据、并发与生产保护；重点覆盖数据库提交后本地结果落盘前中断和改密中断。规模验证报告实际数量、耗时与吞吐量，不假设固定性能目标。

操作命令与配置集中维护在[本地开发指南](../guidelines/local-development.md)。
