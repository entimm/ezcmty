# 平台微信小程序架构

## 范围与入口

本文件规定统一客户端与多身份框架下的小程序目标架构。居民、物业和商家共用一个平台微信小程序及 AppID；小程序只访问 `/api/client`，使用一份统一客户端会话，每次业务请求分别解析授权上下文。客户端运行及身份边界见 [统一客户端设计](../design/client/overview.md)。

生产只接入居民业务。物业审批继续通过现有 Web 后台完成，物业和商家接入时再确定关联授予、认证、改密、权限及页面规则，不改变现有后台认证策略，不预建业务占位入口、空分包或跨进程共享会话。

小程序位于 `apps/miniapp/`，使用原生 WXML、WXSS、TypeScript 和自定义组件，构建到 `dist/` 后由微信开发者工具运行。系统运行边界见 [系统架构](overview.md)，跨端目录及测试归属见 [代码组织](code-organization.md)，居民认领规则见 [居民身份与房屋认领](../design/resident/identity-and-house-claims.md)。

## 前端边界

路径相对 `apps/miniapp/src/`。目录表达职责，只在实现对应能力时创建文件。

```text
src/
├─ app.ts、app.json                    生命周期与主分包页面注册
├─ core/
│  ├─ session.ts                     统一登录、恢复、退出及客户端凭据
│  ├─ request.ts                     HTTP、错误、幂等头与请求协调
│  ├─ identities.ts                  身份目录、当前选择、业务请求及上下文代际
│  ├─ account-api.ts、types.ts        本人账号、手机号、会话与身份公共契约
│  └─ phones.ts、format.ts           本人号码恢复、微信协议适配与纯展示转换
├─ pages/
│  ├─ index/                         会话恢复与身份分流
│  ├─ login/                         统一微信登录
│  ├─ identities/                    身份选择
│  └─ phones/                        本人手机号管理
├─ components/、ui/、assets/         无业务副作用的壳、状态、图标与白名单导航
└─ packages/resident/
   ├─ api.ts、types.ts                居民业务薄封装及契约类型
   ├─ claims.ts、payments.ts          认领与原支付恢复、SDK适配
   ├─ selection.ts                   居民房屋选择
   ├─ presentation.ts、page-state.ts 展示与页面生命周期隔离
   └─ components/、pages/            居民组件和原生页面
```

主包不静态导入分包代码，分包可导入主包公开共享能力，不得导入其他业务分包。共享层不维护居民房屋或其他业务实体；仅被居民使用的 API、类型和恢复协调归居民分包。公共本人手机号不依赖居民 API 或当前业务身份。导入方向通过 Lint 与构建检查验证。

HTTP 类型遵循 [API 类型生成约定](../api/conventions.md#前端类型)，公共与业务契约分别由所属类型入口引用生成声明；只允许纯类型引用，生成器及声明不进入小程序运行产物。

业务首页及合法导航通过固定类型注册，主包仅持有必要的页面元数据，不导入业务分包运行时代码。服务端身份投影不指定页面路径。客户端忽略新增响应字段，但对不支持的 `type` 明确展示不可进入或更新提示，不回退为居民、不拼接任意路径。

居民导航继续为“首页、缴费、房屋、我的”，配置归居民业务；通用壳不授予业务权限。视觉与页面密度遵循 [居民体验设计](../design/resident/miniapp-experience.md)，公共选择和回跳遵循 [客户端交互设计](../design/client/interaction.md)。

## 认证与身份

每个客户端登录使用一份 ClientToken，同一微信用户可在不同设备分别登录。客户端会话只认证微信用户，服务端不保存可变的当前身份，切换不换 Token、不调用切换写接口。Web 后台 Cookie、CSRF 及公司上下文仍由对应后台进程独立管理。

有效微信用户直接派生居民身份，选择键固定为 `resident`，不写入 `miniapp_user_identities`，不要求房屋、手机号或额外关联，也不能单独撤销。通用关联表只维护额外业务身份，其选择键为关联 UUID，类型为已受控注册的非居民稳定码；数据约束见 [客户端数据库设计](../design/client/database.md)。

身份公共投影为 `id`、`type`、`display_name`。目录统一归并派生居民及可用额外身份，居民固定首位，之后按关联 `created_at,id` 升序排列，再统一统计与分页。客户端必须完整取得目录分页，才可自动选择唯一居民或恢复本人上次有效身份；任一分页失败都不能使用部分结果自动进入。

有效客户端认证的目录总数至少为一。越界空页且总数大于零是正常分页结果；总数为零或完整目录缺失居民项属于完整性异常，保留会话并提供重试，不能在本地补造身份或自动注销。额外身份失效后可选择服务端确认的居民。首次多身份选择、详情校验及导航规则由 [客户端交互设计](../design/client/interaction.md) 维护。

## 请求与状态

公共账号、手机号、会话、身份目录及详情只使用 ClientToken，不依赖当前业务选择。居民业务请求必须显式携带 `X-Client-Identity: resident`；额外业务使用开始操作时确定的关联 UUID。详情路径的 `identity_id` 与请求头使用同一选择键，服务端按端点要求解析身份和资源授权，不自动默认或转换类型。字段和错误以 [客户端 API 设计](../design/client/api.md) 及其 OpenAPI 为准。

会话恢复区分初始化、未登录、已登录及读取失败。首次微信登录与手机号授权由用户主动触发，匿名介绍不伪造业务身份。网络失败不解释为未登录。

`sessionRevision` 隔离凭据替换、退出及用户变化，`contextRevision` 隔离业务切换及额外身份失效。请求启动时固定用户、会话代际，业务请求还固定身份键和上下文代际；响应回填另检查页面可见生命周期。公共手机号请求不因业务身份切换失效。

同会话客户端 401 先处理认证失效，即使请求来自切换前上下文；旧会话响应不能清理新登录。`client.identity_unavailable` 仅清理仍与该请求对应的业务上下文，类型不匹配停止错误调用并重新核验入口，不视为关联撤销；普通业务 403 不清全部身份，网络错误不清身份。详细状态和竞态处理见 [交互设计](../design/client/interaction.md#请求与页面状态隔离)。

切换时停止原业务轮询、取消所属请求、清理敏感列表及草稿，并重建导航栈，不能复用退出路径清理同用户原支付恢复。未知写结果按原业务的幂等规则核实，不因取消请求或切换后选择变化自动重放。

缓存和进行中的请求按环境、用户及所属业务隔离，固定居民键不代替用户隔离。持久存储只保存客户端凭据、所属用户、上次选择键、必要选房 ID 及 [账单支付模块](#账单支付模块) 允许的非敏感恢复。姓名、手机号表单、微信 code 及支付凭证不进入 URL、日志或持久化草稿。

## 账单支付模块

居民账单、支付确认及本人缴费记录归居民分包，页面规则见 [居民账单支付设计](../design/payment/bill-payments.md#页面与交互)。`packages/resident/api.ts` 和 `types.ts` 定义居民契约薄封装，`payments.ts` 协调原请求恢复、SDK 调用和结果刷新，原生页面负责展示及生命周期。

普通 GET 只读本地服务端事实，调起参数通过专门写接口获取。微信支付 SDK 的成功只触发服务端核实，页面以服务端确认入账为缴费成功依据。页面隐藏、卸载或切换身份时停止结果查询并阻止旧响应回填。

恢复数据只含原幂等键、必要非敏感输入和已知订单 ID，按环境、用户及居民业务隔离。身份切换和同用户 Token 重建保留原依据，退出与换用户按交互设计分别处理。调起参数、签名、预支付凭证只在内存使用，不进入 URL、日志、页面展示数据或持久存储。取消或未知结果恢复原订单，不换键付款。

账单读取检查当前房屋授权，本人支付记录按付款人授权，解绑后仍可查询，不对所有支付页面统一要求当前房屋绑定。已发生的支付确认继续由既有 Webhook 与 Worker 链路处理，不依赖前端停留在居民身份。

## 后端与迁移

客户端应用 Service 编排本人身份、数据范围和事务，共用 Domain、Repository、Model、Integration 及纯 Mapper，不调用后台私有用例或共享后台会话。微信登录、访问令牌和手机号兑换由现有微信 Integration 封装，外部响应必须校验。

平台 AppID、AppSecret 由服务端配置，数据库不保存 AppID。Redis 保存客户端会话、微信访问令牌、限流与非凭证协调锁，不保存临时手机号凭证或兑换成功结果。手机号验证成功后直接在 PostgreSQL 同事务保存绑定和成功记录。

微信支付继续使用平台 AppID、服务商商户号、业务所属物业特约商户号及该 AppID 下用户 OpenID。物业商户号由服务端业务归属解析；支付规则与存储分别见 [居民支付设计](../design/payment/bill-payments.md) 和 [支付数据设计](../design/payment/bill-payments-and-profit-sharing.md)。

从居民入口迁移到客户端入口时重新微信认证，旧 Token 不能自动升级或获得新业务身份。旧、新 API 地址只有在版本内明确声明同一部署环境、并由新会话确认同一用户后，才能迁移非敏感选房及原支付恢复。新副本校验写入成功后再清旧键，跨环境、跨用户不合并，不因迁移失败创建新支付。迁移设计统一见 [客户端技术架构](../design/client/architecture.md#迁移与发布)。

## 验证

保留 TypeScript、ESLint、Prettier 及分包构建检查，页面按批准路由验证，不以固定旧页数限制身份选择。业务与恢复测试使用 Vitest，微信 API 使用替身。

多类型与多身份通过测试专用解析器、路由和页面注册验证，不能放宽生产白名单或添加物业占位业务。覆盖完整目录分页、未知类型、公共与业务请求分离、会话和上下文代际、迟到 401、身份级失效、敏感草稿、原支付恢复和同环境同用户迁移。微信登录与手机号授权在体验版真机验收，替身不能替代真实协议验证。
