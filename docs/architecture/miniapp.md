# 平台微信小程序架构

## 范围与入口

居民、物业和商家共用一个平台微信小程序及 AppID。当前实现居民登录、手机号管理和房屋认领；物业审批使用现有物业管理后台。物业和商家小程序的业务接口与任职授权在相应功能设计中确定，不预建空页面或占位业务模块。

小程序位于 `apps/miniapp/`，使用原生 WXML、WXSS、TypeScript 和自定义组件，构建到 `dist/` 后由微信开发者工具运行。保留现有目录及构建方式。小程序身份与房屋认领规则见 [居民身份与房屋认领](../design/resident/identity-and-house-claims.md)。

后端进程沿用 [系统架构](overview.md)：居民 HTTP 接口仅组装于 `resident-api`，物业审批仅组装于 `property-admin-api`。微信支付的服务商身份不等于微信开放平台的第三方代开发身份；登录和手机号使用平台小程序自身的服务端配置。

## 前端边界

| 位置，相对 `apps/miniapp/src/`                          | 职责                                           |
| ------------------------------------------------------- | ---------------------------------------------- |
| `app.ts`、`app.json`                                    | 生命周期、主包与分包注册。                     |
| `pages/`                                                | 平台入口、登录和本人手机号管理。               |
| `auth/`                                                 | 按业务作用域创建的会话控制器；当前为居民会话。 |
| `shared/http/`、`shared/wechat/`                        | 网络、Problem Details、微信基础协议。          |
| `shared/components/`、`shared/styles/`、`shared/types/` | 无业务副作用的展示、样式和类型。               |
| `packages/resident/`                                    | 居民页面、API、状态、组件与业务编排。          |

主包不静态导入分包代码。分包可以导入主包公开共享能力，不得导入其他业务分包。共享层不依赖业务分包，也不维护居民房屋、物业公司或商家数据。导入边界通过 Lint 和构建检查验证。

本期采用居民首页卡片导航及个人中心入口，不设置跨业务的全局 tabBar。居民分包包含首页、我的房屋、认领、申请详情、房屋详情和个人中心；分包内复用选房及状态组件。原生组件、统一颜色、间距和字号保证界面一致。

## 身份、请求与状态

一个微信账号可同时拥有多个业务身份，不设置互斥角色字段。微信身份解析可以复用，各业务会话与授权上下文独立；居民令牌不能用于物业审批或商家业务。现有后台 Cookie、CSRF 和公司上下文保持独立。

请求客户端由工厂绑定 API 前缀、令牌读取和失效处理。居民通过 `/api/resident` 访问，手机号管理本期由居民会话授权访问本人数据。后续业务只能复用同一用户的本人能力，不能扩大其业务数据范围。

会话恢复区分初始化、未登录、已登录及读取失败。首次主动微信登录，已有令牌自动恢复。401 清理居民会话及请求；网络失败不解释为未登录。不自动重放未知结果的写请求；有幂等契约的操作使用原键恢复。

缓存和进行中的请求按 API 环境、作用域、用户隔离。退出、用户变化、认证失效时取消请求并清理状态，旧响应不得回填。持久存储只保存居民令牌、所属用户标识及必要的房屋选择 ID；姓名、手机号表单、微信 code 不进入 URL 或持久化草稿。表单保留在当前用户的内存状态中。

## 后端与外部能力

各端应用 Service 分别编排身份、数据范围和事务，共用 Domain、Repository、Model、Integration、纯 Mapper，不相互调用私有用例。微信登录、访问令牌和手机号兑换由 `integrations/wechat/` 封装，外部响应必须校验。

平台 AppID、AppSecret 由服务端统一配置，数据库不保存 AppID。Redis 只保存居民会话、微信访问令牌、限流和非凭证的请求协调锁，不保存临时手机号验证凭证或兑换成功结果。手机号验证成功后直接在 PostgreSQL 中提交绑定及成功验证记录。

后续微信支付采用平台 AppID、服务商商户号、业务所属物业特约商户号及该平台 AppID 下的用户 OpenID。物业商户号由服务端业务归属解析，不由客户端指定；支付协议和资金流程另按对应功能设计实施。

## 验证

保留 TypeScript、ESLint、Prettier 和分包构建检查；业务规则及请求恢复使用 Vitest，微信 API 使用替身。微信登录和手机号授权在体验版真机验收，不能以模拟器替代真实微信协议验证。跨业务导入、会话缓存隔离和旧响应丢弃作为回归边界。
