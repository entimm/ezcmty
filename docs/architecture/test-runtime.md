# 后端测试运行准备

## 范围

本文件定义后端集成测试的数据库与账号准备方式。测试分类、隔离和执行门禁遵循[测试规范](../conventions/testing.md)，命令见[本地开发指南](../guidelines/local-development.md#质量检查)。生产代码、密码算法及业务接口不因测试准备优化而改变。

## 数据库模板

- 每轮测试在所属的临时 PostgreSQL 实例内创建模板数据库，执行项目真实 Alembic 迁移到 head。模板只包含迁移产生的结构和必要初始数据，不包含测试账号、会话或业务数据，不跨测试进程或代码版本持久缓存。
- 普通集成测试从已迁移模板克隆独立数据库。每个用例继续拥有独立数据库和真实事务，允许实际提交、回滚、行锁及并发连接。
- 模板准备必须显式设置目标数据库并清理配置缓存；完成后释放连接、禁止新连接，避免用例连接或修改模板。用例数据库仍通过现有环境配置和连接管理使用。
- 空库迁移、历史版本升级、结构与迁移一致性等迁移专项保留从空库执行真实迁移的路径，不使用模板替代待验证的迁移过程。`fresh_migrated_database_url` 统一提供此路径；迁移目录内的 fixture 使用该路径，目录外的结构与迁移一致性专项也显式依赖它。
- 用例失败时仍释放所属连接并删除数据库；模板在全部依赖用例结束后删除，临时实例最后关闭。清理只针对本轮测试创建的资源，不连接已有业务数据库。

## 业务账号与会话

- 身份认证、密码变更、会话生命周期、账号管理、初始化审计及相关事务专项保留真实账号初始化、登录和首次改密流程。
- 普通业务测试使用独立的业务 fixture，通过测试数据工厂准备最小合法账号、角色、关联关系及必要公司、小区。仅不可变的有效密码哈希可在进程内复用，数据库记录、权限状态和客户端会话仍按用例隔离。
- 业务 fixture 通过真实会话存储创建会话，并按所属后台的 Cookie Path 写入测试客户端。请求继续执行真实身份认证、会话版本、角色权限、租户范围及 Origin/CSRF 校验，不直接替换管理员上下文或全局模拟密码算法。
- 用例明确测试的业务操作仍调用实际接口或应用服务；仅与断言无关的前置账号准备可走数据工厂。依赖初始化审计、首次改密状态或密码版本的用例不能直接切换业务 fixture。
- 数据工厂集中在测试辅助模块，fixture 放入最近的 `conftest.py`；测试文件不相互导入。

## 验证

- 验证模板迁移版本、结构和业务数据为空，验证两个克隆数据库的写入、提交、回滚相互隔离，以及异常退出后的资源清理。
- 验证业务会话仍受权限、租户、CSRF、停用和会话版本约束，并保留原认证、审计、事务和并发覆盖。
- 使用相同代码基线、相同用例集合及机器比较优化前后耗时；分别记录准备、调用和清理阶段。重复样本报告中位数和范围，完整回归记录通过、失败、跳过与未执行。
- 首批范围为数据库模板与业务初始化优化；测试进程并行度的变更另行依据实测结果评估。
