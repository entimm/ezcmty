# 错误与异常规范

## 响应与权威定义

内部 API 错误使用 RFC 9457 Problem Details 和 `application/problem+json`，包含 `type/title/status/detail/instance`，扩展 `code/request_id`；校验异常还包含 `errors`。HTTP 状态与 `status` 一致，错误结构见 [公共错误 Schema](../../openapi/components/errors.yaml)。

该文件的 `x-error-catalog` 是错误码、标准状态和公开标题的唯一权威来源，按领域组织并校验全局唯一。新错误码采用 `<domain>.<name>`，不得重用、随意更名或变更已有语义；必要历史错误码保留。不提前定义尚未实现业务领域的错误。

`type` 由同文件的 `x-error-type-prefix` 与 `code` 拼接，`instance` 使用 `urn:request:<request_id>`，不维护另一份类型标识或回显请求 URL。`title` 是错误类型的稳定公开标题，`detail` 只能提供已设计的安全说明。

后端目录通过现有聚合契约生成，运行时不读取仓库文档或依赖 Node.js。生成与一致性检查命令见 [API 规范](conventions.md#校验和构建)。

## 分类与集中处理

通用异常转换集中在后端异常处理模块，由应用工厂注册；请求中间件的未知异常回退调用同一模块，各业务模块不得复制通用处理器。

| 类别                             | HTTP 状态与处理                           |
| -------------------------------- | ----------------------------------------- |
| 请求参数校验异常                 | 422；仅返回位置与校验类别。               |
| 认证、权限异常                   | 401、403；保留适用的 `WWW-Authenticate`。 |
| 资源、方法异常                   | 404、405；保留适用的 `Allow`。            |
| 已知业务状态或并发冲突           | 409；不能自动解释为可以重试。             |
| 明确的基础设施不可用             | 503；按连接、连接池或明确驱动错误分类。   |
| 未识别基础设施异常或未知系统异常 | 500；公开安全说明，记录脱敏诊断。         |

业务异常只能引用已登记且有确定状态的错误码，不默认统一返回 400。HTTP 异常保留合法的 400–599 原状态；未分类情况使用目录中的 HTTP 回退错误，不因缺少标准状态短语而返回 500。

SQL 编程错误、未识别的约束错误不能一律映射为 409 或 503。只有 Repository / Service 能明确识别业务约束、状态竞争及其语义时才转换为业务异常。

## 安全与追踪

- 响应不得包含原始异常、堆栈、SQL、内部服务地址或敏感信息。校验问题不返回原始输入、校验上下文或异常文本；公开详情不得传入任意内部对象。
- 响应头 `X-Request-ID`、响应中的 `request_id` 及服务端日志使用同一经过校验的标识，禁止重复或错配的同名响应头。
- 诊断日志仅保留错误码、异常链类别及脱敏模块、函数、行号，不记录异常文本、源码行、局部变量、SQL 参数、请求体或认证数据。
- 响应开始后发生异常时不发送第二个响应；记录脱敏诊断并结束失败响应。

## 事务与并发

事务所属层见 [系统架构](../architecture/overview.md#后端分层)。数据库依赖在异常或取消时显式回滚未提交事务并释放资源，不自动提交；清理失败不能掩盖原始异常。

失败事务不得继续作为成功结果返回。只有已识别的唯一性约束或状态竞争才使用冲突错误。数据库提交结果不确定时，不得假设回滚撤销了已经提交的数据。

## 幂等与安全重试

幂等行为逐接口写入契约，明确重复调用效果、请求标识和拒绝条件。资金类写入需稳定的业务请求标识与持久化去重；相同标识配不同输入必须明确拒绝，不能只依赖 Redis 锁确保唯一。

自动重试只适用于能确认安全的读取或已有幂等保证的操作，并设置上限与退避。409、超时或 503 本身不是允许重试的充分条件；只有能承诺等待时间时才返回 `Retry-After`。

第三方调用由 Integration 区分明确失败、超时和结果未知。支付、退款、分账发出请求后未收到确定结果时按结果未知处理，先查询原单或对账，不重新创建资金操作或直接宣称失败。具体错误与恢复行为由对应模块契约定义，不预建通用支付或重试框架。

## Webhook

Webhook 的运维接口使用共享内部契约。外部回调按对应服务协议验证、确认成功及返回错误和重试响应，显式协议响应不由内部错误格式改写。

协议适配由 Integration 与 Webhook API 承担；不假设所有服务共用一种签名头，也不复刻内部通用异常处理器。具体协议只在实际对接时定义。
